## ★ どこを見て、どこへ書くか（2026-08-30 に整理）

**参照元と出力先は別物。** ここを取り違えると「直したのに画面が変わらない」が起きる。

| | パス | 役割 |
|---|---|---|
| `SHARE` | Dropbox `（★必読★）新共有フォルダ` | **読む側**。ここのファイル・フォルダを見てリンクを作る |
| `OUT` | `gyomu-manual/業務マニュアル.html` | **書く側**。**8521 が配信するのはこれ** |

> **2026-08-30 に直したこと**: 従来 `OUT` は共有フォルダを指していたが、**そこにファイルは存在しなかった**。
> 社員が見ているのはローカルの方なので、**生成し直しても画面は変わらない**状態だった。
> 共有フォルダに置いてあるのは `業務マニュアル.url`（8521へのショートカット）だけ。

## ★ 共有フォルダは動く。リンクは定期的に確かめる

**2026-08-30 の実測で、176本のリンクのうち29本が切れていた。**
押しても何も開かないが、押した人にしか分からないので誰も報告していなかった。

原因はすべて共有フォルダ側の移動・改名（オーナー談「フォルダ構成を色々変えている」）。

- `物件・管理/管理業務/塚本/` → `物件・管理/検針関連/`
- 台帳2本の先頭に `★要更新★` が付いた
- 社内様式2本 → `社内・総務/[社内様式（届出書等）]/` へ
- `物件・管理/損保業務` → `営業・募集/損保関係`
- `経理・請求/発行請求書（テナント別・ビル別）` → `（家賃等、テナント賃料、管理料他）` に統合され、**中は物件別**に組み替え
- `★本社・西・メーター表 .xls` … **実ファイル名の末尾に空白**が入っていた

**移動しやすいものは完全一致で書かず `_R()` 経由にする**（hintの部分一致で解決するので、
末尾の空白や `【旧】` の付加に強い）。

## ★ 退職者名の読み替え

`杉田→松本 / 服部→塚本 / 森下→吉浦 / 平木→大鹿`。`generate.py` の `rename_retired()` が
**書き出す直前に必ず通す**。本文を直すだけでは足りない（このスクリプトは共有フォルダの
Word/Excel を生成時に読むので、原本に古い名前が残っていれば再生成で復活する）。

**★「様」は置き換えない。** この会社は**社員に「さん」、社外に「様」**を使い分けている。
`杉田様` は杉田ビル片町のオーナー（管理物件台帳・オーナー連絡先・見積書に電話番号つきで
載っている実在の人）。`様` まで対象にすると**社外の人の名前が化ける**。
入れ替え漏れより害が大きいので、**迷ったら当てない側に倒す**。

## ★ 法令の根拠（`law` ブロック）

マニュアルには法令が一言も書かれていなかった（2026-08-30 実測: インボイス・電帳法・
経過年数・重要事項説明・個人情報 すべて0件）。知識索引の一次資料から6件を補った。

- 生成: `bookshelf/make_manual_law_notes.py` → `law_notes.json` → `generate.py` が読む
- **引用は索引の本文と1文字ずつ照合**する。落ちたらJSONを書き出さない
- **会社の手順と見た目を分ける**（色・枠・出典表記）。「国が決めていること」と
  「当社のやり方」を読む人が区別できるようにするため
- ★キーワード検索は**目次のページを掴む**（「適格請求書の記載事項」で引くと250ページの
  Q&Aの目次が出た。本文はP30）。だから人が場所を決めて機械が照合する形にしている
