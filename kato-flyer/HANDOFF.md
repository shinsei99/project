## 9. 2026-08-09 追記 ── `賃貸資料.xls` からの素材取り出し（解決）

```bash
.venv/bin/python maisoku.py          # → data/maisoku/<案件フォルダ>/
open data/maisoku/index.html         # 目視用の一覧
```

**13ファイルから69枚**（写真・間取り図・地図スクショ）。**LibreOfficeは要らなかった。**

### なぜ今まで取れなかったか（再調査しないこと）
画像は**二段で分断**されている。生ファイルの走査もQuick Lookも当然当たらない。

1. OLE複合ドキュメント … `Workbook` ストリームが512バイトのセクタに散っている
   → `olefile` で組み直す
2. BIFF レコード … 1レコード**8224バイト上限**のため、画像を含む `MSODRAWINGGROUP`(0x00EB)
   が `CONTINUE`(0x003C) に刻まれている → **後続の CONTINUE を連結する**

連結すると Escher が素直に読める（`DggContainer` → `BStoreContainer` → `BSE` → BLIP）。
BSEヘッダは36バイト、その後ろのBLIPは `recInstance` の最下位ビットが立っていると
UIDが2個（32バイト）入る。中身は JPEG / PNG / DIB。DIBはBMPのファイルヘッダを足せば開く。

- 全13ファイルの先頭に同じ 5947×3533 のPNGが入っている。**マイソクの枠**なので
  sha1 (`f6003b…`) で除外している
- `olefile` を `requirements.txt` に追加済み

### 使ったもの
- **秋津9に間取り図が付いた**（案件フォルダにファイルとして無く、xlsの中だけにあった）。
  `properties.py` の `"madori": "加東市秋津9/00.jpg"` で名指し。あわせてスペック表に
  **間取り 2DK**（和室6帖＋和室6帖＋DK、縁側つき）を追加
- `list_madori()` は `madori` キーがあればそれを最優先で返す

### ⚠️ 自動選択にはしていない
`data/maisoku/` は案件フォルダ由来なので、**build_site が勝手に拾うことはしない**。
`index.html` で人が見て、`build_kato.py` / `properties.py` に書いたものだけが載る。
今回の69枚は全て物件写真・間取り図・地図で、身分証・申込書の類は無いことを目視で確認済み。

## 13. 2026-08-09 追記 ── 流入元の計測（看板ごとの反響を数える）

**看板を複数出すので、どれが効いたかを分けて数えられないと出し直しの判断ができない。**
GA4などの外部サービスは使わず、**サーバーのPHPだけ**で完結させた（アカウント不要・
Cookie不使用・IPも保存しない。持つのは「月・流入元・ページ・件数」だけ）。

```
tracking.py          流入元の定義とPHPの中身。SOURCES を直せば増やせる
site/hit.php         1×1の画像を返しながら数える
site/stats.php       集計の表示。?k= が要る（キーは tracking.STATS_KEY）
site/data/counts.json 集計の実体。hit.php が .htaccess を置いて外から読めなくする
```

### 配るURL（QRにするのはこれ）
| 流入元 | URL |
|---|---|
| 検索など | `https://daikyocorp.co.jp/slowlife/` |
| チラシ | `https://daikyocorp.co.jp/slowlife/?from=doc` |
| 看板（都会） | `https://daikyocorp.co.jp/slowlife/?from=city` |
| 看板（田舎） | `https://daikyocorp.co.jp/slowlife/?from=local` |

**この4つに絞ってある。**細かく分けても見るのが面倒になるだけ、という判断。
検索経由はほぼ無いので、「検索など」の欄は実質**キャンプ場の予約メッセージ経由**が入る
（スペースマーケットの予約メッセージには `?from=` なしの素のURLを貼っている）。

集計を見る: `https://daikyocorp.co.jp/slowlife/stats.php?k=<キー>`
（キーは `kato-flyer/.stats_key` の1行。**公開リポジトリなのでソースにも文書にも書かない**。
他PCへはこのファイルを別途コピーする。無い場合は空になり、集計ページは誰も開けない）

### チラシメーカー（app.py）との連携
QRの飛び先の既定を **`tracking.from_url("doc")`＝トップ + `?from=doc`** にしてある。
サイドバーで手入力すれば上書きでき、既定に戻すURLもその場に出る。

### 仕組み
- 入口で `?from=` を **sessionStorage** に覚えるので、物件ページへ進んでも同じ流入元で数える
- **問い合わせフォームにも流入元を hidden で持たせてある**。届くメールに
  「流入元: 看板 中崎町」が出るので、**件数だけでなく実際の反響の出所**が分かる
- `send.php` は `hit.php` を `require_once` して件数を計上する。hit.php は
  `SCRIPT_NAME` を見ていて、直接開かれたときだけ画像を返すので読み込んでも副作用がない
- 動作確認済み（2026-08-09）: ビーコン→gif／キー無しのstats.php→404／
  counts.json への直アクセス→403／実送信でメールに流入元が出る。テスト分は削除済みで0から

## 10. 2026-08-09 追記 ── 問い合わせページ（公開済み）

**https://daikyocorp.co.jp/slowlife/contact.html**

会社サイトの `mailform/send.cgi`（2013年のPerl CGI・全社の窓口）とは**別系統**。
あちらは売買・管理・土地活用まで受けるので、加東の貸家の問い合わせが混ざらないよう
独立させた。件名に `［加東の貸家］` が付く。

```
contact.py     フォーム・完了ページ・send.php の中身
site/contact.html  site/thanks.html  site/send.php   ← build_kato.py で一緒に出る
```

- **サーバーは PHP 8.3 が動く**（Perl 5.26 も動くが、保守が楽なPHPにした）。
  調査用に置いた `_probe.php` / `_probe.cgi` は削除済み
- 送信先は `contact.py` の `MAIL_TO` ＝ **`info@shinsei-pm.co.jp`**（2026-08-09に会社サイトと分離）。
  差出人は `no-reply@daikyocorp.co.jp` のまま。**サイトが載っているドメインに合わせる**必要があり、
  ここを shinsei-pm.co.jp にするとSPFが通らず迷惑メール行きになりやすい。
  **送信者にも控えのメールが自動で返る**
- **必須はお名前とメールだけ。** 電話・住所・見学希望日・本文は任意
- **物件と用件はリンクから自動で選ばれる**（`contact.html?p=物件&k=用件`）
  - 募集中の物件ページの「メールで問い合わせ」→ その物件＋**見学したい**
  - 一覧の**賃貸中の写真をタップ**→ その物件＋**空きが出たら連絡してほしい**
  - `p` の値は `PROPERTIES` のキー／`RENTED` の `title`。表示名とは別なので、

  **2秒未満の送信を無視**。CAPTCHAは入れていない
  - ⚠️ 経過時間の元になる `t` は**お客様の端末の時計**で作られる。時計が進んでいる端末では
    差が負になるので、**負のときは判定しない**。ここを単純な `< 2` に戻すと、
    時計がずれているだけの本物の問い合わせが黙って消える
