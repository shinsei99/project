# AI重説調査 〜 Excel自動入力システム

不動産業務の「物件調査 → 登記簿解析 → 重説下調べ → Excelテンプレート自動入力」を
一気通貫で行う**調査支援・下書き生成**システム（Streamlit）。最終ゴールは宅建士が
確認できる「重要事項説明書ドラフト（Excel）」の自動生成。完全自動ではありません。

## 設計方針

- すべての情報は `models/property_data.py` の **PropertyData**（単一辞書）に集約。
- **入力 → 調査 → 整理 → 出力（Excel / PDF）** の一方向パイプライン。
- AI文章はテンプレート生成（OpenAI 等の有料LLMは不使用）。
- Google Maps は**座標の精度が上がるときだけ**使う（下の「ジオコーディングの選び方」）。
  キーが無いPCでは従来どおり国土地理院だけで動く。
- API失敗時もアプリは停止せず、空欄（「要確認」）で継続。

## 入力

1. 住所（必須）
2. 登記事項証明書（土地PDF）
3. 登記事項証明書（建物PDF）
4. 物件概要書PDF（任意・将来対応）

## 使用データ / API（すべて無料）

| 用途 | データ源 | キー |
|------|----------|------|
| ジオコーディング | 国土地理院 住所検索API（基本） | 不要 |
| ジオコーディング（精度が出るときだけ） | Google Geocoding | 直下 `.env.google-maps` |
| ストリートビュー（画面表示） | Google Street View Embed | 直下 `.env.google-maps` |
| 最寄駅・距離 | HeartRails Express API | 不要 |
| 周辺施設（学校/病院/スーパー/公園） | OpenStreetMap Overpass API | 不要 |
| 災害（ハザード確認導線） | 国土地理院 重ねるハザードマップ | 不要 |
| 用途地域/建ぺい率/容積率 | 国交省 不動産情報ライブラリ **XKT002** | 任意 `REINFOLIB_API_KEY` |
| 人口・世帯数 | e-Stat（政府統計）**統計表 0000020101** | 任意 `ESTAT_APP_ID`（直下 `.env.estat`） |

> 用途地域・人口は無料でもキー登録が必要なため、未設定時は空欄で継続します。

## 調べて分かったこと（次の担当が同じ調査を繰り返さないため）

### 公式書式への流し込みエンジン（2026-08-21 実装）

全宅連の公式書式186本（xlsx 74 / docx 112）に対し、**セル座標を人が書かずに**
`PropertyData` を流し込む。要は「見出しの文言から入力欄を割り出す」方式。

| 経路 | 対象 | 実装 |
|---|---|---|
| Excel | xlsx 74本（重説・売買契約書・自動入力書式） | `services/official_format_service.py` |
| Word | docx 112本（賃貸借契約書36・媒介契約書10ほか） | `services/docx_format_service.py` |
| 対応表 | 見出し→項目の規則（包含＋除外） | `services/field_map.py` |
| レジストリ | 走査結果のキャッシュ | `scan_formats.py` → `data/format_registry.json` |

#### 肝: excel版自動入力書式は「重説シートだけ埋めればよい」

1ファイルに重説・売買契約書・実測清算確認書・引渡し書・媒介手数料承諾書が同梱され、
**契約書側のセルが重説シートを参照する数式**になっている（同梱の注意事項シートに明記）。
実測で、他書式から参照されている重説セルは **90種類**。ここだけ埋めれば5書類が完成する。

入力欄は色で区別されている:
`FFFFFF99`(黄)=共通入力欄（他書式へ波及） / `FFCCFFCC`(緑)=選択欄 / `FFFFCC99`(橙)=その書式のみ。

#### つまずいた点（同じ穴を掘らないため）

- **見出しは左だけを見ても当たらない。** 左だけ→17項目中11、上の列見出しも見て15、
  **結合セルの左上を解決して17**。結合セルは左上以外の値が `None` になるため、
  「地　積」のような列見出しが拾えていなかった
- **除外規則が要る。** 「所在」は宅建業者の**主たる事務所所在地**にも出る。除外しないと
  業者の住所を物件所在地に書く。同様に「種類」に権利の種類、「地積」に地積の確定、
  「建蔽率」に緩和の欄がある
- **最寄駅・駅距離・人口・世帯数・路線価・公示地価は重説に記載欄が無い。**
  あれは調査資料であって重要事項説明書の記載事項ではない。画面に出すだけにする
- **書き込みは `xlsx_patcher`（無損失）を使う。** openpyxl で再保存すると図形・罫線が落ちる。
  検証で zipエントリ36→36・転記数式81本が健在であることを確認済み
- **Word は run を全部消して書き直すと書式が飛ぶ。** 先頭 run だけ差し替える。
  `(住居表示)` のような案内文は消さずに後ろへ足す
- **`.doc`（旧Word・14本）は python-docx で読めない。** Word で `.docx` 保存し直しが要る

#### 対応率（実測）

| 分類 | 本数 | 平均対応 |
|---|---|---|
| excel版自動入力書式 | 25 | 12.8/17（主要9本は **17/17**） |
| 重要事項説明書(xlsx) | 12 | 10.2/17 |
| 売買契約書(xlsx) | 25 | 6.8/17 |
| 賃貸借契約書(docx) | 30 | 4.0項目（契約書は物件表示のみなので正常） |

対応0の書式（付帯設備表・物件状況確認書・従業者名簿・宅建業者票・保証協会一覧）は
**そもそも物件欄が無い**書式なので、これで正しい。


### ★ `templates/*.xlsx` は白紙ではなく「他社の実案件が記入されたファイル」だった（2026-08-21 実測）

**この状態で書類を作ると、前の案件の情報が混ざったまま出力される。** 直すまで実務に使わないこと。

`format_export_service.FORMATS` が書き込むのは各書式 3〜9 項目だけで、**残りはテンプレートの
記入内容がそのまま残る**設計（空欄はテンプレ既定を保持する仕様のため）。テンプレが白紙なら
正しい挙動だが、実物は記入済みだったので事故になる。

| テンプレート | 残っている他社データ（抜粋） |
|---|---|
| `rental_building_template.xlsx` | 物件「ロジュマン門真 512号室」／**貸主 有限会社ケン・コーポレーション**（P65・P67）／**借主 株式会社喜多村商事**（P71）／構造RC・1K・22.68㎡・平成10年7月新築／乙区 根抵当権あり／関西電力・都市ガス・EV1基・駐車場無 |
| `sale_landbuilding_template.xlsx` | **売主 株式会社ジャック**（W5）／物件 大阪市北区東天満一丁目46番地 |
| `sale_mansion_contract_template.xlsx` | 物件 大阪市淀川区新北野三丁目70番の215 |
| `sale_mansion_jyuusetsu_template.xlsx` | 自社情報が中心（大京商事・新誠プロパティマネジメント）＝これは残ってよい |

**特に危ないのは貸主・売主欄。** `FORMATS` の `map` は登記名義人（L106）は上書きするが、
**貸主欄 P65/P67 は対象外**なので、**他人の貸主名が入った重説が出る**。

- **公開リポジトリへの流出は無い**（`.gitignore:169` で `jyuusetsu-research/templates/*.xlsx` を除外済み。確認済み）
- 差し替え先の**白紙雛形は社内 Dropbox にある**:
  `共有フォルダ/（★必読★）新共有フォルダ/契約・書類/★仲介（賃貸・売買）/賃貸/★事業用（店舗・事務所）/_雛形・マスター様式/`
  - `重説/★★★重説-建物の賃貸借用（A4）（20140407）2.xlsx` … **実データ0件を実測で確認**
    （保証協会・法務局の固定情報だけ入っている）
  - `契約書/★★★★★★★賃貸借契約証書（特殊詐欺追加）クリーン版（2020民法改正版).doc`
    … **探していた賃貸契約書の白紙雛形**
- **ただし白紙雛形はシート構成が違う。** アプリのテンプレは1シート616行（`建物賃貸借用`）、
  白紙雛形は**6ページ分割**（`賃貸）1P`〜`賃貸）6P`）。**セル座標は流用できず作り直しになる**
- **賃貸契約書は `.doc`（旧Word）**。このPCに LibreOffice は無く、`textutil` はレイアウトを保てない。
  → **Word で「.docx として保存し直す」のが確実**（人の作業）。Excel前提の `xlsx_patcher` では
  扱えないので、契約書は `python-docx` の別ルートが要る


### 用途地域は XKT002。XKT001 では**永久に空**（2026-08-20 修正）

不動産情報ライブラリのレイヤ番号を取り違えており、**キーは設定済みなのに用途地域が常に空**だった。

| | 誤 | 正（実測して確認） |
|---|---|---|
| エンドポイント | `XKT001`（＝都市計画区域・区域区分） | **`XKT002`**（用途地域） |
| 用途地域 | `youto_chiki` | `use_area_ja` |
| 建ぺい率 | `kenpei` に `%` を付ける | `u_building_coverage_ratio_ja`。**既に `"80%"`** なので付けない |
| 容積率 | `yoseki` に `%` を付ける | `u_floor_area_ratio_ja`。同上（`"60.0%"` の揺れは `60%` に正規化） |

- **防火地域・高度地区はこのAPIでは取れない**（XKT001〜XKT007 を実測。該当レイヤが無い）。
  空欄のまま返し、画面と重説ドラフトでは「都市計画図で要確認」として扱う
- 地点を含むポリゴンが無いとき、**最寄りポリゴンで代用してよいのは 100m 以内だけ**
  （`NEAR_LIMIT_M`）。上限が無いと、用途地域の定めが無い土地で **2.9km 先の地域**を返した
  （加東市・六甲山中の座標で実測）。重説ドラフトに入ると事故になる

### ジオコーディングの選び方 — Google に一本化しない（2026-08-20 実測）

`location_type` が **ROOFTOP / RANGE_INTERPOLATED のときだけ Google を採用**し、
それ以外は国土地理院を使う（`address_service.geocode_detail`）。

| 住所 | 地理院とGoogleのずれ | Google の精度 | 用途地域 |
|---|---|---|---|
| 大阪市中央区本町4-2-12 | 21m | ROOFTOP | 同じ |
| 千代田区丸の内1-1-1 | 62m | ROOFTOP | 同じ |
| 世田谷区北沢2-23-12 | 18m | ROOFTOP | 同じ |
| **兵庫県加東市社1** | **892m** | **APPROXIMATE** | **★違う（地理院が正しい）** |

画面には「座標: … （出典 Google(ROOFTOP)）」と出しているので、宅建士が精度を判断できる。

### e-Stat の人口・世帯数（2026-08-20 実装）

それまでは「地域名を抜き出すだけで API を呼んでいない」状態だった。実測して次のように解いた。

住所 → 緯度経度 → **市区町村コード**（国土地理院 `LonLatToAddress` の `muniCd`。先頭ゼロが
落ちるので5桁ゼロ埋め）→ e-Stat `getStatsData`。

| 指定 | 値 |
|---|---|
| `statsDataId` | **`0000020101`**（社会・人口統計体系 市区町村データ 基礎データ Ａ　人口・世帯） |
| `cdCat01` | **`A1101` 総人口** / **`A7101` 世帯数** |
| `cdArea` | 5桁の全国地方公共団体コード（例 大阪市中央区 = `27128`） |
| `metaGetFlg` | **`Y`**。指定した地域の正式名称だけがメタに入る（応答 6.9KB と軽い） |

- **地域名を住所文字列から作ってはいけない。** 「大阪府大阪市中央区…」から素朴に抜くと
  「大阪府大阪市」になり、**区が落ちて実データと食い違う**。e-Stat が返す正式名称を使う
- 値は5年おきの国勢調査が中心なので、**値が入っている最新年**を自動で選ぶ（現時点は2020年）
- 実測: 大阪市中央区 103,726人 / 67,139世帯、世田谷区 943,664人 / 492,065世帯、
  加東市 40,645人 / 17,070世帯、占冠村 1,306人 / 849世帯

### ストリートビュー（未了・要 Console 設定）

`GOOGLE_MAPS_WEB_KEY` は **HTTPリファラが `https://daikyocorp.co.jp/*` に限定**されているため、
社内画面（`http://127.0.0.1:8599` 等）から Embed を開くと **403** になる（2026-08-20 実測。
撮影メタデータはサーバー用キーで取れるので「撮影時期 2021-08」は表示できている）。

**2026-08-21 に作成・設定済み。** キー名 `maps-embed-internal`（Maps Embed API 1個のみに制限、
アプリケーションの制限なし）。直下 `.env.google-maps` の `GOOGLE_MAPS_EMBED_KEY` に入れてある。
実測で埋め込みURLが HTTP 200、画面に「撮影時期 2024-09」が出ることを確認した。
**アプリケーションの制限を付けなかった理由**: 社内画面はポートが変わるのでリファラ制限だと
再び403になる。Maps Embed API は無制限・無料なので、制限なしでも課金は発生しない。

以下は作成手順の控え（同じキーを作り直すとき用）:

1. Google Cloud Console（プロジェクト `daikyo-maps-2026`）→ 認証情報 → **APIキーを作成**
2. 名前は `maps-embed-internal` など
3. **「APIの制限」で `Maps Embed API` **だけ**を選ぶ**（ここが肝。Embed は無制限・無料なので、
   このキーは**どう使われても課金が発生しない**）
4. 「アプリケーションの制限」はリファラでも「なし」でもよい。社内画面はポートが変わるので、
   リファラにするなら `http://localhost:*/*` `http://127.0.0.1:*/*` `http://192.168.1.105:*/*` を許可
5. できたキーを直下 `.env.google-maps` に **`GOOGLE_MAPS_EMBED_KEY=...`** として追記する

コード側は対応済み（`google_maps_api.embed_key()` が `GOOGLE_MAPS_EMBED_KEY` →
無ければ `GOOGLE_MAPS_WEB_KEY` の順で使う）。**キーを1行足すだけで表示される。**
- **規約**: ストリートビューは**印刷物に一切使えない**（チラシ・DM・重説の紙面は不可）。
  Google以外の地図と同一画面に並べない（この画面はハザードマップを"リンク"で置くだけ）

## 実書式テンプレートへの流し込み（重要）

実際の重説書式（Excel）へ `PropertyData` を流し込めます。書式は
`services/format_export_service.py` の `FORMATS` に登録し、`{項目: セル}` の
マッピングで書き込みます。**新しい書式は FORMATS に 1 エントリ足すだけ**。

対応済み書式:

| キー | 書式 | テンプレート | 流し込み項目 |
|------|------|--------------|--------------|
| `rental_building` | 賃貸重説（建物賃貸借用 A4） | `templates/rental_building_template.xlsx` | 所在地→L90/L92、床面積→Y100、所有者→L106 |
| `sale_landbuilding` | 売買契約書（土地建物・公募用 一般売主） | `templates/sale_landbuilding_template.xlsx` | 所在地→D10/H18、地番→W10、地目→AF10、地積→AL10/AL15、家屋番号→AN18、種類→H19、構造→X19、床面積(延床)→AN21、所有者(売主)→D5 |
| `sale_mansion_contract` | 売買契約書（区分所有建物・敷地権 宅建業者売主） | `templates/sale_mansion_contract_template.xlsx` | 所在地→I8/H16、地番→Z16、地目→AK16、地積→AT16、家屋番号→I12、種類→AT12、構造→I13、床面積(専有)→AT13 |
| `sale_mansion_jyuusetsu` | 重要事項説明書（区分所有建物の売買・交換用） | `templates/sale_mansion_jyuusetsu_template.xlsx` | 所在地→M58/F77、地番→V77、地目→AD77、地積→AO77、家屋番号→M62、種類→M63、構造→M64、床面積(登記簿)→AD66 |

- 賃貸（建物賃貸借）は登記記録に基づく **所在地・床面積・所有者** を下書き。
  法令制限・災害・ライフライン等のチェック欄は自動判定値を持たないため既定のまま。
- 売買（土地建物）は「（A）売買の目的物の表示」へ **所在地・地番・地目・地積・家屋番号・
  種類・構造・床面積・所有者(売主)** を下書き。代金・期日・数式セルは変更しない。
- **無損失書き込み**: `services/xlsx_patcher.py` が編集対象シートの XML だけを
  書き換え、図形・画像・他シート（表紙等）は元ファイルからバイト単位でコピーします。
  openpyxl の再保存と異なり図形が欠落しません。空の項目はテンプレ既定値を保持します。

### 汎用ドラフトテンプレート

書式を指定しない汎用ドラフトは `templates/jyuusetsu_template.xlsx`（無ければ自動生成）。
セル位置は `services/excel_export_service.py` の `CELL_MAP`（項目→行番号）で調整します。
