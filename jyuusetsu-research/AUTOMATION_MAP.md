# 書類パターン別 自動化マップ

社内 Dropbox `契約・書類/★仲介（賃貸・売買）`（**実ファイル 1,725件**）を種類別に棚卸しし、
**どこまで自動で作れるか**をパターンごとに判定した記録。2026-08-21 実測。

> 元フォルダは**実案件そのもの**（貸主・借主の実名が並ぶ）。**公開リポジトリには一切持ち込まない。**
> 参照するのは `_雛形・マスター様式/` の白紙雛形と、様式の構造（セル座標・項目名）だけ。

## 1. パターン別の自動化可否

判定の基準は `models/property_data.py` の **25項目**（謄本・行政API・e-Stat で自動取得できるもの）。

### ★A 重要事項説明書（賃貸・建物賃貸借用）— いま3項目 → 12項目まで伸ばせる

| | 項目 |
|---|---|
| **自動で埋まる** | 所在地（住居表示・登記記録の両方）／地番／家屋番号／構造／種類／床面積／登記名義人／乙区の権利（抵当権・根抵当権）／土砂災害警戒区域／津波災害警戒区域／造成宅地防災区域／水害ハザード |
| **半自動** | 電気・ガス・水道・排水の供給事業者（地域から推定→要確認） |
| **人が入力** | 賃料・共益費・敷金・礼金・契約期間・更新条件・貸主・借主／設備の有無（現地確認が要る） |
| **欄が無い** | **用途地域・建ぺい率・容積率**（賃貸重説にはそもそも記載欄が無い。実測で確認） |

### ★B 賃貸借契約証書（賃貸契約）— 差し込みは約10項目

雛形の構造（`textutil` で本文を確認）: 第1条 貸室の表示 → 第2条 賃貸借条件 → 第3〜28条は定型条文。

| | 項目 |
|---|---|
| **自動** | 所在／構造／名称（ビル名）／契約面積 |
| **人が入力** | 賃貸人・賃借人／使用目的／賃貸借期間／賃料月額／共益費／保証金／保証金の償却額 |
| **固定** | 第3条以降の条文（2020年民法改正版・特殊詐欺条項入り） |

**要注意: 雛形は `.doc`（旧Word）。** Excel差し込み（`xlsx_patcher`）は使えず、
`python-docx` の別ルートになる。しかも `.doc` は python-docx で読めないので
**Word で `.docx` に保存し直す作業が先に要る**（このPCに LibreOffice は無い）。

### ★★C 重要事項説明書（売買・土地建物）— **最も自動化が効く**

| | 項目 |
|---|---|
| **自動** | 物件表示一式（所在地・地番・地目・地積・家屋番号・種類・構造・床面積・所有者・抵当権）／**用途地域・建ぺい率・容積率**（XKT002）／都市計画区域・区域区分（XKT001）／土砂災害・津波・洪水浸水／最寄駅・駅距離／人口・世帯数／路線価・公示地価 |
| **人が入力** | 売買代金・手付金・引渡日／既存住宅状況調査／石綿使用調査／耐震診断／私道負担／隣地との申し合わせ |
| **取れない** | 防火地域・高度地区（**不動産情報ライブラリに該当レイヤが無い**ことを実測済み。都市計画図で要確認） |

**PropertyData 25項目のうち20項目以上に記載欄がある。** ここを最優先で作るのが投資対効果が高い。

### C' 重要事項説明書（売買・区分所有）

C に加えて **管理費・修繕積立金・管理規約・管理会社** が要る。
これらは管理会社が出す**重要事項調査報告書（PDF）**に載っているので、
**PDF取り込みで半自動化できる**（実物が `売買/ジオタワー南森町/重要事項調査報告書.pdf` にある）。

### D 売買契約書（土地建物 / 区分所有）

物件表示は C と同じデータで自動。売買代金・手付金・引渡日・融資特約は人が入力。
条文は固定。**特約条項は `tokuyaku-generator`(8513) の170項目から続けて作れる導線にする。**

## 2. 既存アプリが担当済み（作り直さない）

| パターン | 担当アプリ | port |
|---|---|---|
| 媒介契約書（66件） | `baikai-generator` — 謄本PDF最大5枚→土地/建物/マンション自動判別 | 8517 |
| 特約事項（12件） | `tokuyaku-generator` — 31カテゴリ170項目 | 8513 |
| 覚書・合意書（22件） | `memorandum-generator` — 12種 | 8524 |
| 決済案内・清算書 | `settlement-creator` — 固都税・管理費の日割り | 8510 |
| 原状回復精算 | `restoration-calculator` | 8508 |
| 送付書・案内文（84件） | `soufu-maker` | 8525 |

**したがって統合アプリがやるべきは A〜D の4書式に絞られる。**

## 3. 未対応だが安く作れるもの（物件＋当事者の差し込みだけ）

`PropertyData` が出来ていれば追加コストが小さい。合計で **80件以上**の実績がある。

- 委任状（12件）／承諾書（13件）／鍵受領書・引渡確認書（24件）
- 解約通知書（3件）／物件状況確認書・付帯設備一覧表（9件）
- 検討申込書・買付証明書（33件）— 雛形が `売買/検討申込書-検討合意書（雛形）.doc` にある
- 仲介手数料契約書（42件）

## 4. 自動化しない・できないもの

- **謄本・図面・公図・測量図（107件）** … 生成物ではなく**入力元**
- **写真（131件）／保証会社の提出書類・身分証** … 対象外。個人情報を含むため取り込まない
- **賃料・敷金・売買代金・手付金・引渡日などの取引条件** … どのAPIにも無い。**人が打つ**
- **設備の有無・現況（エアコン何台・給湯の種類など）** … 現地確認が要る
