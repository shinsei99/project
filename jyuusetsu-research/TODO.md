# TODO — AI重説アシスタント（旧: AI重説調査〜Excel自動入力）

## 🔧 進行中の大改修: 4書式の書類自動作成へ（2026-08-21 着手・オーナー決裁済み）

> 複数セッション・複数ファイル・**稼働中アプリ（8513）に影響**するため様式で書く。

### 目的

**基本4種（賃貸重説 / 売買重説 / 賃貸契約 / 売買契約）を、できるだけ自動で作成する。**
あわせて、いま**同じ物件・売主・買主を3つのアプリに3回入力している**無駄をなくす。
`PropertyData` を単一の真実にし、謄本PDFを1回読ませれば全書式・特約・検算の初期値が埋まる。

### ★ 現状の実測（2026-08-21・ここが出発点）

**調査で25項目を取っているのに、書式へ流し込んでいるのは基本情報の8項目だけ。**
用途地域・建ぺい率・容積率・洪水浸水想定・土砂災害・津波・最寄駅・駅距離・人口・世帯数・
路線価・公示地価の**12項目は、取得済みなのに1つも書式に入っていない**。
自動化率を上げる一番の近道は `format_export_service.FORMATS` の `map` を増やすこと。

| 基本4種 | 手元の書式 | 流し込んでいる項目 |
|---|---|---|
| **賃貸重説** | ✅ `rental_building_template.xlsx`（建物賃貸借用A4） | **3項目だけ**（所在地・床面積・所有者） |
| **売買重説** | △ `sale_mansion_jyuusetsu_template.xlsx`（**区分所有のみ**。土地・戸建て版が無い） | 8項目 |
| **賃貸契約** | ❌ **書式が1本も無い** | — |
| **売買契約** | ✅ `sale_landbuilding`（土地建物）＋ `sale_mansion_contract`（区分所有） | 9項目 |

> **`templates/*.xlsx` は gitignore**（公開リポジトリのため）。別PCへは Dropbox で運ぶ。

### 「全部自動」の正しい線引き（先に決めておく）

- **自動で埋まる**: 物件の表示（謄本）／法令制限（用途地域・建ぺい率・容積率）／災害／
  周辺環境／価格指標 — **調査で取れるもの**
- **人が打つ**: 賃料・敷金・礼金・売買代金・手付金・引渡日・特約の個別事情 — **取引条件**
  （どのAPIにも無い。ここを自動と言うと嘘になる）
- したがって目標は「全自動」ではなく **「調査で取れるものは全部埋まっていて、
  人は取引条件だけ打てばよい」** 状態。完了条件もこの線で測る。

### 実装内容

1. **書式の穴を埋める**（ここが最優先。**人に実書式をもらう必要がある**）
   - **賃貸契約書（建物賃貸借契約書）の白紙書式** … 手元に無い。要提供
   - **売買重説（土地・戸建て用）** … 区分所有版しか無い。要提供
2. **`FORMATS` の `map` を8項目 → 全25項目へ広げる**。取得済みの法令制限・災害・周辺環境・
   価格指標を各書式の該当セルへ流し込む。**賃貸重説は3項目しか入っていないので最優先**
3. **共通モジュールの切り出し**（実装は jyuusetsu 側が新しいので**そちらを正**にする）
   - 謄本PDF解析: `registry_service.py`(46行) ← `legal-crosscheck/registry_parser.py`(96行) を突き合わせ
   - ジオコーディング: `address_service.py`(137行・Google併用) が正。`geo_service.py`(56行) は捨てる
   - 用途地域: `zoning_service.py`(XKT002・100m上限) が正。`admin_research_service.py` は捨てる
4. **③ 特約条項タブを載せる**。**8513 は恒久的に残す**ので、`tokuyaku-generator/clauses.py`
   （170項目・38KB）と本文生成ロジックは **絶対にコピーしない・共有する**。
   コピーすると170項目のカタログが2箇所に分岐し、**片方だけ直した特約が契約書に載る**事故になる。
   → 特約のコアを共有モジュールに置き、`tokuyaku-generator/app.py`（8513）と
   新アプリの③タブが**同じ1本を読む**形にする（`flyer-creator` が `agent-platform/core` を
   使っているのと同じやり方）。**8513側も共有モジュールを読むように書き換える**（ここが作業の肝）。
   売買契約書を作ったら、その特約をそのまま続けて作れる導線にする
5. **④ クロスチェックタブを載せる**。`law_validator.py`(311行) の3レイヤー検閲はそのまま活かす
6. **legal-crosscheck のモックfallbackを廃止**する（`_MOCK_MASTERS`）。
   キー未設定時に「新宿→商業地域80/600」等の**架空の値が"行政の正解"として赤字判定の基準になる**のは
   検閲アプリとして事故の芽。取得できないときは「判定不可」を返す
7. 表示名を **「AI重説アシスタント」** に変更（調査だけのアプリではなくなるため）。
   port は **8536**（8535 まで使用済み。8513 は現役のまま残るので取らない）
