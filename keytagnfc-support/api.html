サーバー連携の仕様と参照実装

KeyTag鍵管理 — Server integration: open API & reference implementation

KeyTag鍵管理は、鍵の台帳を端末の中だけで持つのが既定です。サーバーは要りません。

そのうえで「複数人で同じ台帳を見たい」場合に限り、お使いのサーバーへ接続できます。 接続先はアプリの「設定 > サーバー連携」で入力する方式で、特定のサービスへの加入は不要です。 このページの仕様どおりのサーバーを立てれば、どなたでもご自身の環境でお使いいただけます。

参照実装をダウンロード（keytag-server.py）

Python 3 の標準ライブラリだけで動きます（http.server と sqlite3）。 追加インストールは不要です。python3 keytag-server.py で起動します。

KeyTag stores its key ledger on the device by default; no server is required. For teams that need a shared ledger, the app can connect to your own server. The protocol is documented on this page and a single-file reference implementation (Python 3 standard library only) is provided above. No sign-up or vendor service is involved.

全体の流れ

① ペアリング   アプリに「サーバーURL」と「6桁コード」を入れる
                 → POST /api/pair        → Bearer トークンを受け取る

② 鍵を登録     アプリで「タグに書き込む」を押す
                 → POST /api/register    → サーバーが URL を発行
                 → その URL を NFC タグに書き込む

③ かざす       タグをかざす（URL から token を取り出す）
                 → GET  /api/asset       → いま誰が借りているかが返る

④ 貸出／返却   → POST /api/checkout ／ POST /api/return
  • 認証は Authorization: Bearer <トークン> ヘッダのみ（/api/pair を除く）
  • 本文・応答とも JSON（UTF-8）
  • 応答は必ず {"ok": true, …} または {"ok": false, "error": "…"}
  • ok:false の error はそのまま画面に出ます。利用者に見せてよい文言を返してください
  • アプリは WebView から呼ぶため CORS を許可してください （Access-Control-Allow-Origin、Allow-Headers: Authorization, Content-Type、OPTIONS への応答）

サーバーに繋がらないときは、アプリが自動で端末内の台帳に切り替えます。 現場を止めないための作りなので、サーバーが落ちても操作は続けられます。

タグに書く URL の形

https://<あなたのサーバー>/t/<token>

token は [a-z0-9]{8,32}。アプリはこの形にだけ反応します （それ以外の URL が書かれたタグは「ただのURL」として扱われます）。

この URL はブラウザで開いても意味のあるページを返してください。 アプリを入れていない人がタグをかざしたときに、鍵の状態が読めるようにするためです。

エンドポイント

1. POST /api/pair — 端末をつなぐ

6桁コードを Bearer トークンに引き換えます。認証不要（これだけ）。

要求{"code": "123456"}
応答{"ok": true, "token": "…", "organization": "サンプル商事"}
失敗{"ok": false, "error": "コードが違います"}

organization はアプリの設定画面に「✅ ◯◯ と連携中」と表示されます。 コードは使い切り・有効期限つきにしてください（参照実装は30分）。

2. GET /api/ping — つながっているか確かめる

応答{"ok": true, "organization": "サンプル商事", "user": "デモ端末"}

3. POST /api/register — 鍵を1件登録し、タグに書く URL を返す

アプリが「タグに書き込む」の直前に呼びます。

要求{"property_name":"サンプルマンション", "name":"101号室 玄関", "box_position":"A-3", "item_number":["10001","10003"], "item_qty":["1","3"]}
応答{"ok": true, "url": "https://…/t/16988f8dc0f55215"}

item_number と item_qty は同じ長さの配列（鍵番号ごとの本数）。 応答に url が無い場合、アプリはサーバー無しの内容だけをタグに書きます（失敗しても書き込みは続行）。

4. GET /api/asset?token=<token> — かざした鍵の状態

登録あり{"ok": true, "found": true, "asset": {…}, "borrowers": [...], "dues": [...]}
登録なし{"ok": true, "found": false}

asset（そのまま画面に出ます）

キー例意味
property_nameサンプルマンション物件名
name101号室 玄関鍵の名称
labelサンプルマンション / 101号室 玄関一覧用の表示名
item_numbers10001 / 10003 ×3鍵番号（表示用の文字列）
total_keys4合計本数。2本以上だと返却時に本数確認を促す
box / box_nameA-3 / 保管場所
statusin_stock / checked_out状態
status_label保管中 / 貸出中画面に出す文字
borrower{"name","company","kind","phone"} または null貸出中のときだけ
checked_out_at / due_at2026/08/28 09:25整形済みの文字列（ISO ではない）
elapsed2時間15分貸出からの経過
is_overduetrue / false返却期限超過

borrowers — 貸出先の候補。 [{"id","name","company","kind","open_count"}]。 open_count は「その人がいま借りている件数」。よく使う人を上に並べてください。

dues — 返却予定の選択肢。 [{"label":"今日 18:00","value":"2026-08-28T18:00:00+09:00"}]。 サーバー側で作るので、会社の運用に合わせて変えられます。

5. POST /api/checkout — 貸出

要求{"token":"…", "borrower_id":"B1234", "new_name":"", "new_kind":"vendor", "new_company":"", "new_phone":"", "due_at":"2026-08-28T18:00:00+09:00"}
応答{"ok": true, "asset": {…}}
失敗{"ok": false, "error": "この鍵はすでに貸出中です"}
  • borrower_id が空なら new_name で新しい貸出先を作ります（どちらか必須）
  • new_kind は vendor / customer / employee / other
  • 二重貸出はサーバー側で止めてください。2台の端末が同時に押しても壊れないようにするためです

6. POST /api/return — 返却

要求{"token": "…"}
応答{"ok": true, "asset": {…}}
失敗{"ok": false, "error": "この鍵は貸出中ではありません"}

返却後、アプリは GET /api/asset を呼び直して貸出先の候補を取り直します。

参照実装を動かす

python3 keytag-server.py
# ─────────────────────────────────────────
#  サーバーURL     : http://192.168.1.20:8765
#  ペアリングコード : 090190   （30分で失効）
#  台帳を見る       : http://192.168.1.20:8765/
# ─────────────────────────────────────────
  1. iPhone とサーバーを同じネットワークに置きます
  2. アプリの「設定 > サーバー連携」に URL と 6桁コードを入れて［連携する］
  3. 「タグに書き込む」で鍵を作ります → タグにサーバーの URL が書かれます
  4. かざすと、貸出・返却がサーバー側に記録されます
  5. ブラウザで http://<サーバー>/ を開くと、台帳が一覧で見えます。 別の端末からかざしても同じ内容になります

参照実装は社内LAN・VPN の内側で動かしてください。 認証は最小限です。インターネットに出す場合は HTTPS と、組織に合わせた認証を足してください。
