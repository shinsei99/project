# ワンピースカード図鑑（onepiece-dex）

ONE PIECEカードゲームの日本語版カードを、名前・カード番号・色・種類・レアリティ・
特徴で引ける図鑑。自分専用（port 8537 / 127.0.0.1）。

    ./run.sh    →  http://127.0.0.1:8537

**ポケモンカード図鑑（`pokecard-dex`・8531）をベースに作った**が、データの取り方は
まったく違う。下の「なぜマイカを使わないか」を読んでから触ること。

## どこから何を取っているか

| ソース | 担当 |
|---|---|
| 公式サイト **カードリスト**（`/cardlist/`） | カードの全部（番号・レアリティ・種類・色・コスト・パワー・カウンター・属性・特徴・テキスト・入手情報・画像） |
| 公式サイト **商品ラインナップ**（`/products/`） | **商品パッケージ画像・発売日・価格・商品分類**（拡張パック/構築デッキ/その他） |

カードリストは**シリーズしか持っていない**（パッケージ画像も発売日も入っていない）。
ポケカ図鑑と同じ「拡張パックの表紙を並べてそこから収録カードへ入る」画面にするには
商品ラインナップ側が要る。記号【OP-17】で突き合わせる。

**1ソースで足りる。** ポケカが4ソース（マイカ・TCGdex・公式・learn-book）の継ぎ接ぎに
なったのは、**公式がレアリティを非公開**で、かつ**公式の画像ファイル名がカード番号と
紐づかない**（通し番号）という2つの事情による。ワンピ公式にはどちらも無い。

- レアリティは `<div class="infoCol">` に `OP17-001 | L | LEADER` と刷り込まれている
- 画像は `images/cardlist/card/OP17-001.png` ＝ **ファイル名がそのままカード番号**。
  別イラストは `_p1` `_p2` `_p3`（`_r1` もある）が付く。取り違えが起きない

### 画像の「SAMPLE」の透かしは消せない（2026-08-23 調査済み・**回り道をした記録**）

公式の画像は 600×838 で、**絵の中央に大きく「SAMPLE」が焼き込まれている**。
これを嫌ってDMMマイカの画像を主にしようとしたが、**マイカの画像にも同じ SAMPLE が
入っていた上に 400×559 と公式より低解像度**だった（実物で確認）。**マイカに替える
意味は無い。** 同じことを試さないこと。取得スクリプトは消したが、調べた内容は残す。

- マイカの画像URLはカード番号から組み立てられる（巡回不要）:
  `https://static.mycalinks.io/app/item/OP/card/<配られたパック>/<カード番号>.jpg`
  フォルダは**そのカードが配られたパックの記号**で、カード自身のセット記号ではない
  （`OP-17/EB04-061_p3.jpg` は200・`EB-04/EB04-061_p3.jpg` は404）。プロモは `PROMO/`
- 収録シリーズ＋セット記号の2候補を順に試して 4,962枚中 **約91%** が当たった

透かしの無い画像は公開されていない。文字も数値も読めるので図鑑としては成立する。
画面にも「公式の画像に元から入っている」と書いて、不具合と誤解されないようにしてある。

### DMMマイカの「カードページ」は巡回しない（相場を足すときの注意）

`https://myca.dmm.com/one-piece-card-game/items/single-card/<ID>` は開くが、
**IDはゲーム横断で、パスの `one-piece-card-game` は絞り込みとして効かない。**
`.../single-card/10` を叩くと**ポケモンの旧裏カード**（`option1: ポケモン`）が返る。
ワンピだけ狙い撃ちできず、ポケカと同じ全ID巡回（数時間）が要る。

オーナー判断（2026-08-23）: **まず公式だけで完成させ、不足が出たら他サイトを検討。**
`dex.price` 列は空のまま用意してあるので、後から相場を足しても画面は壊れない。

## 実行の順番

    python crawl_official.py     # 全62シリーズ巡回（約1分）
    python crawl_products.py     # 商品156件＋パッケージ画像（約1分）
    python fetch_images.py       # 画像4,962枚（約1.2GB）
    python make_thumbs.py        # 一覧用サムネイル180px
    python build_dex.py          # 図鑑テーブルを組み立て（ネットワーク不要）
    python check_dex.py          # 整合性の検査
    ./run.sh                     # http://127.0.0.1:8537

**`fetch_images.py` はDBに書かない。** どの画像を持っているかは「ファイルがあるか」が
正で、図鑑へ移すのは `build_dex.py` の仕事。以前は1枚ごとに UPDATE していたが、
200枚ごとにしか commit せず**書き込みロックを2分近く握りっぱなし**になり、裏で
`build_dex.py` を流すと `database is locked` で落ちた。読むだけならぶつかりようがない。

`crawl_official.py` と `build_dex.py` は何度流しても同じ結果になる（冪等）。
新弾が出たら順に流し直せばよい。画像取得は既にあるファイルを取りに行かない。

## 実測で分かった、はまりやすい点

**カードリストは POST でないと返らない。**
`GET /cardlist/?series=550117` は 200 を返すが**中身はシリーズの選択肢だけ**で、
カードが1枚も入っていない（51KB）。`POST /cardlist/` に `series=550117` を送ると
463KB のカード入りHTMLが返る。JSで描いているわけではないので、ブラウザ自動操作は要らない。

**`/cardlist`（末尾スラッシュなし）は301。** `curl` は `-L` を付けないと空で返る。
POST を301でリダイレクトすると GET に化けるので、**最初から `/cardlist/` を叩く**こと。

**LEADER だけ「コスト」の見出しが「ライフ」。** HTMLの構造は同じ
`<div class="cost">` だが、中の `<h3>` が `ライフ` になる。値の意味が違うので、
`cost_label` 列に見出しをそのまま保存して画面でも出し分けている。

**属性は文字ではなく画像。** `<div class="attribute"><img alt="打">` の `alt` に
「打／斬／特／知／射」が入っている。無いカード（EVENT・STAGE）は `-`。

**カード1枚が複数シリーズに載る。** 例: `EB04-061_p3`（EB-04のカード）は
**OP-17のシリーズページにも出てくる**（そのパックで配られた別イラストのため）。
`cards` は1枚1行のまま、収録関係は `card_series`（多対多）に分けて持つ。
シリーズの枚数は `card_series` で数える。

**色は多色がある。** `赤/緑` `青/紫` のように `/` 区切り。絞り込みで「赤」を選んだ
ときに多色も出るよう、`dex_colors` に1色ずつばらして持つ。特徴（`四皇/白ひげ海賊団`）
も同様に `dex_features` へばらす。

**`executescript()` は busy_timeout を無視する。** 裏で画像取得が走っていると
`build_dex.py` が0秒で `database is locked` に落ちた。同じDBに `execute()` で
`BEGIN IMMEDIATE` を投げたほうは46秒待って成功した（実測）。DDLを流すところは
executescript をやめて1文ずつ `execute()` している。DBは WAL にしてある。

**商品ラインナップはページ送りがあり、同じページ内に同じ商品が2度出る。**
`?subcategory=all&page=N`（1〜15・1ページ12件）。重複を1件ずつ弾かないと
171件拾って実数156件、という取りこぼし方をする。

**商品ページURLの末尾スラッシュに注意。** `/products/boosters/op17/` を basename すると
**空文字**になり、そういう商品のパッケージ画像が全部同じ名前に潰れる（実際に発生。
171件中152件しかファイルが残らなかった）。`rstrip("/")` してから取る。

**8シリーズは商品ラインナップに載っていない**（ST-02〜04・ST-16〜20）。現行の
ラインナップから外れているため。名前の頭で分類し、表紙は**リーダーの絵を借りる**
（画面にもその旨を書いてある）。発売日は「発売日不明」と出す。

**「スーパーパラレル（コミパラ）」は公式データに区分が無い。** カード自体は
別イラストとして全部入っている（参照した一覧の36型番すべてDBに存在することを確認済み）が、
レアリティは通常と同じ（OP17-005 は通常も `_p1` も `_p2` も一律 `SR`）。
HTMLにも差が無く、**公式データだけでは絞り込めない**。枠の有無で機械判定も試したが
当たらなかった（EB01-009_r1 はコミパラなのに縁のばらつきが小さい）。
やるなら手で作った型番の一覧を持つしかない（2026-08-23 時点では作っていない）。

## テーブル

| テーブル | 中身 |
|---|---|
| `cards` | 巡回した生データ。**書き換えない** |
| `series` | シリーズ62件（公式の並び順 `sort` つき） |
| `card_series` | どのカードがどのシリーズに載っているか（多対多） |
| `unparsed` | 読めなかったHTML。**捨てない**（欠番と読み落としを混ぜないため） |
| `dex` | 画面が引く図鑑。`rarity_i`（並び順）や日本語ラベルを足したもの |
| `dex_series` | シリーズ＋収録枚数・画像枚数・表紙 |
| `dex_features` / `dex_colors` | 特徴・色を1件ずつばらしたもの（絞り込み用） |

`dex*` は `build_dex.py` が毎回 DROP して作り直す。生データは触らない。

## 画面

- **📦 拡張パック** … パッケージ画像・発売日・収録枚数のタイルから収録カードへ（23件）
- **🗃 構築デッキ・その他** … 同じ形。構築デッキ37件 / その他の商品2件（プロモ・限定商品）
- **🔎 さがす** … カード名／`OP01-001` 形式の番号／数字だけなら全シリーズ横断の番号検索。
  色・種類・レアリティ・特徴で絞り込み。**テキスト（効果文）は検索対象にしない**
  （「ルフィ」で効果文にルフィが出る別カードが大量に混ざり、探しものが埋もれる）
- **👑 リーダー** … リーダーだけを色別に。ワンピはリーダーを決めてから組むので独立の入口にした

一覧は180pxサムネイル＋150枚ずつのページ送り。原寸PNGは1枚200〜300KBあり、
169枚のパックをそのまま並べると40MBをブラウザへ送ることになる。
