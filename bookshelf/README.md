# bookshelf — 自炊本のOCR作り直しと、知識索引への配置

自炊した書籍PDFを **読める・引ける**状態にして、AI業務マネージャーの知識索引へ入れるまでの道具。
2026-08-29 に蔵書77冊（21,482ページ）を通した実績がある。

**本のPDFそのものはここに置かない**（著作物・容量）。実体は Dropbox `書籍/`。

---

## なぜ作ったか

自炊本のOCR（スキャナ付属）が使い物にならなかった。**画像は300dpiできれいなのに、
テキスト層だけが壊れている**状態で、デジタル書斎の本文表示も検索も機能しなかった。

決め手は**縦書き**だった。実測:

| エンジン | 縦書きページの結果 |
|---|---|
| スキャナ付属OCR（`SS Manager for fi Series`） | 1文字ずつバラバラ |
| Apple Vision 従来の `VNRecognizeTextRequest` | **15文字しか取れない** |
| **`RecognizeDocumentsRequest`（macOS 26〜）** | **1,235文字を読み順どおり** ✅ |

**AIサービスではない。** OSに入っている機能なので、通信なし・課金なし・データは端末から出ない。

## 手順

```bash
S=~/bookshelf
cd "$S"

# 0. OCRの実行ファイルを作る（初回のみ。macOS 26 以降が要る）
swiftc -O -parse-as-library dococr.swift -o dococr

# 1. 棚卸し（どの本が壊れているか。OCRはしない・数分）
python3 survey.py "/Users/apple/Library/CloudStorage/Dropbox-個人/書籍" > survey.jsonl

# 2. 作り直して原本の場所へ入れ替え、題名へ改名する
#    ★検証に通らなければ原本に触らない（ページ数・全ページの画像が原本とバイト単位で同一・本文あり）
python3 replace_all.py --limit 10 --shard 0/4   # 4並列で流すなら shard を 0..3 で4本

# 3. 裏表紙のISBNから書誌を引く（出版年月・正式書名・出版社・著者）
python3 isbn.py            # openBD（新刊流通）
python3 ndl.py <ISBN>      # 国立国会図書館サーチ（openBDで落ちた古い本・ムック）

# 4. 棚と用途を決める
python3 shelves.py         # → assign.json

# 5. 知識索引へ入れて棚に置く
python3 ingest_all.py law    # 一次資料
python3 ingest_all.py case   # 判例（RETIO）
python3 ingest_all.py book   # 本

# 判例の取得（RETIO機関誌。号を指定）
python3 retio.py 138 134
```

## 分かったこと（次に同じ作業をする人へ）

### 速度

- **1本流し 1.38秒/ページ、4並列 0.77秒/ページ（1.8倍）。8並列にしても改善しない**
  （Vision側で直列化している）。実測は 21,482ページ / 約6時間
- 文書OCR（`RecognizeDocumentsRequest`）は通常OCRより重い。114ページで約12分

### 品質

- **本文サイズの文字はほぼ正確。6〜7ポイントの脚注・出典表記で崩れる**
  （例: 業界→楽界、着眼点→活眼点、翔泳社→3泳社）。**引用の正確さが要る用途では原本を見る**
- **段組みを解ける。** 従来OCRは2段組みを1行ずつ交互に拾って意味が通らなかった
- 漫画は吹き出しの位置順に出る（話の流れの順ではない）

### 指標

- **ひらがな率は当てにならない。** 壊れたテキスト層は縦書きを1文字ずつ拾うので、
  **読めないのにひらがな率が高く出る**（実例: 23.2% → 22.8% でほぼ動かないのに文章として読める形になった）
- 使うなら **1行の文字数の中央値**。2文字以下なら壊れている（デジタル書斎の `pdfClient.ts` と同じ見方）
- 図表主体の本はひらがな率が構造的に低い。OCRの失敗ではない

### 書誌

- **ISBNは奥付ではなく裏表紙にある**ことが多い。OCRは数字を誤読するので**チェックディジットで検算する**
- **openBD は新刊書店の流通データ**なので、ムック・古い本・専門書は落ちる。**NDLサーチで拾える**
- **ISBNが読めない本は、書名でもNDLで引ける**（77冊中3冊がこれで埋まった）
- **スキャン日は出版日の手がかりにならない**（2024年スキャンの本が2022年出版だった）

### 入れ替え

- **二重に持たない。** 新ファイルを作って原本を消すのではなく
  「一時ファイル → 検証 → 原本の場所へ `os.replace` → 題名へ改名」の順にする
- **上書き前に必ず検証する。** 1つでも合わなければその本は飛ばして原本を残す
- Dropbox は削除・変更から30日は版を戻せる（最後の保険）

## 棚と用途（`shelves.py`）

**年数の基準は分野ごとに変える。** 税制は毎年変わるので3年でも古い。一方
マーケティング理論や商業集積の見方は20年経っても変わらない。同じ「5年」で切ると
どちらかで必ず間違える。

| 棚 | 古さの基準 |
|---|---|
| 税務・お金 | 3年 |
| 不動産実務／投資 | 5年 |
| 物件企画・地域／経営・理論／小説資料 | 年数を見ない（法令を語らないので） |

`use_scope` は**その資料を何に使ってよいか**:

- `full` … そのまま使える。法令・数値・要件も引いてよい（一次資料、直近の実務書）
- `concept` … **考え方だけ**。法律・税率・要件・期限は引かない（古い本）
- `case` … 判例・紛争事例

**古い本を丸ごと捨てない。** 変わらない部分（サービス業の考え方、承継の発想）まで失うため。
逆にそのまま使うと、消費税5%時代の税率を根拠に出してしまう。**同じ本でも用途で線を引く。**

## 無料で手に入る一次資料

**本を買う前にこちらを見ること。** 2026-08-29 の実測では、
「賃貸管理業法・宅建業法・電子帳簿保存法の本を買うべき」と考えていたが、
**一次資料のほうが新しく確実**だったので3冊ぶん不要になった。

| 出どころ | 内容 |
|---|---|
| 国土交通省 | 原状回復ガイドライン／標準契約書／標準管理規約／長期修繕計画／賃貸住宅管理業法 解釈運用・FAQ／宅建業法 解釈運用 |
| 国税庁 | インボイスQ&A／電子帳簿保存法 一問一答 |
| 個人情報保護委員会 | 個人情報保護法ガイドライン（通則編） |
| **RETIO（不動産適正取引推進機構）** | **機関誌のバックナンバーに「最近の裁判例」「紛争事例検討報告」が号ごとにPDFで無料公開**（`retio.py` で取得） |

APIも無料・鍵不要のものがある:

- **e-Gov法令API**（`/Users/apple/egov_law_api.py`）… 現行条文＋**施行日**
- **国会会議録API** … `https://kokkai.ndl.go.jp/api/speech?any=<語>&recordPacking=json`
  立法趣旨・運用の実態・大臣答弁。**通達にAPIが無いので、その穴を部分的に埋める**
- **openBD / NDLサーチ** … 書誌

**取れないもの**: 国税庁の法令解釈通達（本文）、裁判例の網羅DB、自治体の条例。

## AI業務マネージャーに繋いだあとの学び（2026-08-29）

索引に入れても**回答に出てくるとは限らない**。実際の回答を4回見て、3つの見落としを潰した。

**★着手前に、この3つを実測してから直すこと。**

1. **回答を作っているのはどの関数か。**
   このアプリは `_agent_prompt`（エージェント型）が本番で、`build_prompt` は
   claude がエラーを返したときのフォールバック。build_prompt だけ直しても効かない
2. **動いているプロセスはどれか。**
   `worker`（Chatwork）と `-line`（LINE）は**別プロセス**。片方だけ入れ替えても、
   もう片方は古いコードのまま動き続ける
3. **エージェントに何が見えているか。**
   関数に引数を足しても、**道具のカタログ（REGISTRY の desc/usage）に書かなければ
   エージェントは使えることを知らない**。docstring は見えない

そのほか:

- **1回でまとめて引くと、件数の多い種別が上位を全部埋める。** 自社書類が12件で埋まって
  法令が押し出されていた。**種別ごとに枠を確保してから混ぜる**
- **人名の置換は誤爆する。** 同じ姓が物件名（`杉田ビル`）や別人（`服部雅輝`）にも出る。
  **敬称付きのときだけ**置き換える
- **資料の年は自社書類にも出す。** ファイルの更新日が新しくても中身は古い。
  マニュアルの担当者名を「現在の担当」と断定して実害が出た
