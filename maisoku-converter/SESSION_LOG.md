### 追記（同日・2回目）— 「少し幅が広い」への対応

実物（`帯変え案内書_加東市秋津_ログハウス_3LDK_photo_first.xlsx`）を測ったところ、
**自社帯は 202mm 幅（＝紙幅いっぱい）なのに、マイソクの中身は 181mm** だった。
元マイソクが左右に 5% ずつ白フチを持っているためで、**帯だけが左右へ 10mm ずつ張り出して**見えていた。

- **本体（マイソク枠＋自社帯）の幅を A4縦のとき 195mm に固定し、中央寄せにした**
  （`_BODY_MM_PORTRAIT = 195.0`／左右余白を各 7.5mm にして `horizontalCentered` で中央へ）。
  マイソクの形やフチの太さが変わっても**帯の幅と位置が動かない**のが利点。A4横は従来どおり 289mm。
- **`trim_white_margins()` を追加**（画面のチェックボックスで任意・既定はオフ）。
  外周の白フチを検出して切る。切ると中身が帯と同じ幅まで広がり左右がそろう。
  暴走しないよう歯止めを2つ入れた: **1辺で 30% を超えて切ることになるなら切らない**
  （白地に小さく置いた写真・枠線デザインを壊さないため）／**残りが元の半分未満なら切らない**。
- `smoke_test.py` に、195mm・中央寄せの確認と、白フチカットの4ケース（切る／フチ無し／
  切りすぎ回避／真っ白）を追加。

実測（ログハウスのマイソク・比 0.812）: 用紙 A4縦、画像枠 **195 × 240mm**、自社帯 高さ 18.7mm。
白フチカットを入れると 194 × 268mm（縦が先に当たるので幅は 194mm になる）。

### 追記（同日・4回目）— 「縦横比が変わって縦が圧縮されている」の原因と修正 ★重要

ユーザーの指摘どおりで、**私の確認不足だった**。xlsx の中身の数値と自作の描き起こしだけを見て
「合っている」と言っていたが、**Excel で開いて実測していなかった**。実測したら2つ壊れていた。

**① 列幅→ピクセルの換算が間違っていた（これが縦圧縮の原因）**

`列幅(文字) × 7px` で計算していたが、Excel に実測させると **1文字 = 6pt（8px）** だった。

```
生成した .xlsx を Excel for Mac で開き AppleScript で問い合わせ:
  A..AX（幅3.796875 の列 50本）= 1150pt   ← round(3.796875*6)=23pt × 50
  旧モデルの見積もり            =  997pt（2割狭い）
```

枠を 2割狭く見積もったまま **TwoCellAnchor**（＝セル範囲に合わせて画像を伸縮する貼り方）で
貼っていたので、画像がセル範囲まで**横に約1.2倍引き伸ばされ**、縦が縮んで見えていた。

- `_col_px()` / `_row_px()` を新設し、換算を1か所に集約（`_PT_PER_CHAR = 6.0`）
- **貼り方を OneCellAnchor（実寸をEMUで固定）に変更**。これなら見積もりが多少ずれても
  **絵が歪むことは無く**、位置が少しずれるだけで済む
- `thumbnail()` は縮小しかしないので、元画像が枠より小さいときに枠いっぱいにできなかった。
  表示寸法を別に計算するよう修正
- 行高は **整数ポイントで割り振る**ようにした（Excel が整数に丸めて描くため）。
  全行を同じ値に丸めると 52行分の誤差で縦横比が2%狂うので、端数のぶんだけ1pt大きい行を混ぜる

**修正後に Excel が返した実測値**（加東市上三草戸建てのマイソク）:

| | 値 |
|---|---|
| 自社帯の幅 (A..AX) | 1150.00pt |
| 貼った画像の幅 | 1149.75pt（**帯とぴったり一致**） |
| 画像の縦横比 | 0.8141（元画像 0.8141 ＝**歪みなし**） |

**② 白フチの自動カットが効いていなかった**

チェックボックスの既定値を False→True に変えても、**すでに開いている画面では
古い状態（False）が残る**（Streamlit はキーが同じだと既定値より状態を優先する）。
`key` を `bs_trim` → `bs_trim_v2` に変えて解決。作成後のメッセージにも
「白フチを切って貼りました／切らずに貼りました」を出すようにした。

### 発生したエラーと解決策

- 症状: 出力した .xlsx の見た目を確かめようとして、Excel を AppleScript で PDF 書き出し
  → `パラメータのエラーです。(-50)` で失敗。ユーザーの画面にオートメーションの
  アクセス権ダイアログが出た。
  → 原因: Excel for Mac の AppleScript は `save as ... file format PDF file format` が
  実質使えない（`/private/tmp` 配下だとエラーも出ずに無言で失敗する）。
  → 直し方: **Excel は使わない**。`qlmanage -t` は埋め込み画像を描かないので、
  xlsx の列幅・行高・結合・罫線・画像アンカーを読んで **fitToPage の縮尺どおりに
  PIL で描き起こす検証スクリプト**を書いて目視した（scratchpad 内・出荷物ではない）。
- 症状: `./va.sh upload 'input[type=file]' <PDF>` が効かない（アップロード欄が空のまま）。
  → 原因: **サイドバーの「会社ロゴ」も `input[type=file]`** で、そちらが 0 番目に当たっていた。
  → 直し方: `'input[type=file] >> nth=1'` を指定する。ロゴは PDF を渡しても
  `Image.open` が例外を投げて弾かれるだけなので、上書きはされていない（確認済み）。
- 症状: `./va.sh shot` に URL を渡しても、**前に開いていたページ**（8536 の別アプリ）を撮っていた。
  → 直し方: `./va.sh goto <url>` → `./va.sh shot` の順に叩く。

### 追記（同日・2回目）— プレビューが小さくて細かく合わせられない、への対応

「もっと細かく調整したい／プレビューが小さい」という指摘を受けて3点直した。
**大きさだけの問題ではなく、刻みが 0.005（0.5%）で頭打ちだったのが効いていた。**

- **刻みを 0.005 → 0.001 に**（`_REGION_STEP`）。1240px幅の原稿なら 6.2px 単位 → 1.2px 単位。
- **プレビューを大きくした**。列比を 1:2 → 1:3 にし、「プレビューの大きさ」
  （640〜1600）を選べるようにした。**1200以上を選ぶとスライダーが上段（横4列）に移り、
  プレビューが横幅いっぱいになる**（左右2列のままでは幅が足りず、実測 926px で頭打ちだった → 1198px）。
- **拡大鏡を付けた**。辺や角をつかんでいる間、その点の周りを ×3.5 で表示する
  （注目点と重ならない側の隅に出る）。境界に線を合わせる作業はこれが一番効く。
- **矢印キーで1ドットずつ動かせるようにした**。■を1回クリックすると
  そのハンドルが選択状態になり、矢印キーで1ドット（Shiftで10ドット）。
  連打で毎回Streamlitを再実行しないよう 450ms の debounce を入れている。
- 数値表示に**元画像のピクセル値**を併記（例: `下 82.4% (1445px)　切り取り 1240 × 1445px`）。

検証（Playwright・合成テスト画像・Console エラー0件）:
プレビュー幅 926 → 1198px ／ 拡大鏡はドラッグ中のみ表示・離すと消える ／
矢印キー3回で 1463 → 1459px、Shift+1回で 1445px、スライダーも 0.824 に追従。

**やっていないこと**: 拡大鏡の倍率は ×3.5 固定（変えられない）。
上段レイアウトへの切り替えは 1200 を境にした固定判定で、画面幅は見ていない。

### 発生したエラーと解決策

- **症状**: 枠をドラッグ → 「範囲をリセット」を押すと一度は初期値に戻るのに、
  その次に何かボタンを押した瞬間、リセット前のドラッグ値へ勝手に戻る。
  **原因**: リセット処理で `st.session_state.pop("band_drag_seen")` していた。
  コンポーネント側の値（`st.session_state["band_crop_editor"]`）は古いドラッグ値を
  保持したままなので、次の実行で「見たことがない新しい値」と判定され再採用されていた。
  ボタンの処理は取り込み判定より**後**に走るため、効くのが1実行遅れて分かりにくかった。
  **直し方**: 消すのではなく `_forget_last_drag()` で
  「コンポーネントに残っている値＝もう見た値」として `band_drag_seen` に記録する。

- **症状**: スライダーの表示が `0.005` なのに `0.01` と出る。
  **原因**: `st.slider` の既定書式が小数2桁。刻みを 0.005 にしたので丸められていた。
  **直し方**: 4本とも `format="%.3f"` を指定。

- **注意（自分でやらかした）**: `./va.sh upload 'input[type=file]' …` は
  **サイドバーのロゴ欄が先に当たる**。`company_logo.png` を検証用画像で上書きしてしまい、
  `git checkout` で復元した。以後は `[data-testid="stMain"] input[type=file]` と
  メイン領域に限定して指定すること。
