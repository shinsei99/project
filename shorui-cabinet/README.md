# 書類キャビネット (shorui-cabinet)

**紙の書類が物理的にどこにあるか**を記録・検索するアプリ。「あの物件の契約書どこ？」を解決する。

- 分類: 不動産 / port **8528** / **自分専用（localhostバインド・社内LAN共有なし）**
- AI: ローカルの `claude` CLI（**APIキー不要・Claude Codeのサブスク内で動く**）

## 管理の単位は「ファイル1冊」

**クリアファイル1冊・バインダー1冊・箱1つ**が登録の単位。**書類1枚ずつは登録しない。**

1枚ずつ登録すると数百枚で作業が終わらず、台帳が続かなくなる。実際に探すときも
「どの箱を開ければいいか」まで分かれば十分なので、そこに合わせてある。

一方で**中身の目録はAIが写真から自動で起こす**ので、検索は書類名・人名・物件名の粒度で効く。
人の手間は1冊あたり1回、検索精度は1枚ずつ登録した場合に近い、という設計。

## 使い方

1. クリアファイルの中身を**パラパラと数枚撮る**（表紙だけでなく中の書類も）
2. 「🤖 中身を読み取る」→ AIが目録・物件名・種別・年代・見出し名を自動生成
3. **保管場所を選んで登録**（人が入力するのは実質ここだけ）

写真を使わず手入力だけでも登録できる。

### 実測例（写真3枚 → 58秒）

賃貸借契約書・重要事項説明書・鍵預り証の3枚を撮ると、こう出力される。

```json
{
  "label": "グランドメゾン天王寺 302号室 賃貸借契約関係",
  "properties": ["グランドメゾン天王寺 302号室"],
  "doc_types": ["賃貸借契約書", "重要事項説明書", "鍵預り証"],
  "year_from": "2026", "year_to": "2026",
  "contents": [
    "2026-05-15 重要事項説明書 … 宅地建物取引士 佐藤 一郎",
    "2026-05-20 建物賃貸借契約書 … 賃貸人 大京商事株式会社／賃借人 山田 太郎 月額82,000円",
    "2026-06-01 鍵預り証 … 受領者 山田 太郎 預り本数3本"
  ]
}
```

和暦（令和8年5月20日）→ 西暦の変換、日付順の整列まで自動。

## 画面

| タブ | 内容 |
|---|---|
| 📥 ファイルを登録 | **倉庫でスマホから送った写真**を拾う／中身を撮る → AIが目録化 → 保管場所を選んで1冊登録 |
| 🔍 さがす | キーワード（**中身の目録まで横断**）／種別／物件／場所で絞り込み。CSV出力 |
| 📄 PDFを整理 | **全文PDF化したもの**を**書類1件ずつに分割**＋種類・日付・タイトル付け → ZIPで受け取る／台帳へ送る |
| 🗄 保管場所 | 「本社3F 書庫A / 棚2」の粒度で登録。場所ごとの在庫一覧 |
| ⚙️ 設定 | 物件マスタ（Excel/CSVから一括取込）、CSV・DBバックアップ |

## 起動

```bash
./run.sh    # 初回は venv 作成＋依存導入
```
→ http://localhost:8528

## AI読み取りの仕様

| 入力 | 経路 | モデル | 目安 |
|---|---|---|---|
| テキスト層のあるPDF | テキストを渡す | sonnet | 数秒〜十数秒 |
| 写真・スキャン画像PDF | 画像化→**向き自動補正**→ビジョン | **opus** | 写真3枚で約60秒 |

**画像経路に opus を使っているのは実測にもとづく判断。** sonnetだと固有名詞を推測で
置き換える誤り（「グランドメゾン天王寺」→「プラチナハイツ大手町」、「大京商事」→「大和商事」、
「82,000円」→「28,000円」等）が2回に1回程度発生した。opusでは3/3で正解。
誤った物件名で登録されると二度と探せなくなるため、速度より正確さを優先している。

向き補正は共有モジュール `pdf_orient.py`（他アプリと同じもの）。横向き・逆さのスキャンでも正立に直す。

**`confidence` が medium / low のときは画面に警告が出る。物件名など固有名詞は目視で確認すること。**

## スマホから送る

倉庫では [書類おくる](../shorui-mobile)（スマホ用PWA・Vercel `shorui-mobile.vercel.app`）で
クリアファイルの中身を撮って送る（`shorui-sender` は重複のため 2026-08-09 に廃止済み）。
個人Dropboxの `書類取込/<名前>/` に届き、「📥 ファイルを登録」に一覧される。
**フォルダ名がそのまま見出しになる。** 取り込みフォルダの既定:

```
~/Library/CloudStorage/Dropbox-個人/書類取込
```

読み取ったフォルダは登録が済んでから `_done/` へ移動する（消さない）。

## データ

- `data/cabinet.db`（SQLite）… ファイル・保管場所・物件マスタ
- `data/thumbs/`… 一覧表示用のサムネイル
- ⚠️ **物件名・所在を含むため `data/` は gitignore**。他PCではDBを手で持ち込む

## 他アプリとの役割分担

| | 対象 | 用途 |
|---|---|---|
| **書類キャビネット**（これ） | **紙の原本** | 物理的な置き場所を管理 |
| file-finder (8520) | 共有ドライブのファイル | メタデータ横断検索 |
| デジタル書斎 | OCR済みPDF | 中身の全文検索 |

PDF化しても権利証や実印を押した契約書原本は捨てられないため、紙の所在管理は残る。

## 続けられなくなったときの対処

この種の台帳は**更新されなくなった時点で「無いより悪い」**（あるはずの場所に無い状態になる）。
そうなったら、次のどれかに切り替えるのが現実的。

- **用途を絞る** — スキャン代行に出す前の棚卸しなど、期間限定の目的だけに使う
- **社内共有にする** — 自分以外が探せると価値が跳ね上がる。`run.sh` の `127.0.0.1` を `0.0.0.0` に変えるだけ
- **やめる** — 探せなくて困る頻度が年に数回なら、維持コストのほうが高い

## メモ: スキャン代行を使う場合

段ボールで送ってPDF化して返してもらうサービスがある（相場: A4白黒3〜4円/枚〜、カラー8〜10円/枚〜）。
ただし**最低料金5万円前後**の会社が多く、これは高性能スキャナ1台分とほぼ同じ。
数百枚程度なら自前スキャンのほうが安い。数千枚（段ボール単位）から代行が有利。

契約書は個人情報を含むため、**Pマーク／ISO27001の取得**と**非破壊スキャン**を条件にすること。
クリアファイルに雑多に入ったままだと仕分け・ホチキス外しが前処理費として加算される。

- **社内共有化**: `run.sh` を `0.0.0.0` バインドに変更しlaunchd常時起動（`192.168.1.105:8528`）。配布は他アプリと同じ作法で **Dropbox共有フォルダ**（`…/（★必読★）新共有フォルダ/社内ツール/`）に `書類キャビネット.url`（URL=http://192.168.1.105:8528）＋`icons/書類キャビネット.ico`、**Mac用**に `Desktop/社内ツール/書類キャビネット.app`（launcherは`open http://localhost:8528`・`AppIcon.icns`）。アイコン生成元は `shorui-cabinet/icon-src/`（PILで白いキャビネット×インディゴ、`.ico`/`.icns`両方）。
- **⚠️ launchd常時起動だとDropbox取込フォルダ（`~/Library/CloudStorage/…/書類取込`）を読めない**（macOS TCC。CloudStorageは保護領域）。**Python本体にフルディスクアクセスを付与しても効かない**（TCCの“責任プロセス”がlaunchdの`ProgramArguments[0]`=`/bin/bash`側のため）。→ **`/bin/bash` にフルディスクアクセスを付与**すれば常時起動でも取込を読める（要手動GUI・1回）。未付与でも他機能（検索・手入力登録・保管場所）は動く。取込セクションはOSErrorをcatchして案内表示。ターミナル由来で起動した場合はTerminalがFDAを持つため読める（＝切り分けの目安）。
- 個人情報（物件名・所在）を含み個人Dropboxも読むため、社内WiFi内のみ・認証なし公開である点に留意。

#### 「📄 PDFを整理」タブ（旧 pdf-organizer を統合・2026-08-09）

**クリアフォルダ1冊をまとめてスキャンした1つのPDF**を、書類1件ずつに**分割＋分類＋リネーム**する。
実体は `pdf_split.py`＋`ai_reader.py`。**単体CLIの `pdf-organizer` は役目を終えたので使わない**
（このリポジトリにも実体は無い）。判定結果はそのまま**中身の目録**になり、分割PDFは
種類別フォルダ入りのZIPで取り出せる。

- **役割分担**: 紙の原本の所在は「棚1-14」粒度で管理（本体機能） / こちらは**PDF化したデータ**を
  書類1件単位で整理。紙をPDF化しても原本は捨てられないので両方要る
- **AIはローカルの `claude` CLI**（APIキー不要）。テキスト層あり→**sonnet**、
  スキャン画像→**opus**（`ai_reader.TEXT_MODEL` / `VISION_MODEL`）。
  画像経路でsonnetは固有名詞を推測で置き換える実測があるため、ここは落とさないこと
- **長いPDFはウィンドウ分割**して判定する（`TEXT_WINDOW=30` ページ／`VISION_WINDOW=8` ページ。
  画像は1ページが高コストなので細かく刻む）。書類がウィンドウを跨いだ場合は
  `continues_from_previous` で結合する
- **ページの取りこぼし防止**（`_fill_gaps`）: AIが範囲を飛ばす／重複させても、
  1〜N全ページが必ずどれか1件に1回だけ入るよう後処理で補正。**出力からページが消えることはない**
- 和暦→西暦はプロンプトで指示（令和/平成/昭和 → `YYYY-MM-DD`）
