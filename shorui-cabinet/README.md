# 書類キャビネット (shorui-cabinet)

**紙の書類が物理的にどこにあるか**を記録・検索するアプリ。「あの物件の契約書どこ？」を解決する。

写真やPDFを放り込むと `claude` CLI が中身を読んで **種別・物件名・日付・相手先を自動で埋める**ので、
人がやるのは「保管場所を選ぶだけ」。台帳づくりが続かない最大の原因＝入力の手間を潰してある。

- 分類: 不動産 / port **8528** / **自分専用（localhostバインド・社内LAN共有なし）**
- AI: ローカルの `claude` CLI（**APIキー不要・Claude Codeのサブスク内で動く**）

## できること

1. **登録** — 写真・PDFを複数まとめて投入 → AIが1件ずつ判別 → 内容を確認して一括登録
   - **スキャン代行から返ってきたPDFをそのまま一括投入できる**
   - AIを使わず手入力で1件だけ登録も可能
2. **さがす** — キーワード（スペース区切りAND）／種別／物件／保管場所で絞り込み、**保管場所を大きく表示**。CSV書き出し可
3. **保管場所** — 「本社3F 書庫A / 棚2」の粒度で登録。場所ごとの在庫一覧が見られる
4. **設定** — 物件マスタ（Excel/CSVから一括取込）、全書類CSV／DBのバックアップ

## 起動

```bash
./run.sh    # 初回は venv 作成＋依存導入
```
→ http://localhost:8528

## AI読み取りの仕様

| 入力 | 経路 | モデル | 目安 |
|---|---|---|---|
| テキスト層のあるPDF | テキストを渡す | sonnet | 数秒〜十数秒 |
| スキャン画像PDF・写真 | 画像化→**向き自動補正**→ビジョン | **opus** | 40〜60秒 |

**画像経路に opus を使っているのは実測にもとづく判断。** sonnetだと固有名詞を推測で
置き換える誤り（「グランドメゾン天王寺」→「プラチナハイツ大手町」、「大京商事」→「大和商事」等）が
2回に1回程度発生した。opusでは3/3で正解。誤った所在を登録すると探せなくなるため、速度より正確さを優先している。

向き補正は共有モジュール `pdf_orient.py`（他アプリと同じもの）を使用。横向き・逆さのスキャンでも正立に直してから読ませる。

**`confidence` が medium / low の書類は登録前に必ず目視確認すること。** 画面の一覧で確度が表示される。

## データ

- `data/cabinet.db`（SQLite）… 書類・保管場所・物件マスタ
- `data/thumbs/`… 一覧表示用のサムネイル
- ⚠️ **物件名・取引先名・書類の所在を含むため `data/` は gitignore**。他PCではDBを手で持ち込む

## 他アプリとの役割分担

| | 対象 | 用途 |
|---|---|---|
| **書類キャビネット**（これ） | **紙の原本** | 物理的な置き場所を管理 |
| file-finder (8520) | 共有ドライブのファイル | メタデータ横断検索 |
| デジタル書斎 | OCR済みPDF | 中身の全文検索 |

PDF化しても権利証や実印を押した契約書原本は捨てられないため、紙の所在管理は残る。

## メモ: スキャン代行を使う場合

段ボールで送ってPDF化して返してもらうサービスがある（相場: A4白黒3〜4円/枚〜、カラー8〜10円/枚〜）。
ただし**最低料金5万円前後**の会社が多く、これは高性能スキャナ1台分とほぼ同じ。
数百枚程度なら自前スキャンのほうが安い。数千枚（段ボール単位）から代行が有利。

契約書は個人情報を含むため、**Pマーク／ISO27001の取得**と**非破壊スキャン**を条件にすること。
クリアファイルに雑多に入ったままだと仕分け・ホチキス外しが前処理費として加算される。
