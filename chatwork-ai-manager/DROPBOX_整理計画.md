## 1. 測って分かったこと（すべて実測値）

対象は索引済みの **11,604文書**（会社Dropbox `（★必読★）新共有フォルダ/` 配下）。

## 2. 計画 ── B（見え方）を先に、A（生成フォルダ）は後

`TODO.md` の結論（Bが先、効かなければA）は**測ったあとも変わらない**。
ただし **Bの前に Phase 0 が要る**ことが分かった。台帳が穴だらけのままでは
物件別の見え方が作れない。

### Phase 0 ── 台帳の穴を埋める（何も動かさない）

| # | やること | 完了条件 |
|---|---|---|
| 0-1 | `properties` に `aliases` 列を追加（`shinsei_properties` と同じ作り） | 列がある |
| 0-2 | 表記ゆれ13件を別名として登録 | 上の表13行が入っている |
| 0-3 | マスタ未登録23件を「物件として追加」か「物件ではない」か仕分け | 23件すべてに判断がついている |
| 0-4 | 名寄せを測り直す | **95%以上**（いま63.7%） |

- **Dropboxのファイルには一切触らない。DBに列と行を足すだけ。**
- 0-3 は**人の判断が要る**（`konami` 320件・`角屋産業` 156件が何なのか、
  管理物件なのか終了案件なのかは中の書類だけでは決めきれない）
- 見込み工数: 0-1〜0-2 は自動で可。0-3 が確認待ちになる

### Phase 1 ── 見え方だけ作る（B案・フォルダは1つも動かさない）

**`全ファイル一覧.xlsx` を厚くする。** 週次で作り直している既存の仕組みに列を足すだけ
（`chatwork-ai-manager` の `build_inventory.py`・日曜5:00）。

足す列:

| 列 | 中身 | 出どころ |
|---|---|---|
| 物件 | 正規化した物件名 | Phase 0 の別名表 |
| 棚 | 01_契約〜09_賃借人資料 | 1-4 の判定（97%） |
| 種別 | 賃貸借契約書・請求書… | 1-5 の判定（75%） |
| 年 | 更新年 | `source_mtime` |
| 重複 | 同一内容が他にもあるか | `content_hash` |
| 古さ | 1年以内／3年／5年／10年超 | `source_mtime` |

シートを分ける: **物件別 / 棚別 / 年別**。

- **複製ゼロ・社員の覚え直しゼロ・1ファイルの中が変わるだけ**
- 完了条件: 「〇〇ビルの解約精算書」を**1画面で引ける**こと（実際に引いて確かめる）
- リスクが低い。**ここまでは Dropbox の実物を1バイトも触らない**

### Phase 2 ── 掃除（一覧を出すところまで自動、消す・動かすのは人）

| # | やること | 対象 | 誰が |
|---|---|---|---|
| 2-1 | 重複の余分346件を一覧化（どれを残すか候補つき） | 312組 | 一覧は自動／削除は人 |
| 2-2 | 10年超3,086件の「アーカイブ行き候補」一覧 | 26.6% | 一覧は自動／移動は人 |
| 2-3 | `社内書式` と `自社書類` が同じものか判定 | 3か所重複 | 判定は自動／統合は人 |

- **移動・削除は自動でやらない**（全社員が毎日開く実物。リンクも記憶も切れる）
- 2-2 は既存の `_アーカイブ（2027年7月削除予定）` に足す形なので、**やり方は前例どおり**

### Phase 3 ── A案（読み取り専用の生成フォルダ）※ Bで足りなければ

- 対象は**契約・書類＋経理・請求のPDFだけ（5,566件）**に絞る
- **Dropboxはシンボリックリンクを実体としてコピーする**ので、全部やると +12GB
- 正本は今のまま＝二重管理にはならないが、**毎晩作り直す仕組みの維持費がかかる**
- **Bを3か月使って「まだ探せない」と言われたときだけ着手する**

## 3. やらないと決めたこと

- **Dropboxのフォルダを自動で並べ替えない。** 全社員が毎日開く実物
- **`全ファイル一覧.xlsx` を止めない**（週次・日曜5:00。社員が直接開く実物でもある）
- **3代目の共有フォルダを作らない。** 旧を凍結して移行済み（2代目）。
  崩れているのはトップの分類ではなく中の深さなので、引っ越しても直らない
- **電帳法は全部やらない。** 義務は電子取引データ（メール添付の請求書・領収書）で、
  原本はすでにメールアーカイバ（8535 / 社内8538）に入っている。紙のスキャンは任意

## B. 5階層に寄せると、どれだけ動くか

## C. ★ただし「一律5階層」はできない ── 34.8%は6階層が正しい

机上で寄せたら **352件が同じ名前で降ってきて上書き事故になる**ことが分かった。
中身を見ると、これは事故ではなく**設計上の意味があった**。

```
A-3476 鴫野東2丁目第2駐車場/04番_竹内深悟（2026.4.11～）/1.駐車場申込書.pdf
A-3476 鴫野東2丁目第2駐車場/08番_増田吉男（2026.4.25～）/1.駐車場申込書.pdf
A-3476 鴫野東2丁目第2駐車場/26番_大黒進次（2026.7.1～）/1.駐車場申込書.pdf
```

**中間フォルダが「分類」ではなく「実体」**（区画番号・部屋番号・契約者・サブ物件）。
潰すと **どの区画の・誰の申込書なのかが消える。**

そこで**「兄弟フォルダが同じファイル名を持つなら実体」**という判定を入れ、
実体は深さを問わず**1階層だけ残す**ルールにした。結果:

| | 件数 | 割合 |
|---|---:|---:|
| 移動後 **5階層** | 4,555 | 65.2% |
| 移動後 **6階層**（実体フォルダを持つ物件） | 2,426 | 34.8% |
| **衝突** | **22件（11か所）** | 0.3% |
| └ 中身も同じ＝重複削除で自然に消える | 8件 | |
| └ **中身が違う＝個別対応が要る** | **14件** | |

**実体フォルダは 326個中136個**（41.8%）。31/65物件が持っている。
多いのは `A-3476 鴫野東2丁目第2駐車場`(26個) / `SATOビルⅡ`(9) / `大京モータープール(横堤P)`(9)。

**→ 目標は「5階層。ただし区画・部屋・入居者単位のものは6階層まで許す」が正しい。**
7階層以上（現在1,880件）は全部なくなる。

## E. ★順番は逆にした方がよい ── 重複削除 → 5階層

オーナー案は「5階層 → 重複削除」だが、**逆の方が安全で軽い**。

# ★★ 確定仕様（2026-09-05）── 大京本社ビルを見本に確立した法則

## AI業務マネージャーへの影響と対処（2026-09-05）

### ① 索引に実在しないパスが 508件 残った

`filepath` の一括置換だけでは足りなかった。**今日の整理でファイル自体も動かしている**ため
（仲介→物件へ346件、重複をアーカイブへ171件、本社の棚わけ68件）。

| 直し方 | 件数 |
|---|---:|
| 移動記録JSON（旧→新の対応表）で付け替え | 104 |

**→ 実在しないパスは0件になった。** 検索も `find_files` も新しいパスで通ることを実流しで確認。

**★教訓: ファイルを動かしたら、パスの置換だけでなく「移動記録との突き合わせ」が要る。**
`local/移動記録*.json` を残しておくと、こういうときに使える。

### ② worker は launchd 管理なので手で起動しない

`pkill` して `nohup python3 worker.py` で立て直そうとしたが、**launchd が自動で1本立て直していた**ため
多重起動になりかけた（多重起動防止で自ら終了したので実害なし）。
正しくは `launchctl kickstart -k gui/$(id -u)/com.shinsei.chatwork-ai-manager-worker`。
`launchctl list | grep chatwork` で管理下かどうかを先に見ること。

### ③ `.lnk`（Windowsのショートカット）7件は元から壊れていた

物件フォルダの奥に埋まっていた、**西村さんのWindowsで作られたショートカット**。

```
参照先: C:\Users\nishimura\…\共有フォルダ\（★必読★）新共有フォルダ\経理・請求書\管理物件請求書\…
                                                              ↑ 現在は「経理・請求」
```

**フォルダ名が変わった時点で既に切れていた**ので、今回の変更が原因ではない。
`.lnk` はバイナリでパス長がヘッダに埋まっているため、**Macからは安全に書き換えられない**。

**★この7件から分かったこと: 社員は「物件フォルダから経理の請求書へ飛びたい」と思っていた。**
`経理・請求` を触らない判断は変えないが、**この動線の需要はある**。いずれ考える必要がある。

### ④「契約」の棚は要らないかもしれない（2026-09-05）

大京本社ビルを仕上げたら、`契約/` に残ったのは**ひな形1件だけ**だった。
中身は空欄の賃貸借契約証書で**物件とは無関係**だったため、
既存の `契約・書類/書類雛形/賃貸借契約書/` へ移し（`賃貸借契約証書（雛型・大京本社ビル由来）.doc`）、
空になった `契約/` を片付けた。

**契約書の行き先は3つに分かれる:**

| 何の契約か | 置き場 |
|---|---|
| テナントとの契約 | `入居者/{区画_名前}/` か `解約済/{区画_名前}/` |
| ひな形・書式 | `契約・書類/書類雛形/`（既存。214件ある） |
| **建物全体の契約**（管理委託・保険など） | `契約/` ← **本社には1件も無かった** |

**→ 他の物件で「建物全体の契約」が実在するか確かめる。無ければ棚は5つになる。**
