### 発生したエラーと解決策

- **症状**: スクリプトがログ4行で止まり、終了コード1。何のメッセージも出ない
  → **原因**: launchd/Cロケールの bash は `"$MAX_DELETE）"` の全角括弧までを変数名として読む。
     `MAX_DELETE）: unbound variable` で `set -u` に落ちていた
  → **直し方**: 先頭で `LANG`/`LC_ALL`/`PATH` を明示し、変数を全部 `${VAR}` の波括弧表記にした

- **症状**: 初回ミラーが 19,050件目で `mkstempat: Illegal byte sequence` で異常終了
  → **原因**: openrsync が作る一時名 `.<元の名前>.XXXXXXXX` が 255 バイトを超え、
     **UTF-8 の途中で切られていた**。該当は最長299バイトの PDF など**2件だけ**
  → **直し方**: `--inplace`（一時ファイルを作らない）を付けた。2件とも通ることを実測

- **症状**: `--backup --backup-dir=` で削除ファイルを退避しようとしたが、削除が起きない
  → **原因**: macOS の `/usr/bin/rsync` は **openrsync** で、`--backup` を付けると
     `--delete` が効かなくなる（GNU rsync と挙動が違う）
  → **直し方**: 退避方式は諦め、素の `--delete` ＋ 空実行での事前チェックに変えた

- **症状**: ログの日本語ファイル名が `\#206\#205` のように読めない
  → **原因**: openrsync が非ASCIIバイトを8進エスケープして出力する
  → **直し方**: `decode_names()`（python3で `\#NNN` を戻す）を入れ、削除予定リストに適用。
     あわせてログに生バイトが混じるので `grep` を全部 `-a`（binary-safe）にした
