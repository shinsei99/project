プロンプト集は星の数ほどありますが、**実際に自分の業務で効いたかどうか**で
選別したものだけを書きます。効かなかった型も理由つきで残します。

## 効いた型

### 1. 症状・再現手順・確認方法の3点セット

```
症状: 決済後の画面が真っ白になる
再現: カートに1件入れて決済 → 完了画面
確認: npm test と、実際に手で1回通す
```

「直して」だけとの差は、**AIが自分で検証できるかどうか**です。
確認方法を渡すと、勝手にテストして自分で直すところまで行きます。

### 2. 触ってはいけない場所を先に言う

```
touch しないでほしいもの:
- data/ 配下（実データ）
- .env（キーが入っている）
```

**やることより、やってはいけないことのほうが伝わりにくい。** 先に言う。

### 3. 判断に迷ったら聞いてほしい、と明示する

「分からなければ勝手に決めずに聞いて」と入れるだけで、
的外れな実装が減ります。逆に入れないと、それらしい仮定で突き進みます。

## 効かなかった型

### ❌「あなたは超一流のエンジニアです」

役割を盛る書き出しは、**最近のモデルにはほぼ効きません。** 字数の無駄です。
それより「このプロジェクトはNext.jsで、テストはvitest」という事実を1行書くほうが効きます。

### ❌ 長い禁止事項リスト

10個も禁止を並べると、かえって当たり前のことまで確認を求めてきます。
**本当に守らせたい2〜3個に絞る。**

### ❌ 「完璧に」「絶対に」の強調

強調語を増やしても精度は上がりません。具体的な合格条件に書き換えるほうが効きます。

## 原則

結局のところ、**人間の同僚に頼むときの書き方がそのまま正解**です。
目的、制約、確認方法。これが揃っていれば通ります。
