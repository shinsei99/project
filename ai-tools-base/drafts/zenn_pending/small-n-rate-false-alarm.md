不動産の仕事で、時間貸ししている区画の予約実績を分析する道具を書きました。
「今年は実績が落ちた」ときに、**入口（見つけてもらえていない）の問題なのか、
来た問い合わせを取りこぼしているのか**を自動で切り分けて言い切る、という道具です。

出てきたレポートに、こういう行がありました。

```
- 申込 9件 → 2件（-78%） / 確定 9件 → 1件（-89%）
- 申込→確定の歩留まり 100% → 50% / 新規 9件 → 1件（-89%）
- 判定: 来た話を取りこぼしている。申込→確定の歩留まりが落ちた。
```

**取りこぼしていません。** 今年の申込は2件で、そのうち1件がまだ保留のままだっただけです。
1件が動けば100%に戻ります。

## 何をしていたか

判定の中身は素直な条件式でした。前年と今年の歩留まりを出して、10ポイント以上落ちたら
「取りこぼしている」と言う。

```python
rate_prev = prev["confirmed"] / prev["applied"] * 100 if prev["applied"] else 0
rate_now  = now["confirmed"]  / now["applied"]  * 100 if now["applied"]  else 0

drop_in   = prev["applied"] and (now["applied"] - prev["applied"]) / prev["applied"] <= -0.15
drop_rate = rate_prev - rate_now >= 10
```

`drop_rate` は 100 − 50 = 50 なので、余裕で成立します。条件式にバグはありません。
**割り算をした時点で、分母が9だったのか2だったのかの情報が消えている**、というだけです。

そして厄介なことに、母数が小さいほど**変化率は大きく出ます**。
2件のうち1件が動けば50ポイント。9件のうち1件なら11ポイント。
つまりこの手の判定は、**いちばん情報が少ない対象で、いちばん強く鳴ります**。

## 直し方：判定を出さない、という選択肢を持たせる

閾値を厳しくする方向では直りません。2件中1件は何ポイントに設定しても跳ねます。
**母数の下限を先に決めて、満たさなければ判定そのものを出さない**形にしました。

```python
# ★母数が小さい年で言い切らない。1件の保留で「歩留まりが50%に落ちた」と
#   出てしまい、実際に申込2件の区画で誤った判定が出た。
MIN_N = 10
if prev["applied"] < MIN_N or now["applied"] < MIN_N:
    msg.append(
        f"- 判定なし: 申込が{MIN_N}件未満の年があり、割合で語ると誤読する"
        "（この区画は件数そのものを見ること）"
    )
    return msg
```

ここで大事なのは、黙って判定を飛ばさないことです。
**「判定なし」という結論を、理由つきでレポートに印字する。**
何も書かないと、読む人は「異常なし」と読みます。それは別の嘘になります。

実際に、申込が 3件 → 3件 の区画でも同じ行が出ました。こちらも数字だけ見せて、
判定は人に返しています。

## もうひとつ：0 と 0 を比べて「維持」と言っていた

同じ性質の穴がもう1か所ありました。リピート客の判定です。

```python
- 申込→確定の歩留まり 100% → 50% / 新規 9件 → 1件（-89%） / リピート 0件 → 0件（—）
```

リピートが0件から0件。変化率で見れば「減っていない」ので、
条件式は素直に **「リピートは保たれている。満足度の問題ではない」** と言おうとします。

0人が0人のままなのは、維持ではありません。**まだ何も分かっていない**が正しい。

```python
drop_rep = prev["repeat"] >= 3 and (now["repeat"] - prev["repeat"]) / prev["repeat"] <= -0.15

if drop_new and not drop_rep and max(prev["repeat"], now["repeat"]) >= 3:
    msg.append("- 新規客だけが減り、リピートは保たれている。…")
```

「減った」と言うときの母数（`prev["repeat"] >= 3`）と、
「保たれている」と言うときの母数（`max(prev, now) >= 3`）は**別に要ります**。
前者は前年に3件以上あったこと、後者はどちらかの年に3件以上あったことが条件です。
片方だけ入れると、逆方向の誤読が残ります。

## 母数を通した結果、本題のほうは言い切れた

誤警報を潰したあと、実績の十分ある区画では判定がはっきり出ました。

```
- 申込 43件 → 20件（-53%） / 確定 32件 → 18件（-44%）
- 申込→確定の歩留まり 74% → 90% / 新規 25件 → 11件（-56%） / リピート 7件 → 7件（+0%）
- 判定: 入口（見つけてもらう回数）の問題。
```

- 申込は半分に減った
- **だが歩留まりは 74% → 90% と上がっている**（来た話は前よりちゃんと成約している）
- **リピートは 7件 → 7件で1件も減っていない**（既存客の満足度は落ちていない）
- 減ったのは新規だけ（25件 → 11件）

表示回数の統計は提供元から取れないので、露出そのものは直接測れません。
それでも、この分解だけで「接客でも価格でもなく入口」と消去法で言い切れました。
別の区画でも同じ形（申込 15件 → 11件、歩留まり 73% → 82%、新規 10件 → 9件）でした。

## 持ち帰ったこと

**割合は、母数を添えないと事実を伝えない指標です。**

- 率で異常を判定する仕組みには、**必ず母数の下限を書く**
- 下限を割ったら、黙って飛ばさず **「判定なし」と理由を出力する**
- **「変わっていない＝良好」と読む条件にも、別の下限が要る**
- 集計する期間は、比べる年どうしで先にそろえる（年の途中の今年と、去年の1年ぶんを
  比べない）

これは業務レポートに限りません。エラー率・成功率・コンバージョン率で
アラートを出す仕組みは、だいたい同じ穴を持っています。
**アクセスの少ない画面ほど派手に鳴り、鳴っても何もできない。**
閾値をいじる前に、まず分母を条件に入れるほうが早く直ります。
