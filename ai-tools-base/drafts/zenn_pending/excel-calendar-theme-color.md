社内のチャットに常駐しているAIが、日報を作ったり、未完了の仕事を催促したりします。
これには「**会社の休業日には動かない**」という条件が付いています。

その休業日は、年間の休暇スケジュールという Excel にあります。
**1シート＝1か月のカレンダー**で、休みの日のマスが**オレンジに塗ってあるだけ**。
「休み」という文字はどこにも入っていません。人が見るために作られた表です。

これを機械に読ませて、3か所で詰まりました。どれも「エラーは出ないが0件」という形で出ます。

## ① 塗りつぶしの色が、空で返ってくる

最初はこう書きました。

```python
ORANGE_RGBS = {"FFED7D31", "FFFFC000", "FFF79646"}

def _is_orange(cell) -> bool:
    f = cell.fill
    if not f or f.fill_type != "solid":
        return False
    return str(getattr(f.start_color, "rgb", "")).upper() in ORANGE_RGBS
```

**1件も取れません。** 例外は出ません。全部 `False` になるだけです。

原因は、そのオレンジが**テーマ色**（アクセント2）で塗られていたことでした。
色見本の上段から選ぶと、ファイルに入るのは色の値ではなく**テーマの番号**です。

```python
c = ws["H6"].fill.start_color
c.rgb     # → 空
c.theme   # → 5
```

色そのものがファイルに入っていない、というのがポイントです。
ブックのテーマを差し替えれば、同じ `theme=5` のまま見た目の色だけが変わります。
**「見えている色」と「保存されている値」は別物**でした。

直したのがこれです。テーマ番号を先に見て、色の値はその次に見ます。

```python
ORANGE_THEMES = {5}          # テーマ5＝アクセント2（Office既定でオレンジ）
ORANGE_RGBS = {"FFED7D31", "FFFFC000", "FFF79646", "FFFFA500", "FFFF9900", "FFE36C0A"}

def _is_orange(cell) -> bool:
    f = cell.fill
    if not f or f.fill_type != "solid":
        return False
    c = f.start_color
    theme = getattr(c, "theme", None)
    if isinstance(theme, int) and theme in ORANGE_THEMES:
        return True
    rgb = getattr(c, "rgb", None)
    return isinstance(rgb, str) and rgb.upper() in ORANGE_RGBS
```

両方を残しているのは、あとから手で塗り直されたマスは色の値で入るためです。
どちらか一方だけでは足りません。

## ② 塗られているのは、日付のマスではなかった

日付の数字は取れているのに、色の判定が合わない。セルを1つずつ見て分かりました。

**1日ぶんのマスが2行1組**でできていて、**日付の数字は上の行、色は下の行**に付いていました。
画面上は罫線で1つの枠に見えます。人の目には1マス、機械には2セルです。

```python
# 色は「日付の1つ下の行」に付く。念のため日付セル自身も見る
if _is_orange(ws[f"{col}{r + 1}"]) or _is_orange(ws[f"{col}{r}"]):
    found[datetime.date(year, month, day).isoformat()] = "休み"
```

日付が入る列は日曜から土曜で `B/D/F/H/J/L/N`、行は1行おきです。
**結合されていない「見かけ上のマス」**は、人向けの帳票によく出てきます。

## ③ 本題：1月だけ0件になる

カレンダーには**前月末と翌月頭の日**も並びます。
そこで「1から始まる連番」だけをその月とみなしていました。

```python
out, started, prev = [], False, None
for v, col, r in seq:
    if not started:
        if v != 1:
            continue          # 前月の日は読み飛ばす
        started, prev = True, 0
    if v != prev + 1:
        break                 # 翌月の1に戻った＝ここで終わり
    out.append((v, col, r))
    prev = v
```

12か月のうち、**1月だけが0件**でした。他の11か月は正しく取れています。

原因は、カレンダーの外にありました。
見出しの上に「何月か」を示す数字が置かれていて、**1月のシートではその値が `1`** だったのです。

```
H2 = 1        ← 「1月」の月番号。これを「1日」と読んでいた
...
日 月 火 水 木 金 土      ← 曜日の見出し
28 29 30 31  1  2  3      ← 次に現れる数字は前月末の 28
```

`1` を1日と判断して読み始め、次の数字が `28` なので `v != prev + 1` に当たり、
**その場で打ち切っていました**。だから0件です。

たちが悪いのは、**8月のシートでは `H2 = 8` なので素通りする**ことでした。
`v != 1` で読み飛ばされるので、他の月では何も起きません。
**1月でしか再現しない不具合**で、しかも例外は出ません。

直し方は、座標の決め打ちをやめて**見出しを探す**ことでした。

```python
# 曜日の見出し行（日 月 火 …）より上は見ない
head = 0
for r in range(1, ws.max_row + 1):
    if str(ws[f"{DAY_COLS[0]}{r}"].value or "").strip() in ("日", "Sun", "SUN"):
        head = r
        break

seq = []
for r in range(head + 1, ws.max_row + 1):
    for col in DAY_COLS:
        v = ws[f"{col}{r}"].value
        if isinstance(v, int) and 1 <= v <= 31:
            seq.append((v, col, r))
```

「表の中身は、**見出しを見つけてから相対で読む**」。これに変えてから月ごとの取りこぼしは消えました。

## 気づけた理由は、月別に数えたから

全体では**2026年ぶんで106日**が取れていました。
それだけ見れば「取り込めている」で終わります。
気づけたのは、月ごとの件数を並べて、**1月が0件**だったからでした。

**合計は成功しているように見える**、というのがこの手の不具合の共通点だと思います。
0件になりうる単位（月・シート・分類）で数えて並べるのが、いちばん安いテストでした。

## おまけ：元ファイルが読めない日がある

元のExcelはクラウドの同期フォルダにあり、**常時起動しているプロセスからは読めないことがあります**。
そこで、一度読めたらデータベースへ写し、以後は写しで判定する形にしました。

```python
def is_holiday(date_str: str) -> bool:
    """休業日か。DB の写しを見る（その年が未取り込みなら一度だけ読みに行く）"""
```

1年ぶんは一度読めれば以後ずっと効きます。読み直しは画面からも叩けます。

## まとめ

- テーマ色で塗られたセルは、**色の値が空**で**テーマ番号だけ**が入る。両方を見る
- 人向けの帳票は、**見かけ上の1マスが複数セル**であることがある
- **座標の決め打ちをやめて、見出しを探してから相対で読む**
- 表の外に置かれた数字（月番号・年・通し番号）が、**中身のふりをして混ざってくる**
- 合計ではなく、**0件になりうる単位で数えて並べる**

人が見るために作られた表は、**線と色と位置に意味が載っています**。
その意味はファイルの中には書かれていないので、こちらで作り直すしかありませんでした。
