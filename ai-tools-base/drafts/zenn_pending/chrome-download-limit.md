調査に必要な公式書式を、画面からまとめてダウンロードできるようにしています。

「重要事項説明書」「告知書」「媒介契約書」など、5本チェックして押すと、
**1本しか保存されませんでした**。

エラーは出ません。残りの4本は、何も起きないだけです。

## 犯人はブラウザの既定設定

Chrome は、**同じサイトから複数のファイルが連続でダウンロードされるのを既定で止めます**。

「このサイトが複数のファイルを自動的にダウンロードしようとしています」という制限です。
アドレスバーの右端に小さいアイコンが出るだけで、**ページ側には何も表示されません**。

利用者から見ると「押したのに、1本しか出てこない」だけです。
こちらのバグに見えます。実際、最初はそう思って調べました。

## 回避する方法はある

やろうと思えば、回避できます。

- **時間をずらして1本ずつ落とす**（数百ミリ秒の間隔を空ける）
- **iframe を並べて別々に発火させる**
- **File System Access API を使う**（対応ブラウザなら）

このうち1つめは、実際によく使われています。ただ、これは
**「ブラウザが止めようとしている挙動を、時間差で通す」**ということです。

その制限は、悪意のあるサイトが大量のファイルを落とすのを防ぐためにあります。
うちの用途は正当ですが、**正当だからといって回避してよいことにはならない**。

社内ツールなので、誰も文句は言いません。それでも、
**制限を回避する実装を1つ入れると、次からも同じ発想で回避する**ようになります。
そこを線引きしました。

## 選んだ方法：まとめて渡す＋人が1回許可する

**2本以上のときは、ひとつの圧縮ファイルにまとめて渡す**ことにしました。
これが本筋です。ダウンロードは1回で済むので、制限にも当たりません。

```python
if len(selected) >= 2:
    buf = io.BytesIO()
    with zipfile.ZipFile(buf, "w") as z:
        for path in selected:
            z.write(path, arcname=path.name)
    st.download_button("選んだ書式をまとめて取得", buf.getvalue(), "書式一式.zip")
else:
    st.download_button(...)      # 1本ならそのまま
```

そのうえで、環境によって制限に当たる場合の**手順を画面に案内**しています。

> 複数のファイルが保存されない場合は、アドレスバー右端のアイコンから
> 「このサイトでは常に許可する」を選んでください（1回だけの操作です）。

**人が1回許可すればいい**ことを、こちらが自動で回避しにいかない。
この判断は、他の場面にも当てはめています。

## 「自動でできること」と「自動でやること」は別

自動化のツールを作っていると、**止まっているものを通したくなります**。

- ブラウザの確認ダイアログ
- 「本当に削除しますか」の確認
- レート制限
- ダウンロードの制限

技術的には、たいてい回避できます。それでも、こう考えるようにしました。

**その制限は、誰を守るために付いているのか。**

ダウンロードの制限は、利用者を守るためのものです。うちの利用者は社員です。
社員を守る仕組みを、社内ツールが勝手に外すのは筋が通りません。

代わりに、**制限に当たらない設計にする**（＝まとめて1ファイルで渡す）。
それでも当たる場合は、**人に判断してもらう**。

自動化の範囲を決めるというのは、こういう線を1本ずつ引いていくことなのだと思います。

## おまけ：気づけるようにする

もう1つ入れたのは、**何本渡そうとしたかを画面に出す**ことです。

> 5本の書式を1つにまとめました（書式一式.zip）

保存されたファイルを開いて5本入っていれば、それで確認できます。
「押したのに出てこない」を、利用者の側で判断できる状態にしておく。

エラーが出ない不具合は、**数を見せるのがいちばん早い**というのは、他の場面でも同じでした。
