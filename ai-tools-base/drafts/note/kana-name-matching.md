# 入金の照合が、静かに当たらなくなっていた

賃貸の管理会社は、毎月同じことをします。**家賃が入ったかどうかを、一件ずつ確認する**という仕事です。

銀行からその月の入金データを落として、こちらの入金一覧と突き合わせる。
入っていれば消し込み、入っていなければ督促の対象にする。部屋数が増えると、これが半日仕事になります。

この照合を自動でやる道具を作りました。作ったあと、別のパソコンで動かしたときの話です。

## エラーは出ていない。ただ、当たらない

処理は普通に終わりました。画面も普通です。赤い文字も、警告も出ません。

ただ、**「未入金」に並ぶ件数が、いつもより多い**。

督促のリストを見て、違和感がありました。ここに並ぶはずのない人がいる。
通帳を見ると、その人の入金はちゃんと入っています。入っているのに、機械は見つけられていない。

## 銀行はカナ、こちらは漢字

理由は、名前の書かれ方にあります。

銀行の入金データに載っている名義は、**カタカナ**です。

```
2026/08/05  振込  ﾀﾞｲｷﾖｳ ﾀﾛｳ  82,000
```

一方、こちらの台帳に入っている契約者名は、**漢字**です。

```
101号室  大京 太郎  82,000
```

同じ人ですが、文字が違います。そのままでは一文字も一致しません。
だからこの道具は、契約者名から「カタカナの候補」を先に作って、それと突き合わせています。

候補は3つの道から作っていました。

1. **人が作った対応表** … 旧姓、法人格の有無（「株式会社」を付ける／付けない）、
   奥さんの名義で振り込まれるケース。こういうものは人が登録します
2. **漢字を自動でカタカナに直したもの** … 「大京 太郎」→「ダイキョウタロウ」
3. **契約者名そのものを整えたもの** … 最初からカタカナで登録されている法人や、外国人の入居者向け

## 一本だけ、消えていた

未突合が増えた原因は、**2番目の道が丸ごと消えていた**ことでした。

漢字をカタカナに変換するのは、外部の部品（ライブラリ）に任せています。
その部品が、そのパソコンには入っていなかった。

普通なら、部品が無ければプログラムは動きません。エラーで止まります。
ところがこの道具は、**「無ければ、その道は使わない」**という作りにしてありました。
止まらずに、候補が2つに減ったまま動き続けます。

その結果、どうなるか。

- カタカナで登録されている契約者 → **当たる**（3番目が効く）
- 対応表に登録済みの契約者 → **当たる**（1番目が効く）
- **漢字で登録されていて、対応表にまだ載っていない契約者** → **当たらない**

つまり、**新しく入居した人から順に、照合できなくなる**。
古い入居者は対応表に載っているので当たります。だから「前は動いていたのに」という壊れ方にならない。
これが、気づくのを遅らせました。

## 止めるか、言うか

こういうとき、選べる道は3つです。

1. **止める** … 部品が無ければ起動させない
2. **言う** … 動かすけれど、「いま性能が落ちています」と画面に出す
3. **隠す** … その機能を使う画面ごと出さない

この道具では、**2番**にしました。

消込は、最悪、対応表と手作業でも回ります。月末の締めの日に道具が起動しないほうが、よほど困る。
ただし、**黙って劣化させることだけはしない**と決めました。

いまは、起動したときに画面の上へこう出ます。

> **pykakasi が入っていないため、漢字の契約者名をカナに変換できません。**
> 動作はしますが、突合の候補が減るぶん**一致率が下がります**（エラーにはなりません）。

「動きます」ではなく、「動きますが、落ちています」と書いてあることが大事です。

## 空欄の理由を、残す

もうひとつ直したことがあります。

この道具は、新しい契約者を見つけると、対応表に自動で行を足します。
そのとき、カタカナを自動で入れられたのか、人が埋めなければいけないのかを、**行ごとに書き残す**ようにしました。

`auto`（自動で入った）と `manual required`（人が埋める必要がある）の二つです。

空欄が並んでいるとき、それが「まだ手を付けていない」のか「そのとき変換が使えなかった」のかは、
見た目では区別がつきません。理由が残っていれば、あとから拾えます。

## 落ちるバグより、落ちないバグ

この件でいちばん怖かったのは、**誰も困っていなかった**ことです。

処理は終わる。画面は出る。督促のリストも出る。
ただ、その中に、払っている人が混ざっている。

もしあのまま督促を出していたら、こちらの手違いで、お客さんに催促の連絡をしていました。
機械は何も間違えていません。人が部品を入れ忘れただけです。
でも、その入れ忘れを**誰にも言わない**ように作ったのは、こちらです。

落ちるバグは、遅くとも次に動かしたときに分かります。
**性能が落ちるだけのバグは、誰かが数えるまで分かりません。**

だから、いまは基準を決めています。

- **結果の正しさに関わる部品** … 無いなら、画面に出す
- **速さにしか関わらない部品** … 記録に一行だけ残す

一致率は、正しさの側です。だから画面に出しました。
