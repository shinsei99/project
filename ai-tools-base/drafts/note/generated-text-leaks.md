# AIが書いたものに、指示のタグが残っていた

AIに、道具一式を書かせました。設定ファイル、処理のコード、説明書。全部で31ファイル。

動かそうとしたら、いちばん最初の準備の段階で止まりました。
エラーの内容は「この行は解釈できません」。

ファイルを開いてみると、**末尾に見慣れない一行**が入っていました。

```
</content>
```

AIに指示を出すとき、「ここからここまでがファイルの中身」と示すために使っていた記号です。
それが、**中身の一部として書き出されていました**。

調べたら、**31ファイル全部**に付いていました。

## 目で見ても、気づけない

厄介なのは、**中身そのものは正しい**ことです。

```
streamlit
openpyxl
pillow
</content>      ← これだけが余計
```

上の3行は正しい。最後の1行だけが余計です。

ファイルを開いて眺めているぶんには、まず気づきません。
見つかったのは、**実際に使おうとしてエラーが出たから**でした。

もし、これが説明書のファイルだったら、そのまま気づかずに配っていたはずです。

いまは、AIに書かせたファイルは**そのまま使わず、機械的に検査してから**使うようにしました。
「末尾に余計な記号が付いていないか」を調べるだけの、単純な検査です。

そして、**実際に使う手順まで通して確かめる**。開いて見るだけでは足りませんでした。

## 日報に、社内用の印が出た

似たことが、別の場所でも起きました。

チャットの記録から日報を作らせています。
社内には、発言の頭に「★」を付けて、本人の発言であることを示す習慣があります。

その意味を、AIへの指示に書いていました。

> ★ が付いた発言は、その担当者本人の発言です。

出てきた日報には、こう書かれていました。

> 山田：進捗の報告なし（★発言0件）

「★」の**意味は伝えました**。でも、「**それを本文に書くな**」とは書いていませんでした。

読ませるために渡した情報は、**書いてよい情報として扱われます**。
言われてみれば当たり前ですが、渡すときには思いつきませんでした。

いまは、指示にこう書いています。

> ★ は社内の内部記号なので、出力には一切含めないでください。

## 設定ファイルに説明を書いたら、壊れた

もう一つ。

外部と連携するための設定ファイルに、**後から読む人向けの説明**を足しました。

「このサーバーは社内の書類検索に使う。止まっているときは…」という、ただのメモです。

その途端、**設定として読み込まれなくなりました**。
その形式は、決められた項目以外を受け付けないものだったのです。

説明は、別のファイルに書くことにしました。
親切のつもりの一行が、機械にとっては異物だった、という話です。

## 人間向けのものを、機械の中に混ぜない

三つとも、同じ形でした。**人間向けの記号を、機械が読む場所に混ぜた。**

- 指示のための記号 → 生成されたファイルに残った
- 社内の内部記号 → 日報の本文に出た
- 人間向けの説明 → 設定として無効になった

AIを使うと、出てくるものは「**だいたい正しい**」ものになります。

そして、だいたい正しいものは、**目で見て正しさを判断できません**。
全部読めば分かりますが、31ファイルを毎回読むわけにはいきません。

だから、間に**検査する仕組み**を挟むことにしました。
AIに任せる量が増えるほど、この検査の重みが増していくのだと思います。
