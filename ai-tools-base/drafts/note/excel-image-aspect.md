# 印刷したら、建物が太って見えた

不動産の物件資料のことを、業界では「マイソク」と呼びます。
間取りと写真と条件が1枚に入った、あの紙です。

他社が作ったマイソクに、うちの帯（社名・連絡先・免許番号）を付けて刷り直す道具を使っています。
お客さんに渡すときに、どこの会社に問い合わせればいいかが分かるようにするためです。

その道具で作った資料を印刷して、違和感がありました。

**建物が、横に太って見える。**

## 画面では気づきにくい

測ってみると、写真が**横に1.2倍**伸びていました。

画面で見ているぶんには、そういうものかと思ってしまう程度の差です。
印刷して、元の資料と並べて、はじめて分かりました。

## 表計算ソフトの「幅」は、長さではなかった

原因の一つめは、単位の話でした。

表計算ソフトの列の幅は、センチでもミリでもありません。
**「標準の文字が何個入るか」**という単位です。

こちらは、それを長さに直すときに「1文字はだいたいこれくらい」という
**よく紹介されている目安の数字**を使っていました。

実際に測ってみたら、その数字は**うちの環境では合っていませんでした**。
2割ほど狭く計算していて、そのぶん写真が横に伸びていた。

「一般的にはこう」という数字を持ってくるより、**測るほうが早い**という話でした。

## 貼り方が「引き伸ばす」ものだった

原因の二つめは、もっと効いていました。

画像の貼り方には、いくつか種類があります。

- **この範囲に収まるように貼る**（左上のマスから右下のマスまでを指定する）
- **この位置に、この大きさで貼る**（左上のマスと、実際の寸法を指定する）

こちらは前者で貼っていました。

前者は、**指定した範囲に合わせて画像を伸び縮みさせます**。
つまり、こちらの計算が少しでもずれれば、そのぶん写真が伸びる。縦横の比率も守られません。

後者に変えました。「ここに、この大きさで」と実寸で指定する形です。
こうすると、マスの都合に振り回されなくなります。

直したあとに測った結果です。

- 帯の幅：1150.00
- 写真の幅：1149.75（縦横の比率も維持）

## 「効いていない」と思われていたスライダー

同じ道具で、切り取る位置を微調整するつまみがあります。

刻みを細かくしたところ、**画面に出る数字が、選んだ値と合わなくなりました**。
0.005ずつ動かしているのに、表示は0.01ずつしか変わらない。

原因は、表示の桁数の設定でした。中の値は正しく動いていて、**見えている数字だけが丸められていた**。

ただ、使う側から見れば、これは「**動かないつまみ**」です。
実際、しばらくのあいだ、そう思われていました。

数字が合っていないだけ、と軽く見ないほうがよかった。
使う人は、中でどうなっているかを見ることができません。**見えているものが全部**です。

## 直せるのに、直していないもの

最後に、直していない不具合の話も書いておきます。

帯に入れている免許番号が、**用紙が横向きのときだけ、隣の欄にはみ出します**。
縦向きのときは、文字を枠に合わせて縮める処理が働くので、収まっています。

直し方は分かっています。それでも、直していません。

理由は、**これまで配ってきた資料の見た目が変わるから**です。

この道具で作った資料は、すでに何十件も外に出ています。
同じ物件の資料を刷り直したときに、前と字の大きさが違うと、受け取った側には「別物」に見えます。

直すなら、時期を決めて、全部刷り直す前提でやる。それまでは、分かったうえで置いておく。

不具合には、**すぐ直すもの**と、**直し方が分かったうえで置いておくもの**があります。
後者は、放置とほとんど同じに見えます。だから、**理由を書いて残す**ことにしました。

書いていなければ、ただの忘れ物です。書いてあれば、判断になります。
