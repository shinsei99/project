# AIが作った書類の文字が切れていた。原因は「たぶんこれくらい」だった

AIエージェントに、毎日夕方に**業務日報**を作らせています。
その日のやりとりを読んで、担当者ごとに「完了したこと」「進行中」をまとめ、
Excelの表にして決まった場所へ保管する。人は目を通して直すだけ、という形です。

中身は問題なく作れるようになりました。ところが、**見た目**が言うことを聞きません。

## 文字が切れている。隣は余白が空きすぎている

出来上がった日報を開くと、ある欄では**文章の下半分が切れて読めない**。
その2つ下の欄では、逆に**下の余白がぽっかり空いて**間延びしている。

書類として人に配るものなので、これは直さないといけません。
中身が正しくても、切れて読めなければ「使えない書類」です。

## 「たぶん、これくらい」で書いていた

原因を追うと、**行の高さを計算している部分**に行き当たりました。

やっていたのは、こういう計算です。

- 文章の文字数を、欄の幅で割って「何行になるか」を出す
- 1行につき「たぶん、これくらい」の高さを掛ける

この「たぶん、これくらい」に**根拠がありませんでした。**
画面を見ながら、それらしく見える数字を入れていただけです。

しかもこの計算には、もうひとつ穴がありました。
**日本語の文字と、英数字の文字を、同じ幅として数えていた**のです。

日本語の「あ」と、英字の「a」では、見た目の幅が倍ちがいます。
それを同じ1文字として数えていたので、

- 日本語だけの文章 … 高さが足りず、**文字が切れる**
- 英数字が混じった文章 … 行数を多く数えすぎて、**余白が空く**

という、**正反対の壊れ方**が同時に起きていました。
片方を直すと、もう片方がひどくなる。ずっと直らなかったのはこのためです。

## 推測をやめて、Excelに測らせた

ここで、直し方の方針を変えました。

**こちらが「たぶんこれくらい」と決めるのをやめて、Excel本人に正解を出してもらう。**

Excelには「文字の量に合わせて高さを自動で整える」機能があります。
そこで、作った日報を実際にExcelで開き、その自動調整をかけたうえで、
**調整後の高さがいくつになったかを読み出しました。**

出てきた数字は、はっきりしていました。

- 文章が1行で収まる欄 … **18**
- 2行に折り返す欄 … **36**

きれいに倍です。つまり**1行ぶんの高さは18**。
自分が使っていた「たぶん」の数字は、1行につき4ずつ足りていませんでした。
2行を超えると必ず切れていた計算になります。

あとは、この実測値に合うように計算をやり直すだけでした。
文字の幅も、日本語は2・英数字は1として数え直しました。

**実際の日報9か所で答え合わせをして、8か所が実測とぴたり一致。**
残る1か所は、こちらが1行ぶん多く見積もる側にずれました。これは直していません。
**ずれるなら、余白が空く側に倒す。**余白は目障りなだけですが、
切れると読めないからです。

## 「たぶん」は、あとで必ず跳ね返ってくる

この件でいちばん時間を食ったのは、直す作業ではありません。
**「たぶんこれくらい」で書いた数字が原因だと気づくまで**の時間でした。

原因の見当がついてから直すまでは、実質10分ほどです。
その前に、見た目の数字をあちこち触っては直らない、という往復をしていました。

AIに任せる仕事が増えるほど、**中身は正しいのに見た目で使えない**という
つまずき方が増えます。そして見た目の問題は、
「なんとなくこれくらい」で埋めたくなる誘惑が強い。

測れるものは測る。測る手段は、たいてい手元にあります。
今回なら、Excel自身がその手段でした。
