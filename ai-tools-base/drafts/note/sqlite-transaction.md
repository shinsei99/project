# 同じ時刻に2件入ると、どちらが先か分からない

管理している建物の鍵を、誰がいつ持ち出したか。
これを記録する台帳を作りました。鍵に付けたタグにスマホをかざすだけで、貸出と返却が残ります。

紙の貸出簿だと、書き忘れが必ず出ます。悪気があるわけではなく、急いでいるからです。
かざすだけなら、忘れようがない。

その台帳で、おかしなことが起きました。

## 一覧の並びが、見るたびに変わる

貸出の履歴を新しい順に並べて表示しています。

同じデータを見ているのに、**表示するたびに、2件の前後が入れ替わる**ことがありました。

調べると、その2件は**まったく同じ秒**に登録されていました。
2人が続けてタグをかざせば、同じ秒に入ります。珍しいことではありません。

機械は、**同じ値のものをどう並べるか、決めていません**でした。
どちらを先に出しても「新しい順」の条件は満たしている。だから、そのときどきで変わる。

## もっと細かく記録すればいい、ではなかった

最初に考えたのは、「秒ではなく、もっと細かい単位で記録すればいい」でした。

これは解決になりませんでした。

細かくしても、**同じ瞬間に2件入る可能性は残ります**。
確率が下がるだけで、無くなりません。しかも、確率が低い不具合ほど、起きたときに原因が分かりません。

必要だったのは、**同じ時刻だったときに、何で決めるか**を決めることでした。

いまは「時刻が同じなら、**後から登録されたほうを後**にする」という規則を足しています。
これで、並びは常に同じになりました。

## 台帳は、順番が保証されてはじめて台帳

この件で考えたのは、**台帳の値打ちは、順番にある**ということでした。

「誰が持ち出したか」が分かるだけなら、名前の一覧で足ります。
**「いま誰が持っているか」を知るには、貸出と返却の順番が要ります。**

見るたびに順番が変わる台帳は、**記録が無いのと近い**。
そのときは表示が入れ替わるだけの小さな不具合に見えましたが、根の部分の話でした。

## 更新が途中で止まって、戻せなくなった

もう一つ、同じ台帳で踏んだものがあります。

台帳の構造を変えるとき、いくつかの変更をまとめて実行します。
このとき、「途中で失敗したら、全部無かったことにする」という囲いをしていました。

ところが、使っていた実行の方法が、**囲いを外してから実行する**仕組みでした。
囲ったつもりが、囲えていなかった。

結果、途中で失敗したときに、**そこまでの変更が残ったまま**になりました。戻せません。

いまは、囲いの指示そのものを、実行する内容の中に書き込んでいます。
あわせて、「この更新を適用した」という記録も、同じまとまりの中で残すようにしました。

**変更と、変更した記録が、別々に残ると食い違う。**
これは、業務の帳簿でもまったく同じ話だと思いました。

## 時刻が9時間ずれていた

ついでに、もう一つ。

別の道具で、記録の時刻が**9時間ずれて**表示されていました。
夕方に作ったものが、朝の時刻になっている。

原因は、保存している時刻が**世界標準の時刻**だったことです。日本時間ではありません。

直し方は二つあります。保存を日本時間に変えるか、表示のときに9時間足すか。

**表示のときに足す**ほうを選びました。
すでに他の記録も世界標準で揃っているので、保存を変えると全部を直すことになります。

どちらが正しいという話ではなく、**すでにあるものと揃えるほうを選んだ**、という判断でした。
