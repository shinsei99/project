# 鍵は合っている。通信もできている。それでも空だった

物件の調査で、その土地に何が建てられるか（用途地域）、
どんな災害の想定があるかを調べます。以前は役所へ行っていましたが、
いまは国が公開しているデータで、かなりの部分が自動で取れます。

その仕組みを作っているときの話です。

## いつまでも、空

用途地域が、**いつ調べても空**でした。

- 利用の鍵は有効
- 通信は成功している
- エラーも出ない
- ただ、結果に何も入っていない

こういうとき、まず「その土地にはデータが無いのかな」と考えます。
実際、データが無い地域もあるからです。

でも、大阪市内の物件でも空でした。さすがにおかしい。

## 似た名前の、別のデータを呼んでいた

原因は、**呼ぶ先を間違えていた**ことでした。

国のデータは、種類ごとに番号が振られています。その番号を、一つ隣のものにしていました。

厄介なのは、**その番号のデータも実在する**ことです。
だから通信は成功します。ただ、そこには用途地域は入っていない。

そして、「その地点にデータがありません」という結果は、
**正常な応答**として返ってきます。エラーではありません。

つまり、**「呼ぶ先を間違えている」のと「本当にデータが無い」のが、区別できない**。

いまは、組み込む前に必ず**データがあると分かっている場所**（自社ビルの住所）で試すことにしました。
そこで何も返らなければ、呼ぶ先が違う、と判断します。

## 拡大すると、消える

地図のデータには、もう一つ癖がありました。

**同じ場所でも、地図を拡大すると件数が減る**のです。

細かく見ようとして拡大すると、逆に情報が消える。
これは、拡大するほど表示する情報を間引く仕組みになっているためでした。

しかも、データの種類によって、**扱える拡大率の範囲が違います**。
洪水や津波のデータは、決まった範囲でしか受け付けてくれません。

いまは、種類ごとに「使える中でいちばん粗い倍率」を決めて、それで取っています。

地図というのは、見た目より仕組みが込み入っている、と実感した部分でした。

## パーセントが、二つ付いた

小さな話ですが、これも実際にありました。

建ぺい率の表示が、**80%%** になっていました。

こちらが「%」を付けて表示していたのですが、**返ってくる値にすでに付いていた**のです。

しかも、あるデータは「60.0%」、あるデータは「60」という具合に、表記が揃っていません。

外から来た値を、そのまま画面に出すのはやめました。
一度こちらで整えてから出す。単位が付いていれば足さない、小数の余分なゼロは落とす。

## 社内の画面だけ、地図が出ない

もう一つ。地図（ストリートビュー）が、**社内の調査画面でだけ表示されません**でした。

原因は、鍵に「うちの公開サイトからしか使えない」制限が付いていたことです。
社内の画面は、公開サイトとは別の住所なので、弾かれていました。

制限を緩めれば動きます。でも、それは鍵の安全性を下げることになります。

そこで、**用途を絞った専用の鍵を新しく作りました**。
地図の埋め込みだけに使える鍵で、それ以外には使えないようにする。

鍵を一つで使い回していると、こういう場面で「緩める」方向に動きたくなります。
**用途ごとに分けて、それぞれ最小限にする**ほうが、結局は安全でした。

## 「呼べた」と「取れた」は別

この一件で覚えたのは、**呼べたことは、取れたことの証明にならない**ということでした。

通信が成功して、エラーも出ず、それでも中身が空。
プログラムから見れば、すべて正常です。

正しく取れているかどうかは、**期待する件数が返ってくるか**でしか測れませんでした。

だから、いまは「必ずデータがあるはずの場所」で試してから使う。
出てこなければ、こちらの間違いだと考える。この順番にしています。
