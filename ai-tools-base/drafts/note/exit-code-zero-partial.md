# 「完了しました」と出ていたのに、半分しかできていなかった

不動産の仕事では、決まった書式の書類をたくさん使います。
重要事項説明書、媒介契約書、賃貸借契約書、告知書。国や協会が用意している公式の書式です。

うちの道具は、それを200本ほど登録してあって、
「この物件のこの取引なら、この書類を出す」という形で選べるようにしています。

その登録の一覧を作り直したときの話です。

## 選ぼうとしたら、無かった

作り直す処理を走らせました。画面には進捗が流れて、最後に「完了しました」と出ました。

数日後、書類を作ろうとして、あるはずの書式が出てきません。
数えてみると、**200本のはずが126本**しか入っていませんでした。

74本、消えていたことになります。

## 途中で止まっていた。でも「成功」だった

原因を追うと、処理は**途中で止まっていました**。

登録の対応表に項目を一つ足したのに、それを取り出す側が古いままだった。
そこでエラーが出て、以降の書式は処理されずに終わっていました。

問題は、**そのことが「失敗」として扱われていなかった**ことです。

- 処理は終わった
- 「完了しました」と出た
- 一覧のファイルも、ちゃんとでき上がっていた（中身が半分でも）

パソコンの世界では、処理が終わったときに「うまくいったかどうか」を表す合図があります。
その合図が、**「うまくいった」になっていました**。

だから、次に動かす仕組みも、人も、「終わったんだな」と思う。
半分しか入っていない一覧が、そのまま使われました。

## 「終わった」と「できた」は別

この件でいちばん効いた直し方は、エラーの拾い方ではありませんでした。

**「いくつできたか」を出すようにしたこと**です。

いまは、作り直すたびにこう出ます。

> 走査完了：200本を登録（前回 200本／差 0）
> 　売買 11分類 139本
> 　賃貸 9分類 87本

こうしておけば、126本になった瞬間に分かります。前回との差も出るので、
「74本減った」と目に入る。

「終わりました」だけでは、何も分かりません。**終わったことは、できたことの証明になりません。**

## 数えられるものは、数えて出す

同じ考え方は、いろんな作業に使えます。

- PDFを書類ごとに切り分けたら → **何ページを、何ファイルにしたか**
- データを取り込んだら → **何件入って、何件はじいたか**
- 一括で変換したら → **入れた数と、出てきた数が合っているか**

うちの道具は、だいたいこの形にしてあります。
最後に数字が出るだけで、「なんとなく動いた」で通り過ぎることが減りました。

## ついでに見つかった、似た話

同じ道具で、書式を名前で探すときに、**名前の一部が一致すれば採用する**書き方をしていました。

「住宅賃貸借契約書」を探すと、「**サブリース**住宅賃貸借契約書」が先に見つかって、そちらが選ばれる。

これもエラーは出ません。**それらしい書類が出てくる**ので、気づくのは使う人です。
契約の場で気づいたら、目も当てられません。

いまは「まず頭から一致するものを探し、無ければ部分一致で探す」という順番に直しました。

似た名前の書類は、これからも増えます。
探す順番を決めていないと、**書式が増えた日に、静かに間違え始めます。**
