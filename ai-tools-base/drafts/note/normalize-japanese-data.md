# 同じ番号のはずなのに、検索に出てこない

顧客の台帳から、FAX番号で相手を探そうとしました。番号は分かっています。

**出てきません。**

台帳を目で追っていくと、その相手はちゃんと載っていました。番号も合っています。
それなのに、検索では見つからない。

## 見た目は同じ、中身は別

原因は、**番号の書かれ方**でした。

```
06-1234-5678
０６－１２３４－５６７８
(06)1234-5678
0612345678
```

全部、同じ番号です。台帳には、入力した人の癖がそのまま残っていました。
全角で打つ人、括弧を付ける人、ハイフンを省く人。

機械は、これを**別の文字列**として扱います。人間には同じに見えても、一文字ずつ比べると違う。

いまは、**数字だけを取り出したもの**を照合用に持っています。
表示は入力されたまま、比べるときだけ数字で比べる。これで見つかるようになりました。

## ハイフンに見える記号が、7種類あった

似た話で、もっと分かりにくいものがありました。

物件の住所を「町名」と「番地」に分ける処理で、**特定の物件だけ失敗**していました。

```
兵庫県加東市上三草1136−291
```

見ての通り、番地の間にハイフンがあります。何の変哲もありません。

調べたら、そこに入っていたのは、**ハイフンではなく「マイナス記号」**でした。

見た目はほぼ同じです。**印刷しても区別がつきません。**
それでも、機械にとっては別の文字です。

日本語の入力欄で「ハイフンのつもり」で使われる文字は、少なくとも7種類あります。
半角のハイフン、全角のハイフン、マイナス記号、長音記号（ー）、その他。

人が入力する欄では、**全部混ざります**。
だから、こちらは7種類とも同じものとして扱うようにしました。

## 濁点が、別の文字として入っていた

もう一つ、いちばん見つけにくかったものです。

メールをパソコンに保管する道具で、フォルダの名前が**一致しませんでした**。

画面に出すと、どちらも「ポータル」です。同じに見えます。
でも、機械の中では違いました。

- 一方は「ポ」という**一文字**
- もう一方は「ホ」＋「゜（半濁点）」という**二文字**

見た目は同じ「ポ」ですが、内部の持ち方が違う。
Macや一部のメールサーバーは、この「分けて持つ」形を使うことがあります。

こちらは、**表示するときと比べるときだけ**揃えることにしました。

## 原本は、書き換えない

この手の話で決めていることが一つあります。

**揃えるのは比べる瞬間だけで、元のデータは書き換えない。**

理由は二つあります。

一つは、**印刷したときに、入力された通りに出したい**から。
相手が全角で書いた番号を、こちらの都合で半角に直して書類に載せるのは、少し違う気がします。

もう一つは、**外部とやり取りするときに食い違う**から。
メールサーバーのフォルダ名などは、こちらが勝手に整えて送ると、別のフォルダを指してしまいます。

だから、比べるための「鍵」を別に持ちます。表に出るのは、あくまで原本です。

## エラーが出ない不具合

この種の問題は、**エラーが出ません**。

「見つからない」「分割できない」という、静かな結果になります。
しかも、たまたま揃っているデータでは正常に動きます。

だから、データが増えるほど気づきにくくなる。
「なんか最近、検索の精度が落ちた気がする」くらいの感覚でしか現れません。

いまは、**照合できなかったデータを捨てずに残す**ようにしています。
あとから中身を確認できれば、「見た目は同じなのに違う」という結論にたどり着けます。

見た目で分からないものは、中身を見るしかありませんでした。
