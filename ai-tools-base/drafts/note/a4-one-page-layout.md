# 画面で見る書類と、印刷して渡す書類は違う

退去の立ち会いが終わると、精算書を作ります。

敷金からいくら引くのか。何にいくらかかるのか。どちらの負担なのか。
これを一覧にして、退去された方にお渡しします。

この書類を自動で作る道具を使っているのですが、
作っていて実感したのは、**画面で見る書類と、印刷して渡す書類は別物**だということでした。

## 右端が、切れていた

最初に作ったものは、画面ではきれいに見えていました。

印刷すると、**右端の列が切れていました**。

備考の欄です。「経過年数を考慮して按分」といった、いちばん説明が必要な部分が、
紙の外に出ていました。

画面は、横に広げられます。紙は広げられません。
**画面の見やすさで列の幅を決めていた**のが原因でした。

## 横は必ず一枚、縦は書類による

いまは、こう決めています。

- **横（幅）は、必ず一枚に収める**
- **縦（高さ）は、書類によって決める**

精算書は、明細の行数が案件によって変わります。数行のこともあれば、20行を超えることもある。
だから、縦は複数枚になってもよい。

ただし、横は絶対に一枚です。**横がはみ出すと、その書類は読めません。**

## 二枚目に、見出しが無かった

明細が二枚に渡ったとき、次の問題が出ました。

**二枚目に、列の見出しがありません。**

「金額」「負担区分」「備考」がどの列なのか、二枚目だけ見ても分かりません。
説明しながら渡すので何とかなりますが、あとで見返す方には不親切です。

いまは、**すべてのページに見出しの行を繰り返す**設定を入れています。

## 署名をもらう書類は、必ず一枚に

もう一つ、誓約書があります。退去される方に署名と押印をいただく書類です。

これが**二枚に割れると、面倒なことになります**。
割印が要るかどうかの話になりますし、片方だけ返送されることもある。

この書類だけは、**縦も必ず一枚に収める**設定にしました。

行数が決まっている書類なので、無理に押し込んで字が小さくなる心配もありません。
**行数が変わる書類と、決まっている書類で、設定を変える**という判断です。

## 「収まった」と「読める」は違う

表計算ソフトには、「一枚に収める」という便利な設定があります。

これを使うと、はみ出したぶんは**自動で縮小**されます。設定としては正しく動きます。

ただ、縮小されすぎると、**収まってはいるが読めない**書類ができます。

だから、列の幅は最初から用紙の幅から逆算して決めておく。
余白も一緒に決める。片方だけ変えると崩れます。

そして最後は、**実際に印刷して見ます**。

- 右端が切れていないか
- 二枚目に見出しがあるか
- 字が小さくなりすぎていないか

ここまでやって、はじめて「渡せる書類」になります。

## 相手の手元に残るもの

精算書は、退去された方の手元に残ります。
場合によっては、家族に見せたり、後から見返したりする書類です。

作った本人の画面でどう見えるかは、正直、どうでもいい。
**相手が受け取ったときにどう見えるか**が全部でした。

自動化の話をしていると、つい「早く作れること」に目が行きます。
でも、書類の値打ちは、渡した先で決まります。そこを外すと、早く作れても意味がありませんでした。
