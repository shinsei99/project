# 同じ名前の写真が、片方だけ消えていた

管理している建物を、担当者が定期的に見て回ります。
外観、共用部、掲示板、気になったところ。そのつど写真を撮って、業務チャットへ投げる。

その写真を、建物ごとのフォルダへ自動で仕分ける仕組みを作りました。
撮った人は投げるだけ。整理は機械がやる。そういうつもりでした。

ある日、「巡回の写真、ちゃんとフォルダに入ってる?」と聞かれました。
入っているつもりでした。数えて、まずそこで驚きました。

- 記録の上では **84枚**
- フォルダに実際に置かれていたのは **9枚**

しかも、エラーは一度も出ていません。仕組みは毎回「終わりました」と言っていました。

## 名前が同じだと、あとの1枚が消えていた

保存するときの名前を「撮影日＋写真の題名」で作っていました。
たとえば「9月5日＋外観」。人が見て分かる名前です。

ところが、同じ日に同じ題名で2枚投稿されることがあります。
撮った本人からすれば、別の場所の別の写真です。でも名前は同じになる。

そこで、こういう作りにしていました。

- 同じ名前のファイルが既にある → **同じ写真をもう一度送ってきたのだろう。飛ばす**

「同じ名前なら、中身も同じはず」。
書いたときはそう思っていました。実際には、**中身の違う別の写真が、黙って消えていました**。

消えたことは、どこにも出ません。失敗とは扱っていないからです。
誰かが「あの写真は?」と言うまで、気づけない類の壊れ方でした。

## 逆に、同じ写真が2枚並ぶこともあった

反対の症状も起きていました。

同じ写真をチャットへ二度投げると、システムから見ると別の投稿です。
別の投稿なので別のものとして扱われ、名前が少し違えば2枚とも保存される。

実際に、**8枚（4組）が中身のまったく同じ写真**でした。

片方は消え、片方は増える。反対向きに見えますが、原因は一つです。

**「同じかどうか」を、名前で判断していたこと。**

## 直したこと

やったのは、判断の基準を変えることでした。

- **同じかどうかは、中身で決める。** 写真そのものから指紋のような値を計算して比べる
- **名前は、人が探すための札に戻す。** 名前がぶつかったら、中身を見る
  - 中身も同じなら、重ねない（送り直しなので1枚でいい）
  - 中身が違うなら、末尾に「-2」を足して両方残す

これで、「名前がぶつかったから消す」という判断が無くなりました。

## もう一つ、静かな不具合

同じ仕組みの中に、もっと分かりにくいものが混ざっていました。

「保存済みのものは飛ばす」という当たり前の処理があります。これが効いていませんでした。
理由は、比べている二つの値の**形式が違っていた**からです。片方は文字の「123」、もう片方は数の123。
人が見れば同じですが、機械は別物として扱います。

結果、いつまでも「まだ保存していない」と判断され、同じ写真を何度でも入れてしまう状態でした。
これもエラーになりません。ただ静かに、毎回すり抜けるだけです。

入り口で形をそろえるようにして直しました。

## 人が消したものが、戻ってきた

もう一つ、運用してすぐ分かったことがあります。

フォルダを見た人が「これは要らない」と外した写真が、次の実行でまた戻ってきました。
仕組みは「入れた記録」しか持っておらず、ファイルを消すと記録も消えるので、
「まだ入れていない写真」に見えてしまうのです。

そこで、**「入れないと決めた」という記録も別に残す**ようにしました。
これがないと、人の判断が毎回上書きされます。自動化の道具としては、そちらのほうが罪が重い。

## 結果

- 消えていた実体を、チャット側から取り直して **74枚を回収**（1枚は投稿者が削除済みで取れず）
- 建物ごとに仕分け直して、**37物件・58枚**
- 残りは、別会社の物件（意図して除外しているもの）と、人の判断が要る2枚

## 学んだこと

ファイルの名前は、人が付けた札です。
分かりやすくするための札であって、「これは世界で一つのこれです」という証明ではありません。

にもかかわらず、プログラムを書くときは、つい名前を頼りにしてしまいます。
名前が同じなら同じもの、違えば違うもの。日常の感覚に近いぶん、疑いにくい。

そして、この手の思い違いは**エラーになりません**。
止まってくれれば直せます。止まらずに、静かにデータが減っていくのがいちばん怖い。

自動で片付けてくれる仕組みほど、**「何を捨てたか」を言わせる**ようにしておく。
今回いちばん強く思ったのは、それでした。
