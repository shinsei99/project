# 休みの日に、催促のメッセージが飛んでいた

社内のチャットに常駐しているAIが、未完了の仕事を見つけて、担当者に催促を送ります。
「この件、まだ動いていませんが大丈夫ですか」という具合です。

これには条件を付けてあります。**休みの日には送らない。**
土日や年末年始に催促が飛んだら、ただの迷惑だからです。

その条件が、効いていませんでした。

## 設定は「有効」になっていた

画面を見ると、休業日の判定は有効になっています。年間の休暇スケジュール（Excelの表）を
読み込んで判定する、という設定です。

エラーも出ていません。動いています。ただ、**休みの日にも催促が飛んでいた**。

## 見に行っていた場所が、無かった

原因は二段階でした。

**一つめ。** 休暇スケジュールの置き場所が、**別のパソコンから見たときの住所**で登録されていました。

うちは2台のMacで同じ道具を動かしています。片方は事務所で動かしっぱなし、もう片方は開発用。
クラウドの同期フォルダは、2台で場所の書き方が違います。

登録されていたのは、開発用のパソコンから見た住所。
動かしっぱなしのほうには、**その場所が存在しません**。だから毎回、読み込みに失敗していました。

**二つめ。** ここが本題です。

読み込みに失敗したとき、この判定は「**休業日ではない**」と答える作りになっていました。

つまり、**分からないときは、平日として扱う**。
平日として扱うということは、**催促を送る**ということです。

## 「止まらないように」が、送るほうに倒れていた

この書き方をした理由は分かります。判定が使えないくらいで、AI全体が止まったら困るからです。
止まらないようにする。よくある考え方です。

でも、この判定の先にあったのは、**社外にも社内にも届くメッセージ**でした。

分からないときに倒す先を、考え直しました。

- **中で完結する処理**（集計する、画面に出す）→ 分からなくても**動かす**。あとから直せる
- **外に出る処理**（送る、投稿する、お金が動く）→ 分からないなら**止める**

基準は、**取り返しがつくかどうか**です。

休みの日に催促を送ってしまったら、取り返しがつきません。相手の休日に届いてしまう。
逆に、送らなかったぶんは、翌営業日に送れば済みます。

## ただし、止めたことは言う

止める側に倒すと、今度は別の問題が出ます。**黙って止まる**という問題です。

「催促が来ない」というのも、それはそれで障害です。
だから、止めたら、止めたことを画面に出すようにしました。

いまは、管理画面にこう出ます。

> 休業日：106件（2026年）　最終取り込み：8月24日 12:31

ここが **0件** なら、判定は効いていないという意味です。ひと目で分かります。

住所が正しいかどうかを目で確かめるのは難しい。でも、**件数はすぐ分かる**。
「設定した」ことではなく、「取り込めた」ことを見せる形にしました。

## 直したあとの確認

付け替えたあと、実際のデータで確かめました。

- 8月23日（土）→ 休業日
- 8月24日（月）→ 営業日
- 8月29日（土）→ 休業日

ここまで見て、はじめて「直った」と言えます。
設定を書き換えた時点では、まだ何も確かめていません。
