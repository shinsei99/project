# 中身は正しいのに、配れない書類

AIに、毎日の業務日報を作らせています。

その日のチャットのやりとりを読んで、担当者ごとに「終わったこと」「進行中のこと」をまとめ、
WordとExcelにして、決まった場所へ置く。人は目を通して直すだけ、という形です。

文章としては、早い段階でちゃんとしたものが出るようになりました。
つまずいたのは、そこから先です。**人に配れる見た目にならない。**

## 表の線が、出たり出なかったり

日報には表が入ります。担当者・件名・状況、という並びです。

こちらのMacで開くと、きれいに罫線が出ています。
ところが、**別の環境で開くと線が消えている**。表が、ただの文字の羅列に見えます。

原因は、線の引き方を「よくある表の型」に任せていたことでした。
その型をどう解釈するかは、**開くソフトによって違う**。

いまは、線の指定を書類そのものに書き込んでいます。
「上下左右と、中の縦横に、黒い細線を引く」と明示する。長くなりますが、どこで開いても同じになります。

表の幅も同じでした。自動で調整させると、**開く人によって列の幅が変わります**。
こちらで決めた幅で固定しました。

## 題字が、消えた

Excelのほうで、こんなことが起きました。

書き出したファイルを開くと、「一部の内容に問題があります」と警告が出て、
**いちばん上の「業務日報」という題字が消えていました**。

原因は、こちらが余計なことをしたからです。

列の幅を計算しやすくしようとして、**部品の内部の設定を書き換えていました**。
本来は触ってはいけないところです。Excelは、そのファイルを「壊れている」と判断して、
勝手に修復し、そのときに書式を落としていました。

細工をやめたら、直りました。**近道をしようとして、遠回りになった**話です。

## ページの終わりに、□だけが残る

日報は、担当者ごとにページを分けています。

出来上がったものを見ると、**ページの末尾に「□」が一つ、ぽつんと残っている**。
中身のない、箇条書きの記号だけです。

調べると、ページを分ける処理が、**見えない空の行を一つ足していました**。
その行が、直前の箇条書きの体裁を引き継いで、記号だけを表示していた。

いまは、空の行を作らずに「次の見出しの手前で改ページする」という指定に変えました。

## 箇条書きの二行目が、左に戻る

これも見た目の話です。

箇条書きで長い文を書くと、二行目が記号の下に潜り込んで、読みにくくなっていました。

こちらは、字下げを明示して直しました。
「本文は少し右へ、一行目だけ記号のぶん左へ」という、Wordでは定番の指定です。

## 気を利かせてくれる部分に、任せない

4つとも、同じ形でした。**ソフトが気を利かせてくれる部分に任せていた。**

- 表の型の解釈 → 開くソフトによって違う
- 部品の内部の設定 → 触ると壊れる
- ページを分ける処理 → 余計な行が増える
- 箇条書きの字下げ → 指定しないと崩れる

書類は、**作った本人の画面で見て終わりではありません**。
配った先のWordで、スマホのプレビューで、印刷したときに、同じに見える必要があります。

だから、見た目に関わるところは、面倒でも自分で指定する方針にしました。

## そして、必ず開いて見る

いちばん効いたのは、書き出したファイルを**実際に開いて、目で見る**ことでした。

ここに挙げた4つは、どれもプログラムを読んでいる限り気づけません。
処理は正常に終わっていて、ファイルもできている。開いて見るまで、崩れていることが分かりません。

中身が正しくても、切れて読めなければ「使えない書類」です。
そこを詰めるまでが、書類を作る仕事だと思っています。
