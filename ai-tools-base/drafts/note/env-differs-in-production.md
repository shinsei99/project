# 同じ道具なのに、パソコンによって結果が違った

うちでは、同じ道具を2台のMacで動かしています。
1台は事務所で動かしっぱなしの本番機、もう1台は作ったり直したりするための開発機です。

中身は同じものです。同じ場所から取ってきた、同じプログラム。

それなのに、**結果が違いました**。

## 片方だけ、読み取りの精度が低い

登記簿のPDFを読ませて、所在や面積を取り出す処理があります。

同じPDFを、両方のパソコンで読ませてみると、**取れる項目の数が違いました**。
片方は9項目取れるのに、もう片方は3項目しか取れない。

エラーは出ません。どちらも「読み取れました」と表示されます。

## AIが、呼ばれていなかった

原因は、**AIを呼び出すためのコマンドの場所**でした。

このプログラムは、書類を読むときにAIを呼びます。
そのAIのコマンドが**どこにあるか**を、プログラムの中に**そのまま書き込んで**いました。

パソコンによって、その場所は違います。
書いてあった場所に無かったパソコンでは、**AIが見つからず、簡易的な読み取りに切り替わっていました**。

問題は、**その切り替わりが表に出なかった**ことです。

結果は返ってきます。項目も入っています。ただ、数が少ない。
「このパソコンだと、なんとなく精度が低い気がする」という形でしか現れませんでした。

いまは、**場所を書かずに、探す**ようにしています。
そして、見つからなかったときは「簡易的な方法で処理しました」と記録に残します。

## 本番だけ、別の仕組みで動いていた

もう一つ、似たことがありました。

事務所で動かしっぱなしにしている常駐のプログラムが、
**開発で使っているのとは別のPython**（Macに最初から入っているもの）で動いていました。

つまり、開発機で新しい部品を足して書いたコードは、**本番では動きません**。
その部品が、本番の側には存在しないからです。

こちらは起動した時点で止まるので、まだ気づけます。

対処として、**本番で使える範囲だけで書く**ことにしました。
外部の便利な部品を使わず、最初から入っている機能だけで済ませる。

そして、**その理由を書き残しました**。

> HTTP は標準の機能を使うため、外部の部品は不要。

これが書いていないと、次に触る人（数か月後の自分を含む）は、
何も知らずに便利な部品を足します。**制約は、書いてあってはじめて制約になります。**

## 「同じコードだから同じ動き」ではない

二つとも、**開発機では正常に動いていました**。

- 一つめは、本番でも動くが**中身がすり替わっていた**
- 二つめは、本番では**そもそも動かなかった**

厄介なのは、明らかに一つめです。動いてしまうので、誰も困りません。
困らないまま、精度の低い結果が使われ続けます。

いまは、環境によって変わるものは**探して見つける**。
そして、**別の方法に切り替わったら、切り替わったと言う**。

この二つを決めました。

2台で同じものを動かすというのは、思っていたより気を遣うことでした。
**同じコードだから同じ動きになる、とは限りません。**
