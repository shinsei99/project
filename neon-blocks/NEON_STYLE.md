# ネオンシリーズ 共通の型（6本）

**なぜ要るか**: 6本は `neon-blocks` の1つのアプリに同居し、下の帯で行き来する。
遊びの中身は違ってよいが、**入口・字面・音・音ボタンの位置が違うと「別のアプリに来た」と感じる**。
2026-08-29 に実測したところ、揃っていたのは「暗い地」「名前」「切り替え帯」の3つだけだった。

**このファイルが正**。各ゲームを触るときは、ここに合わせること。

---

## 1. 配色（共通5色）

| 用途 | 色 | 使いどころ |
|---|---|---|
| 主 | `#41E3FF`（シアン） | 枠・道・味方・進む方向 |
| 副 | `#FF4FC3`（マゼンタ） | 敵・危険・決定ボタン |
| 強調 | `#FFD54F`（金） | 得点・ゴール・報酬 |
| 成功 | `#7CFF4F`（緑） | 可能・達成・HP |
| 補助 | `#B36BFF`（紫） | 設定・その他 |

地は `#0A0720`〜`#241247`（夜）。**面は暗く、輪郭を光らせる**（塗りつぶさない）。

> **ゲーム固有の色は残してよい**（ブロックスの多色ブロック、グラビティの惑星など）。
> 揃えるのは**枠・ボタン・文字・HUD**。中身の絵まで同じ色にすると見分けが付かなくなる。

## 2. 書体

- 日本語 … **Zen Kaku Gothic New**（500 / 900）
- 英数字 … **Orbitron**（700 / 900）
- どちらも SIL OFL。**使う文字だけ同梱**（各アプリの `tools/fetch-font.py`）
- 指定は必ず `Orbitron,"Zen Kaku Gothic New",sans-serif` の順（英数字が Orbitron に落ちる）
- **丸ゴシックは使わない**（幼く見える）

## 2-b. 題字のレインボー

**題名は6本ともレインボーのグラデーション**（`background-clip:text`。canvas の場合は
`createLinearGradient` を文字幅ぶん作って `fillStyle` にする）。

**並びはゲームごとに変える。** 下の6色の輪から**4色を、開始位置を1つずつずらして**取る。
同じ家族に見えて、1本ずつ違って見える（調の振り分けと同じ考え方）。

```
輪: G #39FF14 → C #00F0FF → P #B026FF → M #FF2D95 → Y #FFD54F → O #FF8A3D →（Gへ戻る）
```

| ゲーム | 開始 | 並び |
|---|---|---|
| ネオンブロックス | 0 | G → C → P → M |
| ネオンサイボーグ | 1 | C → P → M → Y |
| ネオンタワー | 2 | P → M → Y → O |
| ネオングラビティ | 3 | M → Y → O → G |
| ネオンアイス | 4 | Y → O → G → C |
| ネオンエスケープ | 5 | O → G → C → P |

**常時見えているヘッダーの題名にも同じ並びを使う**（サイボーグ・グラビティ・ブロックス・エスケープ）。

## 3. 入口（タイトル画面）

**6本すべてに全画面のタイトルを出す。** 中身は次の4つだけ。

1. 日本語の題名（大・発光）＋ ラテン表記（小・マゼンタ）
2. 1行の説明
3. **START**（マゼンタのネオン管・押せることが分かる明るさ）
4. 副ボタン（ステージ選択・図鑑など。無ければ省く）

## 4. 音ボタン

**画面の右上に固定**。48×44px 程度、暗い地＋シアンの縁。設定画面の中に隠さない。
状態は各アプリの localStorage に持つ（キーはアプリごとで可）。

## 5. 音

**同じ楽器・同じ音階・違う調**。これで「同じシリーズの別の曲」に聞こえる。

- 音量: `master 1` → `sfx 0.9` / `bgm 0.24`（±0.04まで）
- BGM: **メジャーペンタトニック（0,2,4,7,9）**のみ。メロディ=`triangle`、ベース=`sine`
- 効果音: 短い `voice()`＋`noise()`。**同じ出来事には同じ音**（取得＝上がる3音／失敗＝下がる2音）
- **調はゲームごとに変える**（下の表）。テンポは遊びに合わせて自由

| ゲーム | 調 | もとの調 | 基準音（実装での定数） |
|---|---|---|---|
| ネオンブロックス | **A** | A（据置） | MIDI 57=A3 / 45=A2（`ARP` / `BASS`） |
| ネオンサイボーグ | **D** | A から移す | ベース `A2 110` → `D3 146.83` |
| ネオンタワー | **E** | C から移す | 各トラックの Hz を **×1.2599**（+4半音） |
| ネオングラビティ | **G** | A から移す | `110` → `98.00`、`220` → `196.00` |
| ネオンアイス | **C** | C（据置） | メロ `523.25` / ベース `130.81` |
| ネオンエスケープ | **F** | C から移す | メロ `698.46` / ベース `174.61` |

## 5-b. 盤の枠

盤（canvas やその親）は**6本で同じ枠**にする。

```css
border:2px solid rgba(65,227,255,.5); border-radius:8px;
box-shadow:0 0 22px rgba(65,227,255,.2), inset 0 0 26px rgba(65,227,255,.06);
```

**狭い画面だけ別の形にしない**（エスケープが `@media` で角17px・枠4pxに上書きしていて、
スマホだけ角が丸かった）。

**★6本すべてが枠を持つ**（2026-08-29 に最後の2本を対応）:

- **ブロックス** … 盤が無くパネルを積んだ作りだったので、「目標の形＋NOW/NEXT」を
  ひとつの枠（9:16）に入れた。セルの大きさは枠から決める
- **タワー** … canvas が画面いっぱいだったので、**12px ぶん内側に寄せて**枠を出した。
  比率（390:844）は変えていない＝遊びは等倍で3%小さくなるだけ

## 5-c. 常時見えている題名

**日本語1行だけ**（レインボー）。ラテン表記と副題は**タイトル画面にしか出さない**
（遊んでいる間ずっと出す必要がなく、その分だけ盤が広くなる。実測でグラビティは45px の帯だった）。
全画面 canvas の2本（タワー・アイス）は持たない。

## 5-d. ルールの置き場

**タイトルに長い説明を書かない。** ルールは次のどれかに置く（既にある型）:

| ゲーム | 置き場 |
|---|---|
| ブロックス | 左上の **?** |
| サイボーグ | 右上の **?**（★初めての人には自動で開く。`localStorage` で判定） |
| タワー | **図鑑** |
| エスケープ | 盤の下の **「ルールと記号」** 折りたたみ |

タイトルに書くのは**1〜2行**まで。

## 6. 画面の向き

**縦持ち**に統一する（スマホで遊ぶため）。

**比率は 9:16（0.563）を基本**とする。**iPhone(390×844) で盤が一番大きくなる比率**だから
（2:3 だと画面の64〜69%しか使えていなかった。9:16 にして 75〜82%＝面積 +14〜19%）。

| ゲーム | 比率 | 盤（iPhone 390×844 実測） | 画面の高さに対して |
|---|---|---|---|
| ネオンタワー | 0.462 | 390×844 | 100%（全画面。**据え置き**） |
| ネオンサイボーグ | **9:16** | 366×650 | 77% |
| ネオンアイス | **9:16** | 386×689 | 82% |
| ネオングラビティ | **9:16** | 378×648 | 77% |
| ネオンエスケープ | **9:16** | 355×632 | 75% |
| ネオンブロックス | DOM可変 | — | — |

**★タワーだけ 0.462（＝iPhoneそのままの形）。** 盤の中に HUD も操作ボタンも入っていて
画面を100%使っているので、9:16 にすると**画面の18%を捨てる**ことになる。据え置きが最適。

**★比率を変えるときは、盤を広げるのではなく「世界を伸ばす」こと。**
物の位置を動かさずに端を伸ばせば距離が変わらないので、遊びは壊れない。実例:

- グラビティ … 高さ 900 → 1067。物の位置は動かさず、**全部に同じ値を足して中央へ寄せた**だけ。
  `tools/verify_solutions.py` は全20面が正解到達のまま
- アイス … 高さ 750 → 889。増えた139pxは**ショーケースの中**に足した（`CASE_BOT` と `BASEY` を
  同じだけ下げる）。看板・店内・カウンターの高さは変えていない
- エスケープ … 高さ 900 → 1067。座標は面ごとに自動で伸縮する（`buildFit`）ので定数を変えるだけ

**★盤を高くすると、下のUIが画面に収まらなくなる。** 実測で必要だった詰め:

| ゲーム | 収めるためにやったこと |
|---|---|
| エスケープ | HUDを1行に（狭い画面ではステージ名の札を隠す）＋余白を詰めて計 **-60px** |
| グラビティ | **ステージ選択と説明文を畳んだ**（`☰ ステージ選択` で開く）＋盤に `max-height` の保険 |
| アイス | 不要（下はヒント1行だけだった） |

## 7. その他

- **favicon を必ず入れる**（data URI で埋め込む。外部ファイルにすると 404 が Console に残る）
- 下の切り替え帯（`www/games/_switch.js`）は**触らない**。各ゲームは読み込むだけ
- 直したら `python3 neon-blocks/tools/sync-games.py` で集合側へ入れ直す
