# GrowLog（グロウログ）— 成長記録アプリ

身長・体重を毎日記録して、**伸びが目で分かる**ようにするアプリ。
小学校中学年〜中学生が自分で使う想定（幼児向けの見た目にはしない）。

- Vite + React + TypeScript + Tailwind CSS v4 / グラフは recharts
- データは **localStorage のみ**（サーバー不要・通信なし）。キーはすべて `growth-app:` で始まる
- PWA 対応（`manifest.json` ＋ `sw.js`）。ホーム画面に追加すると単体アプリとして開ける
- スマホ縦画面が前提。PC でも中央 1 カラムで崩れない

## 動かし方

```bash
./run.sh                 # = npm run dev（127.0.0.1:3005）
npm run build            # 本番ビルド → dist/
python3 -m http.server 3006 --bind 127.0.0.1 --directory dist   # PWA の確認はビルド後に
```

**service worker は本番ビルドでだけ登録する**（`import.meta.env.PROD`）。
開発中に登録すると、キャッシュが残って「直したのに変わらない」が起きるため。

## 画面

| 画面 | 中身 |
|---|---|
| ホーム | 今日の日付・年齢（○歳○か月○日）・最新の身長体重と前回差・記録ボタン（今日ぶんがあれば「修正」に変わる）・連続記録・誕生日まで・バッジ |
| グラフ | 身長／体重の切り替え、1か月／1年／すべて、平均身長ライン、目標ライン、点タップでその日の値とメモ |
| くらべる | 1年前の記録との差を大きく表示／家族を登録して棒で身長比べ（複数登録・削除可） |
| カレンダー | 月表示。記録のある日に色。日付タップで確認・修正・削除。記録の無い日はその場で入力できる |

設定はホーム右上の歯車から（プロフィール変更・サンプル投入・全削除）。

## データの持ち方

```ts
記録       { date: 'YYYY-MM-DD', height: number, weight: number, memo: string }   // 1日1件・同じ日は上書き
プロフィール { name, birthday, gender, targetHeight }
家族       [{ id, name, height }]
バッジ     [{ id, date }]      // 獲得日だけを保存し、条件の判定は毎回記録から計算し直す
```

キー: `growth-app:profile` / `growth-app:records` / `growth-app:family` / `growth-app:badges`

## ファイルの役割

| 場所 | 役割 |
|---|---|
| `src/App.tsx` | 画面の出し分けと **localStorage への保存の一本化**（各画面は保存を知らない） |
| `src/lib/storage.ts` | 読み書き。壊れた値でも落ちないよう既定値に落とす。`upsertRecord` が1日1件を保証する |
| `src/lib/date.ts` | 年齢・連続日数・誕生日まで。**日付は必ず `YYYY-MM-DD` の文字列**で持ち回す |
| `src/lib/average.ts` | 平均身長ラインの**目安値の表**。差し替えるならここだけ |
| `src/lib/badges.ts` | バッジ条件。記録から毎回計算し直す（状態を二重に持たない） |
| `src/lib/sample.ts` | 開発用サンプル（3か月＋1年前の数日） |
| `src/components/ui.tsx` | カード・ボタン・数値入力・シートなど見た目の決まり |

## 調べた事実・つまずいた所

- **平均身長の表は「目安」**。5〜17歳は学校保健統計調査、1〜4歳は乳幼児身体発育調査の値を丸めた概数として持っている。
  **公表値との厳密な照合は未実施**なので、正確さが要るなら `src/lib/average.ts` の表を差し替える。
  表の範囲外（1歳未満・18歳以上）は**線を引かない**（作り話をしない）。
- **目標身長の線を常に描くとグラフが潰れる**。目標150cm・現在120cmだと変化がまったく読めなかったので、
  目盛りの中に入るときだけ線を描き、遠いときは「目標まであと◯cm」を文字で出すようにした。
- **recharts の onClick は型が合わない**（`CategoricalChartFunc`）。`(state: unknown)` で受けて
  `activePayload[0].payload` を取り出す形にした。Tooltip の formatter も同様に型が厳しいので既定表示のまま使う。
- **日付を `new Date('2026-08-30')` で作ると UTC 扱いになり1日ずれる**。`parseKey()` で
  年・月・日に分解してローカル時刻の Date を作っている。
- `<meta name="apple-mobile-web-app-capable">` は非推奨の警告が出る。`mobile-web-app-capable` を併記した。

## 検証（2026-08-30 サブPC）

`./va.sh` の headless Chrome で実測。**Console エラー0件**、390×844 / 768×1024 / 1440×900 の
3幅で横スクロール・はみ出し・小さすぎるタップ領域・文字の重なり **すべて0件**。
初回設定→記録→バッジ獲得演出→グラフ→カレンダーの確認/修正/削除→くらべる（1年前・家族）まで画面で確認。
本番ビルドを配信して **manifest.json と sw.js が 200 で読まれ、service worker が登録される**ところまで確認済み。

**未確認**: 実機スマホでの操作感と、ホーム画面に追加したときの見え方（headless では確かめられない）。
