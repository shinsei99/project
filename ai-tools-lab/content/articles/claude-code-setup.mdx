このサイトは Claude Code を主軸に据えています。ここが最初の関門なので、
**手順を飛ばさずに書きます。** うまくいかなかったときの分岐も併記します。

## 0. 前提：Claude Code とは何か

Claude Code は**ターミナルの中に住むコーディングエージェント**です。チャット欄に
コードを貼って返してもらうのではなく、**あなたのフォルダを直接読んで、直して、
テストして、コミットまでやる**。ここが従来のチャット型との決定的な差です。

したがって「使い始める」＝「自分のプロジェクトのフォルダで起動する」ことになります。

## 1. 必要なもの

| 必要なもの | 確認方法 | 無かったら |
|---|---|---|
| ターミナル | Mac: `ターミナル.app` / Windows: PowerShell | OS標準で入っています |
| Node.js 18以上（npm 版を使う場合） | `node -v` と入力 | 公式サイトからLTS版を入れる |
| Claude のアカウント | claude.ai にログインできるか | 無料登録できます |

`node -v` を打って `v18.0.0` 以上の数字が出れば大丈夫です。`command not found` と
出たら Node.js が入っていません。**ネイティブインストーラを使う場合は Node.js は不要**なので、
その場合は次の手順の②を選んでください。

## 2. インストール

方法は2つあります。**どちらか片方だけでいい**です。

### ① npm で入れる（Node.js を既に使っている人向け）

```bash
npm install -g @anthropic-ai/claude-code
```

`-g` はグローバル、つまり「どのフォルダからでも呼び出せる場所に入れる」という意味です。

### ② ネイティブインストーラで入れる（Node.js を入れたくない人向け）

macOS / Linux:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows（PowerShell）:

```powershell
irm https://claude.ai/install.ps1 | iex
```

### インストールできたか確認する

```bash
claude --version
```

バージョン番号が出れば成功です。

**`command not found: claude` と出たら**、インストールは成功しているが「PATH が通っていない」
状態です。ターミナルを一度閉じて開き直してください。それでも駄目なら、シェルの設定ファイル
（`~/.zshrc` など）に、インストーラが表示したパス（多くは `~/.local/bin`）を追加します。

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

## 3. 起動とログイン

**まず、作業したいプロジェクトのフォルダへ移動します。** ここを飛ばして適当な場所で
起動すると、Claude Code は関係のないファイルを読んでしまいます。

```bash
cd ~/projects/my-app   # 自分のプロジェクトのパスに置き換える
claude
```

初回はブラウザが開いてログインを求められます。認証方法は2通り：

- **サブスクリプション（Claude Pro / Max）でログイン** … 月額定額。使うほど得。
  長時間の試行錯誤をする人はこちら。
- **Anthropic Console の APIキー** … 従量課金。使った分だけ。
  たまにしか使わない人や、会社の経費で従量管理したい場合。

料金は改定されることがあるため、**金額は必ず公式の料金ページで確認してください。**
参考までに、APIの従量課金は 2026年8月時点で Claude Opus 5 が入力 $5 / 出力 $25（100万トークンあたり）、
Claude Sonnet 5 が入力 $3 / 出力 $15、Claude Haiku 4.5 が入力 $1 / 出力 $5 です。

> **どちらを選ぶべきか。** 「毎日1時間以上さわる」なら定額、「週に数回、数分」なら
> 従量課金が目安です。定額プランは長時間の試行錯誤で青ざめずに済むのが最大の利点で、
> エージェントに任せる使い方とは相性がいい。

## 4. 最初の1回：`/init` を打つ

起動できたら、いきなり難しい指示を出す前に、これを打ってください。

```
/init
```

Claude Code がプロジェクト全体を読んで、`CLAUDE.md` というファイルを作ります。
これは**「このプロジェクトはこういう構成で、こういうルールで動いています」という
引き継ぎ書**です。以降のセッションで毎回読み込まれるので、同じ説明を繰り返さずに済みます。

**`CLAUDE.md` は育てるファイルです。** 「テストは `npm test` で走らせる」「このフォルダは
触らない」といったルールを書き足していくほど、指示が短くて済むようになります。

## 5. 覚えるべき操作は6つだけ

| 操作 | 何が起きるか |
|---|---|
| そのまま日本語で入力 | 指示になる。「ログイン画面のバグを直して」でいい |
| `/help` | 使えるコマンドの一覧 |
| `/clear` | 会話をリセット。**話題が変わったら打つ**（後述） |
| `/model` | 使うモデルを切り替える |
| `Shift + Tab` | プランモード切替。**いきなり編集させたくないとき** |
| `!` を先頭につける | シェルコマンドをその場で実行（例: `!npm test`） |

補足でもう2つ。`@` を打つとファイル名を補完してくれるので、`@src/app.ts のバグを直して`
のように**対象を名指し**できます。`Esc` は生成の中断です。

### `/clear` を打つ癖をつける

Claude Code は会話の履歴を全部覚えています。前の話題が残ったまま別の作業を頼むと、
関係ない文脈に引きずられて精度が落ちます。**作業が一区切りしたら `/clear`。**
これだけで体感の賢さが変わります。

### プランモード（Shift + Tab）

いきなりファイルを書き換えられるのが怖いうちは、これを使ってください。
**「何をするつもりか」を先に説明させ、承認してから実行**させられます。
慣れるまでの安全弁として非常に有効です。

## 6. 最初の指示の書き方

初心者がいちばん失敗するのは「指示が短すぎる」ことです。悪い例と良い例：

```
❌ バグを直して

✅ ログイン画面で、パスワードを間違えたときにエラーが出ずに
   真っ白になる。原因を調べて直してほしい。
   再現手順: /login を開く → 適当なパスワードで送信
   テストは npm test で走ります
```

**「症状・再現手順・確認方法」の3点セット**を書くだけで、成功率が跳ね上がります。
これはAIへの指示というより、**人間の同僚に頼むときの書き方と同じ**です。

## 7. つまずきどころ

| 症状 | 原因 | 対処 |
|---|---|---|
| `command not found: claude` | PATH が通っていない | ターミナルを開き直す → 手順2の PATH 追加 |
| 関係ないファイルを読み始める | 起動フォルダが違う | 一度終了し、`cd` してから起動し直す |
| 途中から的外れになる | 会話が長すぎる | `/clear` してから要点だけ再投入 |
| 勝手に大きく書き換える | 指示の範囲が曖昧 | プランモード（Shift+Tab）で承認制にする |
| 権限を毎回聞かれて煩わしい | 既定が慎重側 | `/config` で許可設定を見直す |

## 8. ここから先

導入が済んだら、次は**任せる範囲を広げていく**段階です。いきなり全部を任せるのではなく、
「1ファイルの修正」→「機能の追加」→「調査から実装まで」と段階を上げるのが結局いちばん速い。
