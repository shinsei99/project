# madori-tracer

- `app.py` ほか: StreamlitメインアプリのAI間取りトレーサー（port 8511、launchd常時起動: com.shinsei.madori-tracer）
- `editor/`: 手動間取りエディタ（Vite + React + TypeScript、port 5175、launchd常時起動: com.shinsei.madori-tracer-editor）。パーツ配置・トレース画像の下敷き編集用。`npm run build`後に`node_modules/vite/bin/vite.js preview`でdistを配信する構成のため、editor側のコードを変更したら`npm run build`→`launchctl kickstart -k gui/$(id -u)/com.shinsei.madori-tracer-editor`が必要（devサーバーの自動リロードは常時起動プロセスには反映されない）

## エディタの保存フォーマット（2026-08-10 追加）

以前は**PNG書き出しのみ**でタブを閉じると編集内容が消えていた。JSON保存/読み込みと localStorage 自動保存を追加。

```jsonc
{ "version": 1,
  "parts": [ /* types.ts の Part[] */ ],
  "bg": { "dataUrl": "data:image/...", "x": 0, "y": 0, "w": 800, "h": 600 },  // null 可
  "bgOpacity": 50 }
```

- **「保存」** → `floor-plan.json`。下絵も dataUrl ごと含むので**このファイル1つで後日そのまま再編集できる**（物件フォルダに置く運用）
- **「開く」** → 同JSONを読み込み。読み込み前に `pushHistory` するので「元に戻す」で戻せる
- **自動保存** → `localStorage['madori-editor-state-v1']` に500msデバウンスで書き込み、次回マウント時に復帰。下絵のdataUrlで容量超過した場合は**パーツだけ保存**して警告表示（下絵は「開く」で復元）
- `restoredRef` で復帰完了まで自動保存を止めている。**これを外すと空の初期stateが保存済みデータを上書きするので注意**
- `sanitizeParts()` / `sanitizeBg()` は外部ファイル由来のデータを検査してから state に入れる（座標がNaN・typeなし等は捨て、サイズ0や不正な回転は補正、`data:image/`以外のdataUrlは拒否）。**任意項目（tatamiJou / fontSize 等）はスプレッドで保持**するので、Part に項目を足してもここは変更不要
- 読み込み口は最小形（`type/x/y/w/h`＋任意で`label`）のPart[]を受理する

## 間取り図の自動部品化は検証済み・不採用（2026-08-10）★再挑戦しないこと

「間取り画像を解析して部品にし、下絵なしで編集する」を実装して実測したうえで**見送った**。実際の2階建て図面（2362×1654）での数値。

**やってみた3方式と結果**

1. **意味で分ける**（部屋・ドア・設備を分類）→ 記号認識になって破綻。部屋領域はCVの閉領域検出では0個しか取れず、OCRの部屋名を種にした floodFill に変えて9個。ただし出てくるのは「画像の上に色の箱を並べたもの」で、下絵はラスタのまま＝箱だけ動いて図面は動かない
2. **線として分ける**（意味を理解せず線を部品化）→ ラン分解1492本。文字をOCRで先に除外して線から抜くと **-266本**（これがいちばん効いた）、OCRしきい値を0.4→0.25で **-136本**、重複除去で **-71本** → 最終307本／円弧9個／文字19個／ブロック7個／1.7秒
3. **厳密モード**（丸めなし・等倍・端の許容0）→ 元に無い画素は **0.156%**（36万画素中566画素＝目視不能）まで下がるが、線で説明できるのは **80%だけ**。残り20%（文字・円弧・記号）は元画素の画像パーツが必要で、線は788本に増える

**不採用の理由**: 2の方式は OCR で文字を読み直して別フォントで描くため**絵が変わる**（縦書きの「押入」が「奨」に、コンロ記号が消滅、姿図が崩壊）。3の方式なら絵は保てるが、20%が固定画素のままで、788本の線を管理する割に**得られるのは「壁を動かせる」ことだけ**。下絵に上書きする既存方式のほうが図面が劣化せず手間も少ない。

**参考**: 専門の研究リポジトリ（`SizheHu/Raster-to-Graph` 等）は Python 3.7 + torch 1.9.1 + CUDA 11.1 + 自作CUDAカーネルのコンパイルが必要で、**Mac では動かない**。
