## 2026-08-27（サブPC）— 「長文をペーストすると途中までしか入らない」の調査と、編集画面の作り替え

### 完了したこと

**調査の結論: スクラップメモは切っていなかった。切れていたのはコピー側。**

オーナー報告「スクラップ編集で長文をペーストすると途中までしか反映されない。開き直しても出てこない」。
iPhoneアプリ（配信中の 1.0.4 / build 8）でのみ発生、とのことだった。

| 調べたこと | 結果 |
|---|---|
| Mac Chrome で 10,291字を入力→保存→再オープン | **無傷**（localStorage 往復もOK） |
| **iOSシミュレータ（本物のWebKit・iPhone 17 Pro / iOS 26.5）**で 7,091字 | **無傷**。`len=7091` / 高さ 9,620px に正しく伸長 / 保存 `block=7091` / 再オープン `len=7091` |
| コードにテキストを削る処理 | **1か所も無い**（`saveMemo` は `ta.value` をそのまま、`save()` は失敗時トースト） |
| 実際に切れた文章の長さ | **2,454字 / 7,228バイト**（Q1〜Q7）。7,091字を通している以上、量の問題ではない |

**決め手**: オーナーが同じ資料を Claude Code のチャット欄へ2回貼ったところ、
**1回目は Q1〜Q5 で切れ、2回目は Q1〜Q7 が全部入った**。
貼る先は同じなのに結果が変わった＝**変わったのはコピーの方だけ**。
iOSで長文を指でなぞって選択すると、画面に見えている範囲までで選択が終わることがある。
確実にコピーするなら「すべてを選択」を使う（なぞらない）。

※ ただし、オーナーのコピー操作そのものは観測していない。
**「測った範囲では無罪」**という言い方が正確で、「絶対に切らない」とまでは検証していない。

**そのうえで、実在の欠陥を1つ直した: 長文だと「完了」に指が届かない。**

テキスト欄は内容に合わせて伸びる（`autoSize`）。実測で **7,091字＝9,620px**、
今回の 2,454字でも **約3,300px**。「完了／キャンセル」は編集内容の末尾（`sh-foot in-scroll`）に
置かれていたので、iPhoneでは数画面ぶんスクロールしないと押せなかった。
届かずに枠外をタップすると `closeMemo()` ＝**保存せず閉じる**。
＝コピーが正常でも「長文を貼ったのに消えた」が普通に起こりうる経路だった。

**直し方（オーナー案）: 完了／キャンセルをヘッダー（タイトルの右）へ移した。**
下に固定バーを作ると編集エリアが縦に削られるが、既存のヘッダーに入れれば**縦を1pxも消費しない**。
あわせて字数の独立行を廃してタイトル横に畳んだ（その行のぶん編集エリアが広がる）。

- `makeMemoFootDOM()` と `sh-foot.in-scroll` は廃止。`edAppendBlock()` は単純な append に戻した
- `#memo-editor` の下余白を 6px → 26px（フッターが無くなった分）
- 字数は3桁区切り（`toLocaleString()`）

### 発生したエラーと解決策

- 症状: シミュレータへタップも ⌘V も送れない（`simtap.py` が osascript で落ちる）
  → 原因: **ターミナルに「アクセシビリティ」権限が無い**。System Events が
    どのアプリについても `count of windows = 0` を返す（Terminal 自身でも0だった）
  → 迂回: **タップを使わずに計測した**。`xcrun simctl openurl` でページを開き、
    ページ内に一時的な計測スクリプトを差し込んで、結果を `fetch('/diag?…')` で
    ローカルのHTTPサーバーへ送り返し、**サーバーのアクセスログを読んだ**。
    OCRより確実で、画面遷移も要らない。**計測コードは剥がし、`__DIAG__` の grep 0件を確認済み**

- 症状: 直したのに画面が変わらない
  → 原因: `python3 -m http.server` はキャッシュ制御を返さないので**ブラウザが旧版を使う**
  → 直し方: URLに `?v=<時刻>` を付けて開く

- 症状: タイトルと字数を1つの `<h3>` に入れたら、iPhone幅で**字数のほうが先に切れた**（`3,0…`）
  → 原因: `text-overflow:ellipsis` は要素の末尾から切るので、後ろに置いた字数が犠牲になる
  → 直し方: `<h3>` を flex にし、**タイトルだけ縮む**（`flex:0 1 auto`）・
    **字数は縮まない**（`flex:0 0 auto`）に分けた

### 完了したこと（続き・写真の容量対策 その1）
- **写真を保存前に縮小するようにした**（`shrinkImageDataURL`）。長辺1600px・JPEG品質0.82。
  入口は2か所とも通す: `addPhotoToPage`（写真タブ）と `addImageBlock`（編集中に写真挿入）

  - 保存場所自体はiPhone本体: アプリのサンドボックス内

    ＝ IndexedDB 側なら「本体の容量が上限」に近い。**入れ物を替えれば広げられる**
- 縮小の効果（4032×3024の画像3種で実測。JPEGは中身で大きく変わるため幅で示す）

  | 細かいノイズ（最悪） | 8.21MB | 10.95MB | 2,391KB | 約2枚 |

  → **1枚で上限だったのが5〜19枚まで延びた**が、**根本解決ではない**。
  写真を本格的に使うなら画像だけ IndexedDB へ移すのが本筋

### 発生したエラーと解決策
- 症状: iOSでスクラップ編集を開いてキーボードが出ると、**シートの上部（ヘッダーとメモの先頭
  8行ほど）が画面の上へはみ出して触れなくなる**。スクロールしても戻せない
  → 原因: iOS(WKWebView)はキーボードが出ると**WebView自体が縮む**（`innerHeight` 874→538）。
  ところが `.sh-box{max-height:96vh}` の **`vh` は縮まない**うえ、`openMemo` が開いた瞬間に

  `align-items:flex-end` なので、あふれた310pxは**下ではなく上へ**出る。

  → 直し方: 上記の `96%` 化 ＋ `visualViewport` の resize/scroll への追従（`fitOpenSheets`）
- 症状: シミュレータでソフトキーボードが出ない（文字欄をタップしてもキャレットは動くが無反応に見える）

  **そのバーを消している**ので、結果として何も出ない。
  → 直し方: **メニューから外す**（`⇧⌘K`）。`defaults write com.apple.iphonesimulator
  ConnectHardwareKeyboard -bool false` は**効かなかった**（メニューの✓は付いたまま）。
  確認は System Events で `AXMenuItemMarkChar` を読むのが確実
- 症状: `osascript`（System Events）でシミュレータを操作できない
  → 原因: このMacで osascript に**補助アクセス（アクセシビリティ）が未許可**。`-1719` が出る。
  → 迂回: `simctl` には tap が無いので、**シミュレータに入った `.app` の `public/index.html` に

### 発生したエラーと解決策
- 症状: スクラップ編集を開くと**メモの先頭が画面外**にある。
  原因は2つ重なっていた。
  1. `makeBlockDOM` の textarea `focus` ハンドラが「textarea の**下端**が見えるように」
     `#memo-editor` をスクロールしていた。`.block-textarea` は `min-height:480px` で
     編集エリア（実測 clientHeight 681px、実機ではさらに低い）より高くなり得るため、
     開くたびに必ず下へずれて先頭が隠れた
  2. 長いメモでは textarea 自身が内部スクロールし、`setSelectionRange(末尾)` で
     さらに下へ送られていた
  → 直し方: ①focusハンドラは **textarea が編集エリアより高いときは下端合わせをしない**
  （上端が隠れているときだけ上へ戻す）②`.block-textarea` を `flex:1 0 auto` + `overflow:hidden`
  にし、`autoSize()` を text ブロックにも掛けて**内容の高さまで伸ばす**（内部スクロール廃止）
  ③`openMemo` で `#memo-editor.scrollTop = 0` を明示。
  カーソルは従来どおり末尾に置く（続きが書ける）。`focus({preventScroll:true})` は
  2026-07-30の盤面上ずれ対策なので**外していない**
- 症状: Safari の `do JavaScript` が無言で失敗（結果が返らない）。
  原因未特定だが、`try{...}catch(e){"ERR:"+e.message}` で包むと原因が見えるので、
  以後の確認はこの形で実行するとよい
