# ポケモンカード図鑑（pokecard-dex）

日本語版のポケモンカードを、名前・番号・レアリティ・タイプで引ける図鑑。
自分専用（port 8531 / 127.0.0.1）。

## 入口は2つ（2026-08-19〜）

| 入口 | 開き方 | 備考 |
|---|---|---|
| **PSAカード管理の中** | http://127.0.0.1:8527 → サイドバー「📖 ポケモンカード図鑑」 | **普段はこちら**。図鑑のカードを「⭐ 欲しい」でアルバムに入れられる |
| 単独 | `./run.sh` → http://127.0.0.1:8531 | 従来どおり。launchd 常時起動（`com.shinsei.pokecard-dex`） |

**画面のコードは `app.py` の1本**で、両方の入口が同じものを呼ぶ。

    main()    … 単独起動用。set_page_config してから render()
    render(album_ui=None, title=…)  … 画面本体。PSAカード管理はこれを呼ぶ

- PSAカード管理は `app.py` をパス指定で読み込む（同名の `app.py` が両方にあるため
  import 文では取り違える。向こうは `pokecard_dex_app` という別名で登録している）
- `album_ui` はカード1枚ぶんの「⭐ 欲しい」ボタンを描く関数。**図鑑側はアルバムの
  実装（albums.json・cert番号）を知らない**。単独起動では None ＝ 何も出ない
- **DBに入っている画像パスは相対**（`data/myca_large/…`）。単独起動は run.sh が
  cd するので気づかないが、PSA側から呼ぶと cwd が変わって画像が1枚も出ない。
  `_p()` を通して図鑑フォルダ基準に直すこと。**画像パスを扱う箇所は必ず `_p()` を通す**

## どこから何を取っているか

4つのソースを、それぞれが唯一持っているもので使い分ける。どれか1つでは
日本語版の図鑑として成り立たない。

| ソース | 担当 | 備考 |
|---|---|---|
| **DMMマイカ** | カードの存在・番号・レアリティ・収録パック・**画像**・発売日 | 骨格。ここだけがレアリティを持つ |
| **TCGdex** | ワザ・HP・タイプ・弱点・にげる・効果文 | 日本語版のレアリティ区分は持たない |
| **公式サイト** | セット名・商品分類（拡張パック/構築デッキ/その他）・パック表紙 | レアリティは非公開 |
| 公式カード画像 | 高画質（360px）だが番号と紐づかない | 補助のみ |
| learn-book.com | eシリーズ・PCG4/9・1996年第1弾の**カード画像** | 最後の手段（`learnbook.py`）。上の3つに存在しない年代だけ |

## 実行の順番

    python crawl_myca_cards.py     # 全カード（ID巡回・約9時間）
    python fetch_myca_large.py     # 400px画像
    python make_thumbs.py          # 一覧用サムネイル（180px）
    python fetch_release_dates.py  # パックごとの発売日
    python build_dex.py            # 図鑑テーブルを組み立て
    python check_dex.py --packs    # 整合性の検査

`./finish.sh` はこれを一連で流す（巡回の完走を待って後続を実行）。

## 実測で分かった、はまりやすい点

**マイカのカード単体ページが唯一の全カード情報源。**
一覧ページと内部API（`/api/ec/item`）は販売中のカードしか返さない。
ハナダシティジム カスミで比べると 一覧5枚 → API 9枚 → 単体ページ25枚。
`/pokemon-trading-card-game/items/single-card/<ID>` は出品ゼロでも開く。

**IDの刻みは時代で変わる。** 10万未満は10刻み、以降は5刻み。全部5刻みで
辿ると古い側が空振りだらけ（1.2%しか当たらない）、全部10刻みだと新しい側を
半分落とす（冷酷の反逆者が59枚→29枚）。境界は8万から5刻みに切り替える。

**タイトルの形式は8通りある。** パーサ（`crawl_myca_cards.py` の `parse`）は
次を全部受ける。新しい形式が来たら `status='unparsed'` として記録されるので、
欠番と混ざらず気づける。

    アメモース （ストームエメラルダ / M6 003/076 C）          番号あり
    ベトベトンex （…天空の覇者 / ☆）                        レアリティのみ
    基本草エネルギー （アルセウス光臨 / Pt4 -）                 セット記号のみ
    基本水エネルギー （25th ANNIVERSARY COLLECTION / s8a WAT） エネルギー種別
    ヒコザル （秘境の叫び / DP5 DPBP#180 ★）                DP期の管理番号
    ペパー （プロモカードパック第9弾 / SV-P 238/SV-P PROMO）    プロモ
    博士の研究（ナナカマド博士） （スターバース / s9 095/100 R）    カード名に括弧
    マリィ （エクストラバトルの日 2022版（2回目）参加賞 / …）      パック名に括弧

**そのパックの正しい枚数は「カード番号の最大値」で分かる。** 総数（「034/054」
の054）は公式ナンバリングの枚数で、特別枠（AR/SR/SAR）を含まない。冷酷の
反逆者は total=54 でも実際は59枚。アプリ版マイカの表示と一致することを確認済み。
判明したものは `data/pack_truth.json` に記録して照合に使う。

**画像は拡張子で解像度が変わる。** 同じCDNで `.gif`＝180px、`.jpg`＝400px。
公式（360px）より大きく、1998年の旧裏面カードにも存在する。

**発売日はマイカのカードページに埋まっている**（JSONの `release_date`）。
公式サイトに商品ページが無い古いパックでも判る（ポケモンジム第1弾 =
1998-04-26）。パックごとに1枚開けば足りる。

**公式の商品名とマイカのパック名は揺れる。** 自動照合（正規化・接頭辞除去・
前方/後方一致）で拾えないものは `data/product_alias.json` に手で書く。
`@20th` のようにセット記号で指定もできる（同名で別時代のパックを区別するため。
「はじめてセット」は HS 57枚(通常)と HXY 51枚(forガール)に分かれている）。

### learn-book.com からの補完（2026-08-13）

公式・マイカ・TCGdex のどこにも画像が無いと確定した年代だけ、
learn-book.com のカードリストから補う（`learnbook.py`）。画像には
`alt` にカード名、ファイル名に番号が入る（`e1087.jpg` = E1の087番）。

**照合の決まり（絵の取り違えを防ぐため）**

1. まず**名前**で照合する。dex 側にもページ側にも同名が1枚しか無いものだけ
2. **番号は、そのセットで信用できると確かめてからでないと使わない。**
   名前で当たった組のうち番号を持つものが3組以上あり、1組も食い違わなければ
   採用する（E1は5/5、E3は7/7で一致した）
3. 自動判定できないものは `VERIFIED_NUMBERING` に手で書く。根拠もそこに書く
4. **番号は、そのページの主役のセットのファイルからしか読まない**（後述）

**⚠️ 番号は末尾3桁だけで読んではいけない（2026-08-14に事故）**

ページには「当たりカード」等で**別セットの画像が混ざる**。e01 のページにあった
★neo第4弾の `neo4098.jpg`（ヨルノズク）が `e1098` と同じ「098」に化けて、

- **E1-098（バタフリー）にヨルノズクの絵が入った**
- 番号が重複した 47 / 68 / 80 / 82 / 84 は「曖昧」として捨てられ、ページに
  `e1068.jpg`（ラフレシア）があるのに未収録のまま残った

`fetch_page()` はファイル名の接頭辞（`e1` / `neo1` / `1st1s` …）を数え、
**最も多い接頭辞のものだけ番号を持たせる**。それ以外は番号を None にして
名前照合に回す（neo01-deck の基本エネルギー `1st1s001` は接頭辞が違っても
名前で当たるので、捨てるのではなく番号だけ落とす）。

**「取得元に無い」と結論づける前に、ページに載っていないかを名前でも確かめること。**
上の件は番号でしか確認しておらず、その番号が壊れていた。

**この年代は dex 側のカード名が壊れている**（要注意）。TCGdex の日本語データが
英語や誤訳のまま入っており、E1の1番は "Koffing"（正: ドガース）、5番は
"奇妙な"（Oddish＝ナゾノクサ）、71番は "カリザード"（リザードン）。
そのため名前照合はほとんど当たらず、番号照合が主になる。PCG9 は
"Snorlax"=カビゴン、"quagsire"=ヌオー のように**全て同じポケモンの誤訳**で、
自動判定では「食い違い53件」と出るが番号は完全に一致していた。英日の対応表を
持っていないのでこの判断は自動化できず、`VERIFIED_NUMBERING` で明示している。

取得した画像は `data/learnbook/` に置き、dex の **`img_web`** 列に入れる。
公式画像（`img_off`）やマイカ画像（`img`）とは列を分けてあり、表示の優先順位も
公式 → マイカ → learn-book の順。図鑑の詳細画面には出所を明記する。

1996年の第1弾は「スターターパック」と「拡張パック」で102枚の同じ札を分け合って
おり、learn-book も `pmcg01` と `pmcg01-deck` の2ページで**同じ画像ファイルを
使い回している**（どちらも `1st1003.jpg` = フシギバナ）。そのため両ページを両方の
グループに当てている。`learnbook` テーブルの主キーが URL だと1枚の画像が2つの
dex 行に対応できないので、主キーは `dex_key`。

**パック名だけで引いてはいけない。**「スターターパック」は1996年（96枚・
set_code なし）と2016年の 20th（84枚・画像あり）にあり、`set_code IS NULL AND
pack_name = ?` で引く。なお dex の「スターターパック」96枚は中身がチコリータ・
レディバ・イトマルで**金銀（第2世代）の別商品**＝1999年「ポケモンカード★neo
スターターパック」であり、1996年のページを当てるのは誤り。正しい対応は
`neo01-deck`（2026-08-14に96枚すべて収録済み）。

**ページ側の表記ゆれは `ALIAS` で解決する（2026-08-14）。** `neo01-deck` は
名前照合が96枚中93枚しか当たらなかった。原因はページ側の略記・注記で、
`ALIAS[slug][ページの表記] = dex の表記` に3件だけ書いて解決している
（「新ポケモン図鑑」→「新ポケモン図鑑HANDY808」、「悪／鋼エネルギー（初期シリーズ）」）。

同じカードだと**確かめてから**書くこと。このときの確認手順:

1. ファイル名 `neo1001`〜`neo1096` の順と dex 96行を key 順で突き合わせ、
   **96対96で1対1・位置のずれ0件**（うち93件は名前も完全一致）であることを見る
2. 残り3件の画像を実際に開き、印字されたカード名が dex と一致することを見る

注記「（初期シリーズ）」を**一律に落とす実装にはしない**。同じ注記が付く基本
エネルギー6枚（草炎水雷超闘）はファイル名が `1st1s001`〜`006` ＝ 第1弾の絵で、
dex のこの96行には含まれない。一律に落とすと巻き込む。

**画像の枚数を数える箇所には `img_web` を必ず入れる。** `check_dex.py` の
`check_set()` が `img` / `img_off` / `image_tcgdex` しか見ておらず、
「画像欠落745枚」と実際より多く出ていた（正しくは145枚。2026-08-14に修正）。
`learnbook.py` の `group_rows()` も同じ抜けで、埋め済みの行が毎回「未取得」に
見えて実行のたびに全ページを取り直していた（同日修正）。
列を1つ足すと、数える場所・挿入する場所すべてに配る必要がある。

### デッキ商品のエネルギー（2026-08-14）

マイカはデッキ商品の**エネルギーだけ**画像も番号も持っていない（同じ商品の
ポケモン・トレーナーには画像がある）。dex では `set_code` が NULL の行になる。
102枚あり、うち99枚を learn-book から補った。

**対応づけはページの title（＝商品名）で行う。スラッグの番号は当てにならない。**
`pcg07-deck` は「ロケット団ハーフデッキW -silver-」であって、マイカ PCG-7 の
レックウザデッキ（`pcg05-deck`）ではない。

商品のページが learn-book に無いものは、**同じシリーズの別商品のページから絵を
借りる**（`PAGES` の後半）。エネルギーの絵はシリーズ単位で共通なので成立する。
借り先は `myca_card.release` の**発売日**で決める。名前で決めてはいけない
——「映画公開記念VSパック」は名前に VS とあるが ADV-9（2003年）で ADVシリーズ。

借り先ページのポケモンやトレーナーが誤って当たらないのは、対象グループ
（`set_code IS NULL AND pack_name = ?`）が**エネルギーだけ**だから。
新しい商品を足すときは、そのグループの全行を目で確認すること。

⚠️ **得られるのはシリーズ共通の絵で、その商品の実物の刷りではない。**
learn-book が画像を商品をまたいで使い回しているため（`pcg02-deck` の中でも
`pcgs07en1` と `pcgs08en2` が混在）。実測でも、2004年の商品の基本炎エネルギーに
©2006 の絵が入った。図鑑の用途として許容する判断（2026-08-14・ユーザー承認済み）。

エネルギーの表記ゆれ（ページ「炎エネルギー（PCGシリーズ）」／dex「基本炎エネルギー」）は
`energy_key()` で寄せる＝末尾の（…）と先頭の 基本／特殊 を落として同じ鍵にする。
**書き換え先はそのグループの dex に実在する名前だけ**なので、商品ごとに ALIAS を
並べる必要はない。

1商品に複数ページを当てるときは `claimed`（この実行で埋めた `dex_key`）が要る。
`dex.img_web` を書くのは `build_dex.py` なので、`learnbook.py` の実行中は
dex がまだ空のまま見え、同じ行を複数ページが奪い合って後勝ちになる。

### 取得元の一覧と優先順位（2026-08-14 時点の実測）

| 取得元 | 寸法 | 透かし | 使いどころ |
|---|---|---|---|
| **カードラッシュ** | **868×1212** | 無し | M-P など他に無い分（`cardrush.py`） |
| 晴れる屋2 | 852×1200〜1288×1805 | **うっすら HARERUYA** | 最後の手段（`extra_images.py`） |
| pcg-search | 593×834 | 無し | eシリーズ全部（`pcgsearch.py`） |
| スニダン | 430×610 | 無し | 背景除去。切り抜きが要る（`snkrdunk.py`） |
| learn-book | 356×500 | 無し | 旧年代のデッキ商品など（`learnbook.py`） |
| 遊々亭 | 500×700 | **斜めに「カードショップ 遊々亭」** | 控え。URLが規則的で機械的に拾える |
| フルアヘッド | 287×400 | **中央に COPY** | **使わない**（画質が最下位） |

**遊々亭（yuyu-tei.jp）のURL規則**（2026-08-14に確認。透かしはあるが機械的に拾える）

    一覧    https://yuyu-tei.jp/sell/poc/card/<セット>/<番号>
    原寸    https://card.yuyu-tei.jp/poc/front/mpromo-100/10079.jpg
    一覧の alt が「 079/M-P PROMO ふしぎなアメ 」＝**番号がそのまま入る**

セット名も `mpromo-100` / `svpromo-100,200,300` / `spromo-100,200,300` と規則的。
Cloudflare も無く curl で通る。M-P 079 ふしぎなアメで比べたところ
**晴れる屋2（852×1200・透かし薄）のほうが良かったので採用は見送った**。

`build_dex.py` の `_add_web_table()` を**画質の良い順に呼ぶ**。各更新に
**`img_web IS NULL` を必ず入れる**こと。入れ忘れると後から呼んだ低画質が
上書きする（実際 `add_learnbook()` がそうなっていて2026-08-14に修正）。

⚠️ **透かし入りは2枚だけ**（XY-P スーパーボール／M-P 079 ふしぎなアメ）。
透かし無しが見つかったら差し替える。該当は
`SELECT dex_key FROM extra_images WHERE source='hareruya2'`。

### Cloudflare で弾かれるサイトの読み方（2026-08-14）

カードラッシュ（cardrush-pokemon.jp）とドラスタ（dorasuta.jp）は
**機械的なアクセスを HTTP 403 で弾く**。curl も WebFetch も、UA やヘッダを
揃えても通らない。

→ **Safari を AppleScript で動かして読む**（`cardrush.py` の `safari_js()`）。
psa-collection の `harvest_collectors.js` と同じ手口。前提は
Safari の「開発 > Apple Events からの JavaScript を許可」がON。

**ただし画像そのものは素通しで curl で落ちる**
（`/data/cardrushpokemon/product/*.jpg`）。守られているのは HTMLページだけなので、
Safari を使うのは「商品ページ → og:image のURL」を読む部分だけでよい。
晴れる屋2（hareruya2.com）はそもそも curl で通る。

※ Claude in Chrome も試したが、**このMacに Chrome が入っていない**ので使えない。

### スニダン（snkrdunk.com）— learn-book にも無い分の取得元（2026-08-14）

`snkrdunk.py`。learn-book は eシリーズのページに一部の番号を載せていない
（E4 069 グランブル等）。フリマ系を当たったところ**スニダンが一番いい画像**だった。

| 取得元 | E4-069 で実測 |
|---|---|
| **スニダン** | **1000×730（切り抜き後 430×610）・透かし無し・背景透明** |
| フルアヘッド | 287×400・中央に「COPY」の透かし |
| learn-book | そもそも 069 が無い |

- **公開API**（認証不要）: `GET https://snkrdunk.com/v1/apparels/<id>`。
  `productNumber` が `pkmn-tcg-e4-069` ＝ **セット記号と番号そのまま**なので、
  dex への対応づけに名前の突き合わせが要らない
- 画像は `upload_bg_removed` ＝ 背景がアルファで抜けている。
  **アルファの外接矩形で切り抜く**（`crop_card()`）
- **商品IDは連番だが、1枚につき 1ED版と通常版の2つ**があり、服・靴も同じ連番に
  混ざる。番号との一対一対応にはならないので `--scan` で範囲を走査して
  `productNumber` で拾い、**確かめてから `WANT` に書く**。
  実測の位置: e3≒429900 / e4≒430070〜430195。**eシリーズのID帯は連続していない**
- 検索APIは見つけられなかった（`/v1/apparels/search` は存在するが引数不明。
  keyword / q / word / text / name / productNumber すべて bad_input）。
  サイト内検索ページは Next.js のクライアント描画で HTML に結果が出ない
- キラ版は別商品になっていない（E4 071 はあるが 072 が無い）。
  そこは `add_twin_images()` が相方から埋める

**控え: フルアヘッド（pokemon-card-fullahead.com）**。品番 `PK-E4-069` 形式で
`/shopbrand/<セット>/page<N>/recommend/` のカテゴリ一覧から全件拾える
（HTMLは EUC-JP、`<img alt="PK-E4-001 ズバット ●">` に品番が入る）。
透かしが入るので画像としては次点だが、**商品名が正確なので dex の壊れた名前の
答え合わせに使える**（73「ヤミカラス」＝dex "マークロウ"、79「預言者」＝"オラクル"、
84「ミステリープレートβ」＝"b"、89「ゴローニャ」＝"ゴーレム"）。

### 同じカードの別の行から絵を借りる（2026-08-14）

**外に取りに行く前に、dex の中に同じカードの別の行が無いかを見ること。**
2026-08-14 はこれだけで **127枚**（M2a 10 ＋ eシリーズ2枚組 96 ＋ 1996年第1弾 9
＋ 記号違い 12）埋まった。外部から取った 260枚に次ぐ量になる。

`build_dex.py` に4つ入れた。いずれも「候補がちょうど1件のときだけ採る」。

**`add_dual_code_twins()` … 同じセットが2記号に割れている分 12枚**
TCGdex とマイカでセット記号が違い、同じカードが2行に分かれて片方にしか
画像が無いことがある。

    tcg/SM1p-059   set_code=SM1p   59番 UR ジュナイパーGX   画像なし
    SM1p/SM1p_059  set_code=sm1+   59番 HR ジュナイパーGX   画像あり ← 同じカード

レアリティが UR / HR と割れるのは出所の違い。**カード名・番号・総数の3つが一致**
するものだけ採る。これで「SM1p・SM2p は公式に画像があるが同名2件（通常GXとSR）で
確定できない」という積み残しが解消した（52番SR と 59番UR は番号で区別できる）。

**`add_error_variants()` … 「（表面加工エラー）」10枚**
マイカは印刷エラー品を別商品として出品するので `メガリザードンXex（表面加工エラー）`
のような行ができる。個体の不良でカードの種類ではないから絵は通常版と同じ。
表面加工のエラーなので対象は加工が特別な枠に限られ、実際 M2a のエラー品10枚は
**MA レアリティの223〜232番ちょうど10枚と1対1で一致**した。
**名前だけで引いてはいけない** ——メガカイリューex は MA 232 / SAR 246 / MUR 250 の
3種類あり、別の絵を出す。実装は `rarity='MA'` で絞っている。

**`add_twin_images()` … eシリーズの2枚組 89枚**
eシリーズは同じカードが「キラ版」と「通常版」の2枚組で収録されている（HP・ワザまで
完全一致）。learn-book は**この2枚に同じ写真1枚**を使っており（e02 の
「（キラカード）一覧」が通常一覧と同じ `e2004.jpg` を出す）、片割れの番号は
ページに載っていない。そこで相方の `img_web` をそのまま入れる。

- **番号の隣り合わせでは決められない。** キラが先の組（E3 70キラ/71通常）と
  後の組（E3 72通常/73キラ）が混在する
- 相方は**カード名（`-004/092` の接尾辞を落とす）＋HP＋ワザの完全一致**で探す
- 名前で決まらないときだけ HP＋ワザで引き直す（E2 は48番 "nidooking" ／
  49番 "ニドギング" が同じカード＝名前が壊れている）。ただし **HP が無い行は対象外**。
  ワザが空のトレーナーが全部同じ鍵になり候補が10件並ぶ
- 借りた絵はキラ加工の有無までは再現していない

`ds` はドラゴンセレクション、`m2a` は MEGAドリームex で、いずれも別のもの。

### 画像の紐づけ（2026-08-13〜14）

**公式画像を引く鍵はセット記号を小文字に潰すこと。** 公式 `SMP1` ／ マイカ `smP1`
のように大小が違い、そのままだと突き合わせが丸ごと空振りする（イワンコ全力デッキ
13枚が全滅していた）。`canon_codes()` はマイカ内の表記ゆれしか見ないのでここでは
効かない。→ `official_index()` / `_low()`

**`img_off` を埋め忘れている経路が無いか確認すること。** dex に行を入れる関数は
3つあり（`build_cards` / `add_myca_cards` / `add_tcgdex_only`）、後ろの2つは
どちらも画像欄を `None` で埋めたままになっていた。合計290枚が、**既にディスクに
ある画像を指さないまま**「画像なし」として数えられていた。

マイカに画像が無いカードでも、**TCGdex のカード記録に付いている公式画像**
（`cards.local_file`。ingest 時に取得済み）があれば `img_off` に入れる。
`add_tcgdex_only()` がここを常に None で埋めていたため、既にディスクにある
251枚が表示されていなかった（SM1p〜SM5p のサブパックが中心）。公式サイトに
同じセット・同名が1枚だけある場合も拾う（+16枚）。

番号での照合はしない。TCGdex の `local_id` と公式の印字番号は割り当てが違い
（M-P はマイカ72番=ジェット／TCGdex72番=ジーランス）、別のカードの絵になる。
名前だけで当てた結合・同名が複数ある場合も使わない（M6のギリーは068番Uと
101番SRで絵が違う）。この判断は official テーブル経由と揃えてある。

## もう使っていないもの

※ `read_official.py` は「公式の高画質画像を正しい番号に紐づけたいとき」に使う。
SM1p 5枚・SM2p 6枚は公式に画像があるのに同名2件（通常GXとSR）で確定できず
保留になっており、これを流せば繋がる見込み。

`fill_rarity_ai.py` / `read_official.py` / `verify_rarity.py` は、公式サイトが
レアリティを公開していないため**カード画像の隅をAIに読ませて**補う試み。
20枚テストで100%読めたが（SR/MA/SARまで正確）、マイカから文字データとして
取れることが分かったので不要になった。番号が印字されていない時代（旧裏面・
ADV期・DP期）は読めないという限界もある。公式の高画質画像を正しい番号に
紐づけたくなったときだけ再利用する。
