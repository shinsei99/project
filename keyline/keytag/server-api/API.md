# KeyTag サーバー連携 API 仕様

KeyTag は鍵の台帳を **端末の中だけ**で持つのが既定です。サーバーは要りません。

そのうえで「複数人で同じ台帳を見たい」場合に限り、**自分のサーバー**へ繋げます。
接続先はアプリの「設定 > サーバー連携」で入力する方式なので、
**この仕様どおりのサーバーを立てれば、誰でも自分の環境で使えます。**

同じフォルダの **`keytag-server.py`** が、この仕様どおりに動く参照実装です
（標準ライブラリだけ・1ファイル・`python3 keytag-server.py` で起動）。

---

## 全体の流れ

```
① ペアリング   アプリに「サーバーURL」と「6桁コード」を入れる
                 → POST /api/pair        → Bearer トークンを受け取る

② 鍵を登録     アプリで「タグに書き込む」を押す
                 → POST /api/register    → サーバーが URL を発行
                 → その URL を NFC タグに書き込む

③ かざす       タグをかざす（URL から token を取り出す）
                 → GET  /api/asset       → いま誰が借りているかが返る

④ 貸出／返却   → POST /api/checkout ／ POST /api/return
```

- 認証は **`Authorization: Bearer <トークン>`** ヘッダのみ（`/api/pair` を除く）
- 本文・応答とも **JSON**（UTF-8）
- 応答は必ず **`{"ok": true, …}` または `{"ok": false, "error": "…"}`**
- **`ok:false` の `error` はそのまま画面に出ます。** 利用者に見せてよい日本語で返してください
- アプリは WebView から呼ぶので **CORS を許可**してください
  （`Access-Control-Allow-Origin: *` と `Allow-Headers: Authorization, Content-Type`、`OPTIONS` への応答）

**サーバーに繋がらないときは、アプリが自動で端末内の台帳に切り替えます。**
現場を止めないための作りなので、サーバー側は落ちても壊れません。

---

## タグに書く URL の形

```
https://<あなたのサーバー>/t/<token>
```

`token` は `[a-z0-9]{8,32}`。アプリはこの形にだけ反応します
（それ以外の URL が書かれたタグは「ただのURL」として扱われます）。

**この URL はブラウザで開いても意味のあるページを返してください。**
アプリを入れていない人がタグをかざしたときに、鍵の状態が読めるようにするためです。

## エンドポイント

### 1. `POST /api/pair` — 端末をつなぐ

6桁コードを Bearer トークンに引き換えます。**認証不要**（これだけ）。

| | |
|---|---|
| 要求 | `{"code": "123456"}` |
| 応答 | `{"ok": true, "token": "…", "organization": "サンプル商事"}` |
| 失敗 | `{"ok": false, "error": "コードが違います"}` |

- `organization` はアプリの設定画面に「✅ ◯◯ と連携中」と表示されます
- コードは**使い切り・有効期限つき**にしてください（参照実装は30分）

### 2. `GET /api/ping` — つながっているか確かめる

| | |
|---|---|
| 応答 | `{"ok": true, "organization": "サンプル商事", "user": "デモ端末"}` |

アプリの「接続を確認」ボタンが呼びます。

### 3. `POST /api/register` — 鍵を1件登録し、タグに書く URL を返す

アプリが「タグに書き込む」の**直前**に呼びます。

| | |
|---|---|
| 要求 | `{"property_name":"サンプルマンション", "name":"101号室 玄関", "box_position":"A-3", "item_number":["10001","10003"], "item_qty":["1","3"]}` |
| 応答 | `{"ok": true, "url": "https://…/t/16988f8dc0f55215"}` |

- `item_number` と `item_qty` は**同じ長さの配列**（鍵番号ごとの本数）
- 応答に `url` が無い場合、アプリは**サーバー無しの内容だけ**をタグに書きます（失敗しても書き込みは続行）

### 4. `GET /api/asset?token=<token>` — かざした鍵の状態

| | |
|---|---|
| 応答（登録あり） | `{"ok": true, "found": true, "asset": {…}, "borrowers": [...], "dues": [...]}` |
| 応答（登録なし） | `{"ok": true, "found": false}` |

**`asset`**（そのまま画面に出ます）

| キー | 例 | 意味 |
|---|---|---|
| `property_name` | `サンプルマンション` | 物件名 |
| `name` | `101号室 玄関` | 鍵の名称 |
| `label` | `サンプルマンション / 101号室 玄関` | 一覧用の表示名 |
| `item_numbers` | `10001 / 10003 ×3` | 鍵番号（表示用の文字列） |
| `total_keys` | `4` | 合計本数。**2本以上だと返却時に本数確認を促す** |
| `box` / `box_name` | `A-3` / `` | 保管場所 |
| `status` | `in_stock` \| `checked_out` | 状態 |
| `status_label` | `保管中` \| `貸出中` | 画面に出す文字 |
| `borrower` | `{"name","company","kind","phone"}` または `null` | 貸出中のときだけ |
| `checked_out_at` / `due_at` | `2026/08/28 09:25` | **整形済みの文字列**（ISOではない） |
| `elapsed` | `2時間15分` | 貸出からの経過 |
| `is_overdue` | `true` / `false` | 返却期限超過 |

**`borrowers`** — 貸出先の候補。`[{"id","name","company","kind","open_count"}]`。
`open_count` は「その人がいま借りている件数」。よく使う人を上に並べてください。

**`dues`** — 返却予定の選択肢。`[{"label":"今日 18:00","value":"2026-08-28T18:00:00+09:00"}]`。
**サーバー側で作る**ので、会社の運用（当日返却が基本、など）に合わせて変えられます。

### 5. `POST /api/checkout` — 貸出

| | |
|---|---|
| 要求 | `{"token":"…", "borrower_id":"B1234", "new_name":"", "new_kind":"vendor", "new_company":"", "new_phone":"", "due_at":"2026-08-28T18:00:00+09:00"}` |
| 応答 | `{"ok": true, "asset": {…}}` |
| 失敗 | `{"ok": false, "error": "この鍵はすでに貸出中です"}` |

- **`borrower_id` が空なら `new_name` で新しい貸出先を作ります**（どちらか必須）
- `new_kind` は `vendor` / `customer` / `employee` / `other`
- **二重貸出はサーバー側で止めてください。** 2台の端末が同時に押しても壊れないようにするためです

### 6. `POST /api/return` — 返却

| | |
|---|---|
| 要求 | `{"token": "…"}` |
| 応答 | `{"ok": true, "asset": {…}}` |
| 失敗 | `{"ok": false, "error": "この鍵は貸出中ではありません"}` |

返却後、アプリは `GET /api/asset` を呼び直して貸出先の候補を取り直します。

## 参照実装を動かす

```bash
python3 keytag-server.py
# ─────────────────────────────────────────
#  サーバーURL     : http://192.168.1.20:8765
#  ペアリングコード : 090190   （30分で失効）
#  台帳を見る       : http://192.168.1.20:8765/
# ─────────────────────────────────────────
```

1. iPhone とサーバーを**同じネットワーク**に置く
2. アプリの「設定 > サーバー連携」に **URL** と **6桁コード**を入れて［連携する］
3. 「タグに書き込む」で鍵を作る → タグにサーバーの URL が書かれる
4. かざす → 貸出・返却が**サーバー側**に記録される
5. ブラウザで `http://<サーバー>/` を開くと、**台帳が一覧で見える**
   （別の端末からかざしても同じ内容になります）

**参照実装は社内LAN・VPN の内側で動かしてください。** 認証は最小限です。
インターネットに出す場合は HTTPS と、組織に合わせた認証を足してください。
