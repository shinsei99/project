### 発生したエラーと解決策

- **症状**: 生成した全31ファイルの末尾に `</content>` などのタグが混入し、
  `pip install -r requirements.txt` が `Invalid requirement: '</content>'` で失敗
  → **原因**: ファイル書き出し時の余分な行
  → **直し方**: 全ファイルの末尾から該当行を除去するワンライナーで一括修正
- **症状**: Gemini が `404 models/gemini-2.0-flash is no longer available`
  → **原因**: モデル提供終了（キーは有効。認証エラーではない）
  → **直し方**: 既定を `gemini-3.5-flash` に更新。使えるモデルは `client.models.list()` で確認
- **症状**: 旧SDK `google-generativeai` が「提供終了」の警告を出す
  → **原因**: パッケージ自体が廃止。madori-tracer は既に新SDK `google-genai` を使っていた
  → **直し方**: `google-genai` へ全面移行（アンインストール済み）。呼び方は `genai.Client(...).models.generate_content(...)`
- **症状**: リサーチャーがGeminiで「JSONを解釈できませんでした」→ claude CLI へフォールバック（遅い）
  → **原因**: **Gemini 3.x は「思考」にも出力トークンを消費する**。長いプロンプトで
    `max_output_tokens=4000` だと思考で使い切り、本文が空か途中で切れる
  → **直し方**: JSONを求めるときは `response_mime_type="application/json"`（ネイティブJSONモード）＋
    出力枠を3倍（最低8000）に拡大。**実測 18秒で失敗 → 14.5秒で成功**に改善
- **症状**: Gemini画像生成のテストが5分以上ハング
  → **原因**: `google-genai` はタイムアウト未指定だと待ち続ける
  → **直し方**: `types.HttpOptions(timeout=ミリ秒)` を指定（`AP_IMAGE_TIMEOUT`=300秒）。**1枚60秒**で生成成功
- **症状**: 出来たはずの mp4 が再生できない（`moov atom not found`）
  → **原因**: **書き出し途中だっただけ**。moviepy はヘッダ（moov atom）を最後に書く
  → **直し方**: 一時ファイル名で書いてから rename。完成品だけが最終パスに存在するようにした。
    あわせて moviepy の英語プログレスバーを日本語の進捗（10%刻み）に置き換え
- **症状**: 動画に音が無いように聞こえた
  → **原因**: **Mac本体がミュート**（音量63・muted:true）。ファイル側は正常（aac 128kbps）
  → **直し方**: `osascript -e 'set volume without output muted'` で解除。
    切り分けは `osascript -e 'get volume settings'` が速い
- **症状**: `ffmpeg not found`
  → **原因**: このMacにシステムFFmpegが未導入
  → **直し方**: `imageio-ffmpeg` の同梱バイナリを `IMAGEIO_FFMPEG_EXE` に設定して moviepy に使わせる
    （`agents/video_editor.py` の `_ensure_ffmpeg_env`）。それでも駄目なら `render.sh` を出力

### 発生したエラーと解決策（後半）

- **症状**: `pip install -r requirements.txt` が `Invalid requirement: '</content>'`
  → 生成ファイル末尾のタグ混入。全ファイルの末尾を掃除して解決
- **症状**: mp4 が `moov atom not found` で再生できない
  → 書き出し途中だっただけ。一時名で書いて rename する方式に変更
- **症状**: 一時ファイル名を `.mp4.part` にしたら
  `Unable to choose an output format` で失敗
  → **ffmpeg はファイル名の拡張子でコンテナを決める**。`.tmp_xxx.mp4` に修正
- **症状**: `mcp.json` に `_comment` を書いたら `Invalid MCP configuration`
  → MCP設定は厳密なJSONのみ。説明は `mcp.README.md` に分離
- **症状（重要・セキュリティ）**: 「`--allowedTools` に入れなければ Bash は使えない」と考えていたが、
  **実際には Bash が実行できた**（`echo TESTOK` が通る）
  → `--allowedTools` は**自動承認リストであって禁止リストではない**。
    禁止は `--disallowedTools` で明示する必要がある。
    既定で Bash/Write/Edit/NotebookEdit/Agent を禁止に設定済み
- **症状**: 動画部隊が「止まった」ように見える
  → **原因1**: 進捗カウンタを音声と映像で共用しており、音声が100%に達すると
    映像の進捗が一切表示されなくなっていた（バーごとに持つよう修正）
  → **原因2**: moviepy が Python 側で1フレームずつ合成していて、2分の動画に8分以上。
    **ffmpegに直接やらせる方式**に変更（1カット7〜11秒）。moviepyは逃げ道として残置
- **症状**: ffmpegの一時ファイルを `.mp4.part` にしたら出力形式を決められず失敗
  → 拡張子でコンテナを判定するため `.tmp_xxx.mp4` にする
- **症状**: `tools/flyer.py` で `int() argument 'width'` エラー
  → 用紙サイズの内部変数 `size` と、新規追加した引数 `size` が名前衝突。`paper_size` に改名
- **症状**: pytest が何分も返ってこない
  → 道具つき経路が本物の claude CLI を呼んでいた。
    `conftest.py` で `AP_AGENT_TOOLS=off` / `AP_ROUTE_TOOLS=none` / `AP_ALLOW_WEB=0` を強制

### 部隊の設計（後半で大きく変えた）

- **成果物の型（genre）を司令塔が決める**: signage / promo / deck / report。
  型が違えば作り方が根本から違うため、後続はこれに従う
- **1枚ものは1部隊が通しで作る**（`agents/poster.py`）。
  分業すると受け渡しで意図が壊れる。実際に「構成→画像→紙面」の3分業で
  **レイアウト指示がそのまま印刷された**。多ページ（パワポ・動画）は分業が有効
- **品質基準を全部隊で共有**（`core/design.py`）。
  Claude Code 単体と比較して負けた原因は「判断の基準を持っていなかった」こと。
  型を増やすのではなく基準を配る。**作る側と最終確認が同じ物差しを使う**
- **司令塔の最終確認**（`agents/acceptance.py`）。
  claude CLI は画像を読めるので、**出来上がった紙面を実際に見て**判定する。
  旧「テスト・QA部隊」はファイルの有無しか見ておらず、中身が壊れていても合格を出していたため廃止
- **自動リテイク**: 不合格なら指摘を制作部隊に渡して作り直す（既定1回・`AP_MAX_RETAKE`）
- **部隊の学習**（`core/memory.py`）: 最終確認の結果を `knowledge/lessons.json` に溜め、
  次から制作部隊のプロンプトに差し込む。**効いた点と避ける点の両方**を記録。
  モデルは変わらず、渡す申し送りが増える方式。人が読んで消せる（`lessons.md`）
- **素材**: 自動取得は Material Symbols(Apache-2.0) と Google Fonts(OFL) のみ。
  いらすとや・ソコスト等は**規約上、人が手で `assets/` に置く**。
  ぱくたそは自動収集禁止（違約金規定あり）のため候補から除外
