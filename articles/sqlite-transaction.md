鍵と備品の貸出を、NFCタグをかざすだけで記録する台帳を作っています。
貸出・返却の履歴が全部残るので、「誰がいつ持ち出したか」が後から追えます。

この台帳で、**同じ秒に2件入ると並び順が決まらない**という問題が出ました。

## 表示のたびに、前後が入れ替わる

```sql
SELECT * FROM checkouts ORDER BY checkout_at DESC;
```

同じデータを見ているのに、**実行するたびに2件の前後が入れ替わる**ことがありました。
どちらも `2026-08-24 09:15:32` で、**同じ秒**です。

SQLite に限らず、**並び替えの鍵が同じ値なら、その2件の順序は保証されません**。
たまたま安定して見えることはありますが、保証はされない。

## 精度を上げても、解決しない

最初に考えたのは「秒ではなくミリ秒で持てばいい」でした。**これは解決になりません。**

- ミリ秒でも、同じミリ秒に2件入ることはある
- マイクロ秒にしても同じ（確率が下がるだけ）
- しかも、鍵をかざす操作は**人が連続でやる**ので、実際に近い時刻が並ぶ

**「衝突しにくくする」のと「順序を決める」のは別の話**でした。

## 第2の鍵を足す

やったのは、**時刻が同じときに何で決めるか**を明示することです。

```sql
SELECT * FROM checkouts
ORDER BY checkout_at DESC, rowid DESC;
```

`rowid` は挿入順に増えるので、**同じ時刻なら後から入ったほうが後**と決まります。
これで並びが一意になりました。

一般化すると、**並び替えの鍵は、一意になるところまで足す**。
「たいてい重複しない」列で止めると、重複した日にだけ挙動が変わります。
そういう不具合は、再現しないので原因究明がとても面倒です。

## おまけ：スキーマ更新が途中で止まった

同じ台帳で、もう1つ踏みました。

スキーマの更新（マイグレーション）を、複数の文をまとめて流していました。

```python
conn.execute("BEGIN")
conn.executescript(sql)        # ← ここ
conn.execute("INSERT INTO migrations ...")
conn.commit()
```

`executescript()` は、**実行の前に暗黙的にコミットします**。
つまり、外側で開いた `BEGIN` は、この時点で確定されて消えます。

結果、スクリプトの途中で失敗すると、**そこまでが適用された状態で残ります**。
戻せません。マイグレーションでこれが起きると、手で直すしかなくなります。

直し方は、**トランザクションをスクリプトの文字列の中に書く**ことです。

```python
sql = """
BEGIN;
ALTER TABLE keys ADD COLUMN tag_uid TEXT;
CREATE INDEX idx_keys_tag ON keys(tag_uid);
INSERT INTO migrations(version, applied_at) VALUES (7, datetime('now'));
COMMIT;
"""
conn.executescript(sql)
```

**適用記録の INSERT も同じスクリプトに入れる**のが要点です。
別々にすると、「スキーマは変わったが、適用済みとして記録されていない」状態が起こり得ます。
次回の起動で同じ更新をもう一度流して、今度はエラーになります。

## ついでに：`datetime('now')` はUTC

これも同じ系統の話です。

```sql
INSERT INTO reports(created_at) VALUES (datetime('now'));
```

SQLite の `datetime('now')` は **UTC** を返します。
日報の生成時刻が「05:43」と表示されて、実際は14:43でした。

判断としては、**保存はUTCのまま、表示だけ +9時間**にしました。
既存の他のテーブルもUTCで揃っているので、**保存の側を変えると全部を移行する**ことになります。

`datetime('now', 'localtime')` もありますが、
**サーバーのタイムゾーンに依存する**ので、保存には使わないことにしています。

## まとめ

- 並び替えの鍵は、**一意になるところまで足す**（`rowid` を第2の鍵に）
- 時刻の**精度を上げても、順序の問題は解決しない**
- `executescript()` は**暗黙コミットする**。トランザクションは文字列の中に書く
- 適用記録は、**同じスクリプトの中で**残す
- `datetime('now')` は UTC。**保存を変えるか、表示を変えるか**を決めておく

台帳は「記録が残ること」が価値です。
その記録の**順序が保証されない**のは、記録が無いのと近い状態でした。
