駐車場の空き状況を、配置図の上に色で出すビューアを社内で動かしています。
区画をクリックすると契約者と賃料が出る、それだけの道具です。

ある日、画面で**空き**になっている区画へ案内したら、**車が停まっていました**。先月から契約済みでした。

図は毎日きれいに描かれています。エラーは一度も出ていません。
読んでいた元の表が、先月のものだっただけです。

## 何が起きていたか

空き状況は、共有フォルダに置いてあるレントロール（Excel）から毎回読んでいます。
パスは、こう書いてありました。

```python
DROPBOX_ROOT = "/Users/…/Dropbox-〇〇/共有フォルダ/物件・管理/"
XLSX_PARKING = DROPBOX_ROOT + "レントロール一覧（駐車場他）.xlsx"
```

ある時期に、共有フォルダ側で2つのことが起きていました。

1. 担当者が、更新が必要な表だと分かるように、**ファイル名の頭へ目印を付けた**（`★要更新★レントロール一覧（駐車場他）.xlsx`）
2. **置き場所も一つ上の階層へ移した**

新しいファイルは別の名前・別の場所にあり、**古いコピーは元の場所に残っていました**。
アプリは元のパスを読み続けます。ファイルは存在するので、例外は起きません。
中身が先月のものだというだけです。

## 「読めない」より「古いのを読む」ほうが厄介

ファイルが消えていれば、`FileNotFoundError` で落ちます。落ちれば気づきます。
このケースで最悪なのは、**古いファイルが同じ名前で同じ場所に残っている**ことです。

- 処理は成功する
- 画面は正常に描画される
- エラーログには何も出ない
- **中身だけが古い**

しかも古い答えは、新しい答えと**まったく同じ顔**で出てきます。
画面を見て「古いかどうか」を判断する手がかりが、どこにもありません。

## 共有フォルダのファイル名は、業務の都合で変わる

まず、名前を新しいほうへ追従させました。

```
parking-map: レントロールの参照先を「★要更新★」付きの新ファイル名へ追従

共有フォルダ側でファイル名と置き場所が変わっていたため、起動時に最新の
空き状況を読めなくなっていた。
```

これで動きます。ただし、**次に誰かが名前を変えれば同じことが起きます**。

共有フォルダで実際に付くものを並べると、こうです。

| 付くもの | 例 |
|---|---|
| 目印 | `★要更新★`、`（★必読★）`、`【最新】` |
| 同期の産物 | `〇〇 (競合コピー 2026-08-17)`、`〇〇 のコピー` |
| 版 | `_修正版2`、`_v3_final` |
| 見えない差 | 全角空白、結合文字（NFD/NFC）の違い |

これは行儀が悪いのではなく、**ファイル名が業務の伝達手段として使われている**ということです。
「★を付けるな」と言うより、機械の側を直したほうが早い。

## 名前で探すのをやめる

同じリポジトリの別のアプリ（社内マニュアルの生成）では、先にこの形にしてありました。
**置き場所の中を見て、手がかりの語を含むものを選ぶ**やり方です。

```python
def _R(base, *hints):
    """base直下から hints のいずれかを含むファイル/フォルダを探し、相対パスを返す。無ければ base"""
    d = os.path.join(ROOT, base)
    try:
        entries = sorted(os.listdir(d))
    except Exception:
        return base
    for h in hints:
        hn = _nfc(h)
        for e in entries:  # ディレクトリ優先（同名を含むファイルに吸われないように）
            if hn in _nfc(e) and os.path.isdir(os.path.join(d, e)):
                return base + "/" + e
        for e in entries:
            if hn in _nfc(e):
                return base + "/" + e
    return base
```

要点は3つです。

- **部分一致で探す**。頭に何が付いても、後ろに版番号が付いても当たる
- **NFCへ正規化してから比べる**。macOS のファイル名は濁点が分解された形（NFD）で返ることがあり、
  見た目が同じでも `==` では一致しない
- **ディレクトリを先に見る**。同じ語を含むファイルに吸われないようにする

候補が複数あるときは、**更新日がいちばん新しいものを採る**のが安全です。
「★が付いているほう」のような目印の解釈を、アプリ側に持ち込まないこと。目印は明日には変わります。

## 古い結果を出さない、いつの結果かを出す

名前の解決とあわせて、2つ足しました。

**① 読めなかったときに、前回の結果を出さない。**

以前は、読み込みに失敗したら前回の描画をそのまま出していました。白紙になるより親切だと思っていたからです。
これをやめて、区画を全部灰色にし「読めませんでした。現地で確かめてください」と出すようにしました。
不便ですが、**空きだと信じて現地に立つよりはよい**。

**② 結果に「いつの表から作ったか」を出す。**

```
この図は 2026-08-17 更新の表から作りました
```

一行あるだけで、見る人が気づけます。作った人ではなく、**使う人が気づけるところ**に出すのが肝心です。

## おまけ：常駐にすると、権限のほうでも同じことが起きる

このビューアは常駐させています。クラウド同期フォルダへのアクセス許可は、
常駐プロセスに対しては**あとから評価が変わることがあり**、権限エラーが続く状態に入ることがありました。

いまは、権限エラーが規定回数続いたら**自分で終了して起動し直させる**ようにしています。
無限に繰り返さないよう、再起動の回数には上限を付けました。

```python
def _handle_permission_error(e):
    global _perm_fail_count
    _perm_fail_count += 1
    if _perm_fail_count < MAX_PERM_FAILS:
        return
    if _should_self_restart():
        os._exit(1)   # 常駐の仕組み（KeepAlive）に起動し直させる
    else:
        print("再起動回数の上限に達したため見合わせます（要手動確認）", flush=True)
```

## まとめ

- 共有フォルダを**固定パスで読む処理は、いつか必ず古いデータを読む**
- 名前は業務の都合で変わる。**部分一致＋正規化＋更新日**で選ぶ
- 失敗したときに**前回の値を残さない**
- 結果に**いつの情報か**を書く

「動いていること」と「合っていること」は別です。
画面が毎日出ていることは、その中身が今日のものである証拠になりません。
