クリアファイル1冊をまとめてスキャンした巨大なPDFを、**書類1件ずつに分割・分類・リネーム**
する機能を作りました。

素直にLLMへ「どこからどこまでが1件か」を判定させると動きます。ただし、
**出力から静かにページが消えます。** そこの潰し方を書きます。

## 症状

判定結果はもっともらしく返ってきます。

```json
[
  {"start": 1,  "end": 4,  "type": "契約書"},
  {"start": 5,  "end": 9,  "type": "図面"},
  {"start": 11, "end": 14, "type": "請求書"}
]
```

よく見ると **10ページ目がどこにも入っていません。** 逆に範囲が重複することもあります。
分割PDFを出力すると、その1ページは**どのファイルにも入らず消えます。**

原本の紙は捨てられないとはいえ、**目録から1枚抜け落ちる**のは実務では致命的です。

## 原因

長いPDFを一度に判定させられないので、ウィンドウに区切って渡しています。
**境界付近で範囲がずれる**のが原因でした。

- ウィンドウの末尾で書類が切れると、次のウィンドウの先頭と噛み合わない
- ページ番号を「そのウィンドウの中での番号」と取り違える

つまり**LLM側の出力を正しいものとして扱う設計が間違い**です。

## 直し方：全ページが必ず1回だけ入るよう後処理で補正する

判定結果を信じず、**1〜Nの全ページが、どれか1件に、ちょうど1回だけ**入るように埋めます。

```python
def fill_gaps(items: list[dict], total: int) -> list[dict]:
    """AIが飛ばした/重複させたページを、必ず1回だけどこかに入るよう補正する"""
    items = sorted(items, key=lambda x: x["start"])
    fixed, cursor = [], 1
    for it in items:
        start = max(it["start"], cursor)
        end = max(it["end"], start)
        if start > cursor:                      # 飛んだページは前の書類に足す
            if fixed:
                fixed[-1]["end"] = start - 1
            else:
                fixed.append({"start": cursor, "end": start - 1, "type": "不明"})
        if start > end:                         # 重複は捨てる
            continue
        fixed.append({**it, "start": start, "end": end})
        cursor = end + 1
    if cursor <= total:                         # 末尾の取りこぼし
        fixed.append({"start": cursor, "end": total, "type": "不明"})
    return fixed
```

分類が多少ずれても、**ページが消えることは無くなります。**
「分類の精度」と「取りこぼさないこと」は別の要件で、**後者はコードで保証できます。**

## 設計：テキスト層の有無でモデルを変える

コストと精度の兼ね合いで、経路を2つに分けました。

| 入力 | モデル | ウィンドウ幅 |
|---|---|---|
| テキスト層があるPDF | 軽いモデル | 30ページ |
| スキャン画像（テキストなし） | 精度の高いモデル | 8ページ |

画像の方を細かく刻むのは、**1ページあたりのコストが高い**からです。

モデルの使い分けには理由があります。**画像経路で軽いモデルを使うと、
固有名詞を「それらしい別の語」に置き換える**現象を実測しました。
読み取れない文字を推測で埋めてしまうためで、書類名や氏名が絡む用途では許容できません。
**ここを削るとコストは下がりますが、使えない出力になります。**

書類がウィンドウを跨いだ場合は、次のウィンドウ側に「前からの継続」フラグを返させて結合します。

```json
{"continues_from_previous": true, "start": 1, "end": 3, "type": "図面"}
```

## おまけ：和暦は指示しないと西暦になりません

ファイル名の日付が「令和6年」と「2024」で混ざりました。**変換の指示を書いていなかった**
だけです。プロンプトに1行入れて解決しました。

```
日付は西暦の YYYY-MM-DD 形式で返すこと。和暦（令和/平成/昭和）は西暦に変換する。
```

LLMは「常識的にどちらでもよい」ものを揃えてはくれません。
**揃っていてほしいものは、揃え方まで書く**必要があります。

## まとめ

- LLMの区間出力は**そのまま使わない**。全体を覆うかどうかは後処理で保証する
- 「精度」と「取りこぼさないこと」を分けて考える。後者はコードの仕事
- 画像を読ませるときのモデル選定は、**固有名詞の扱い**で判断する
