他社の物件資料（マイソク）に自社の帯を付けて刷り直すツールを使っています。
出来上がったExcelを**印刷すると、写真が横に太って見える**。実測すると**横に1.2倍**伸びていました。

原因は2つありました。どちらも「Excelの座標系を、こちらが正しく理解していなかった」という話です。

## ① 列幅から長さへの換算が、2割ずれていた

openpyxl の列幅は、**標準フォントの「0」の文字幅を1とする単位**です。ポイントやピクセルではありません。

換算にこう書いていました。

```python
# 直す前：1文字 ≒ 7px という一般的な目安で計算していた
width_px = col_width * 7
```

この「7px」は環境によって変わります。うちの環境で実測したら**合っていませんでした**。
帯の幅を計算した値と、実際に印刷される幅が2割ずれます。

実機のExcelに測らせて、定数を置き直しました。

```python
_PT_PER_CHAR = 6.0      # 実測値。目安の数字ではなく、この環境で測った値
```

ここは「一般的にはこう」という数字を持ってきても合いません。**測るのが早い**です。

## ② アンカーの形式が、引き伸ばすものだった

より効いたのはこちらでした。openpyxl で画像を貼るとき、位置の指定（アンカー）には形式があります。

| 形式 | 挙動 |
|---|---|
| `TwoCellAnchor` | **始点セルと終点セル**で範囲を指定。セルの大きさが変わると**画像も伸縮する** |
| `OneCellAnchor` | **始点セル＋実寸**で指定。セルが変わっても**画像の大きさは変わらない** |
| `AbsoluteAnchor` | シート上の絶対座標＋実寸 |

こちらは `TwoCellAnchor` で貼っていました。
つまり、**画像は「この範囲に収まるように引き伸ばされる」**。列幅の計算が少しずれれば、
その分だけ画像が伸びます。縦横比は保たれません。

実寸で貼る形に変えました。

```python
from openpyxl.drawing.spreadsheet_drawing import OneCellAnchor, AnchorMarker
from openpyxl.drawing.xdr import XDRPositiveSize2D
from openpyxl.utils.units import pixels_to_EMU

img = Image(path)
w_emu = pixels_to_EMU(width_px)
h_emu = pixels_to_EMU(width_px / aspect)          # 縦横比はこちらで決める
img.anchor = OneCellAnchor(
    _from=AnchorMarker(col=0, colOff=0, row=start_row, rowOff=0),
    ext=XDRPositiveSize2D(w_emu, h_emu),
)
ws.add_image(img)
```

EMU（English Metric Unit）は Office 内部の長さの単位です。
ここまで落として指定すると、**セル側の都合に影響されません**。

実測はこうなりました。

```
帯の幅   1150.00 pt
画像の幅 1149.75 pt   （縦横比 0.8141 を維持）
```

## おまけ：スライダーの表示が、選んだ値と合わない

同じツールで、切り取り位置を微調整するスライダーがあります。
刻みを `0.005` にしたところ、**画面には `0.01` と出る**。値は正しいのに、表示だけ合っていません。

```python
# 直す前
st.slider("下カット位置", 0.0, 1.0, 0.88, step=0.005)
# 直したあと
st.slider("下カット位置", 0.0, 1.0, 0.88, step=0.005, format="%.3f")
```

Streamlit のスライダーは、表示の既定が**小数2桁**です。刻みを細かくしたら、表示の桁も一緒に見る。

数字がずれて見えるだけですが、**利用者は「効いていない」と判断します**。
実際、しばらく「このスライダーは動かない」と思われていました。

## 直せるのに、直していないものもある

最後に、直していない不具合の話を書きます。

帯に入れている免許番号が、**用紙が横向きのときだけ隣の欄へはみ出します**。
縦向きでは、文字を枠に合わせて縮める処理が通るので収まっています。

直し方は分かっています。同じ処理を、倍率1.0のときにも通せばよい。**それでも直していません。**

理由は、**これまで配ってきた帳票の見た目が変わるから**です。
このツールで作った資料は、すでに何十件も外に出ています。
同じ物件の資料を刷り直したときに、前と字の大きさが違うと「別物」に見えます。

直すなら、全部刷り直す前提で、時期を決めてやる。それまでは、**分かったうえで残す**。
記録にもそう書いてあります。

不具合には、**直すべきもの**と、**直し方が分かったうえで置いておくもの**があります。
後者は「放置」と紙一重なので、**理由を書いて残す**ことにしています。書いていなければ、ただの忘れ物です。
