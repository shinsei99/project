日本語の業務データを扱っていると、**見た目が同じなのに一致しない**という形の不具合が定期的に出ます。
うちで実際に踏んだ3つを挙げます。

## ① ハイフンに見える記号は、7種類ある

住所を町名と番地に分割する処理で、**特定の物件だけ失敗**していました。

```
（住所）… 1136−291     ← これが分割できない
（住所）… 1136-291     ← これは分割できる
```

区切りに使われていたのは **U+2212（MINUS SIGN）** でした。
こちらの正規表現には `-－ー‐` を入れていましたが、`−` が抜けていました。

日本語の入力欄で「ハイフンのつもり」で使われる文字は、少なくとも7種類あります。

| 文字 | コードポイント | 名前 |
|---|---|---|
| `-` | U+002D | HYPHEN-MINUS（半角） |
| `－` | U+FF0D | FULLWIDTH HYPHEN-MINUS |
| `−` | U+2212 | MINUS SIGN |
| `ー` | U+30FC | KATAKANA-HIRAGANA PROLONGED SOUND MARK（長音） |
| `‐` | U+2010 | HYPHEN |
| `–` | U+2013 | EN DASH |
| `—` | U+2014 | EM DASH |

**印刷しても区別がつきません。** 人が入力する欄では、全部混ざります。

```python
HYPHENS = "-－−ー‐–—"
_num = re.compile(rf"([0-9０-９]+)[{re.escape(HYPHENS)}]([0-9０-９]+)")
```

## ② 番号は、数字だけ取り出してから比べる

顧客台帳でFAX番号を検索しても、**相手が出てこない**ことがありました。

```
03-5555-0123
０３－５５５５－０１２３
(03)5555-0123
0355550123
```

全部同じ番号です。台帳には、入力した人の癖がそのまま入っています。

照合用の鍵を別に作りました。

```python
def tel_key(s: str) -> str:
    """数字だけ取り出す。全角は半角へ"""
    s = unicodedata.normalize("NFKC", s or "")
    return re.sub(r"\D", "", s)
```

`NFKC` 正規化は、全角英数を半角へ、半角カナを全角へ揃えてくれます。
**業務データの照合では、まずこれを通す**のが基本になりました。

氏名も同じで、姓名の間の空白（半角・全角・複数）を落としたものを鍵にしています。

```python
def name_key(s: str) -> str:
    return re.sub(r"[\s　]+", "", unicodedata.normalize("NFKC", s or ""))
```

**大事なのは、原本を書き換えないこと。** 表示は入力されたまま、比較は鍵で行います。

## ③ 濁点の持ち方が違う（NFD / NFC）

メールをローカルへ保管するツールで、**フォルダ名が一致しない**ことがありました。

```python
name = decode_imap_utf7(raw)     # デコードは正しい
name == "ポータル"                # → False
```

表示すると同じ「ポータル」です。しかし内部では違いました。

```
"ポ" = U+30DD                    （NFC：1文字）
"ポ" = U+30DB + U+309A           （NFD：ホ + 半濁点）
```

macOS のファイルシステムや、一部のIMAPサーバーは **NFD** で持ちます。
デコードが正しくても、比較で落ちます。

```python
def nfc(s: str) -> str:
    return unicodedata.normalize("NFC", s or "")
```

ここでも、**サーバー側の原本の名前は書き換えません**。
IMAP のフォルダ名は、こちらが勝手に正規化して送ると別のフォルダを指してしまいます。
**表示と比較のときだけ揃える。**

## 揃える対象と、揃えないもの

まとめると、こうなりました。

| 対象 | 揃え方 | 原本 |
|---|---|---|
| 住所の番地 | ハイフン7種を同一視 | そのまま |
| 電話・FAX・郵便番号 | NFKC → 数字だけ抽出 | そのまま |
| 氏名 | NFKC → 空白を除去 | そのまま |
| フォルダ名・ファイル名 | NFC | **そのまま（重要）** |

共通しているのは、**照合用の鍵を別に持ち、原本は触らない**ことです。

原本を正規化して保存してしまうと、

- 印刷したときに、入力された通りの表記でなくなる
- 外部システムへ渡すときに、向こうの原本と食い違う

という別の問題が出ます。**揃えるのは比較の瞬間だけ**にしています。

## 気づき方

この種の不具合は、**エラーが出ません**。「見つからない」「分割できない」という
静かな結果になるので、データが増えるほど気づきにくくなります。

うちでは、こう見ています。

- 照合率を数える（前の記事に書いた「一致率が黙って下がる」と同じ話です）
- 失敗したデータを**捨てずに残す**（あとで文字コードを確認できるように）

`repr()` して並べると、一発で分かります。

```python
>>> repr("1136−291")
"'1136\\u2212291'"
```

見た目で分からないものは、**バイト列で見る**しかありません。
