AIに一式を書かせたあと、`pip install -r requirements.txt` がこう落ちました。

```
ERROR: Invalid requirement: '</content>'
```

ファイルを開くと、**末尾に `</content>` が1行**入っていました。
調べると、**同じ形式で生成した31ファイルすべて**に付いていました。

## なぜ気づかなかったか

中身は正しいのです。

```
streamlit
openpyxl
pillow
</content>          ← これだけが余計
```

コードのファイルなら、末尾に1行増えても**目で読んで気づきにくい**。
`.py` なら構文エラーになりますが、`.md` や `.txt` や `.json` は
「末尾に妙な行がある」だけで、開いた印象は正常です。

見つかったきっかけが `pip` のエラーだったのは、たまたまでした。
**実際に使う経路を通したから**見つかった、とも言えます。

## 原因は、指示の書き方

生成の指示で、ファイルの中身を `<content>…</content>` で囲む形式を使っていました。
モデルが、閉じタグを**出力の一部として書いた**わけです。

対処は2つあります。

**① 出力の形式を、混ざらないものにする**

区切りをタグではなく、明確に本文と分離できる形式（JSONの1フィールドなど）にする。

**② 生成後に機械的に検査する**

こちらを入れました。生成物は、**そのまま使う前に検査する**。

```python
BAD_TAILS = ("</content>", "```", "---")

def check_generated(path: Path) -> list[str]:
    text = path.read_text(encoding="utf-8").rstrip()
    problems = []
    if text.endswith(BAD_TAILS):
        problems.append(f"{path}: 末尾に生成の痕跡がある")
    return problems
```

そして**実際に使う経路まで通す**。依存ファイルなら `pip install --dry-run`、
JSONなら読み込み、Pythonなら import。開いて眺めるだけでは足りません。

## 日報に、社内用の印が出た

似た形は、指示のほうでも起きました。

チャットの記録から日報を作らせています。社内では、発言の頭に `★` を付けて本人を示す慣習があります。
これを指示に書いていました。

```
★ が付いた発言は、その担当者本人の発言です。
```

出てきた日報に、こう書かれていました。

> 山田：進捗の報告なし（★発言0件）

**`★` の意味は伝えましたが、「本文に書くな」とは書いていませんでした。**

読ませるための情報は、そのまま**書いてよい情報として扱われます**。
指示を書くときは、この2つを分けるようにしました。

```
★ が付いた発言は、その担当者本人の発言です。
★ は社内の内部記号なので、**出力には一切含めないでください**。
```

「言わなくても分かる」は通りません。**読ませた記号は、書かれると思ったほうがいい**。

## 設定ファイルに注記を書いたら、壊れた

もう1つ、性質の近い話です。

外部連携の設定（`mcp.json`）に、後から読む人向けの説明を足しました。

```json
{
  "_comment": "このサーバーは社内のPDF検索に使う。停止時は…",
  "mcpServers": { ... }
}
```

結果は `Invalid MCP configuration` でした。**余分なキーを許さない**仕様です。

JSON にコメントは書けません。`_comment` のような慣習は、**受け取る側が許している場合だけ**通ります。
説明は別ファイル（`README` や、同じディレクトリの `.md`）に置くことにしました。

## 共通しているのは「人間向けのものが混ざる」

3つとも、**人間向けの記号を、機械が読むところへ混ぜた**という形でした。

| 混ぜたもの | 混ざった先 | 結果 |
|---|---|---|
| 指示の区切りタグ | 生成ファイル31本 | インストールが落ちる |
| 社内の内部記号 | 日報の本文 | 読む人に意味不明な記号が出る |
| 説明のコメント | 設定JSON | 設定として無効 |

対策も同じ形になります。

- **書かせるものと、読ませるだけのものを分ける**
- **生成物は、実際に使う経路を通して検査する**
- **説明は、機械が読まない場所に置く**

生成AIを組み込むと、出力は「だいたい正しい」ものになります。
だいたい正しいものは、**目で見て正しさを判定できません**。
機械的に検査する層を、間に1枚置くしかありませんでした。
