不動産の重要事項説明書などの公式書式（Excel・Word で200本ほど）に、
調査した内容を自動で書き込むツールを作っています。

このとき必要なのが、**「この項目は、この書式のどのセルに書くのか」**を割り出す処理です。
見出しの文字を探して、その隣を入力欄とみなす。素直に考えればそうなります。

素直に作ったら、**実物で0点**でした。

## ① 実物の登記事項証明書は、罫線を文字で描いていた

まず、読み取る側から。テスト用に自分で作ったデータでは、10項目とも取れていました。
実物の登記事項証明書（謄本）のPDFを読ませたら、**10項目中0項目**です。

実物は、こういう形をしていました。

```
┏━━━━━━━━┯━━━━━━━━━━━━┓
┃ 所　在　　　　│ 大阪市都島区…      ┃
┠────────┼────────────┨
┃ ① 地　番     │ 1234番5             ┃
┗━━━━━━━━┷━━━━━━━━━━━━┛
```

**罫線がアート（文字）**で、**見出しの文字の間に空白が入る**。
しかもその空白は、全角のときも半角のときもあります。

こちらのパーサは「全角スペース混じりの見出し」を前提にしていました。
`所　在` は拾えても `所 在`（半角）は拾えません。実物が半角混じりだった、というだけの話です。

**合成データが通ったのは、自分の前提でデータを作ったから**です。テストになっていませんでした。

直し方は、パーサを鍛えるのではなく**乗り換え**でした。
別のアプリで完成していた読み取り（AIで構造化する・スキャンPDFは画像として読む・
だめなら正規表現、の3段構え）を共有部品にして使う形にしました。→ **9/10項目**。

## ② 見出しは、左にあるとは限らない

書き込む側の話です。「見出しの右隣が入力欄」という前提で組んだら、**17項目中11**しか当たりません。

原因は2つでした。

**表形式の書式では、上の行が見出しになる。**

```
        | 面積     | 構造   | 築年月 |     ← 見出しは「上」
土地    | 123.45㎡ |        |        |
```

**結合セルは、左上以外を読むと空になる。**

openpyxl でも同じで、`B5:D5` が結合されているとき、`C5.value` は `None` です。
見出しの文字が入っているのは `B5` だけ。

なので、こういう索引を先に作るようにしました。

```python
def merged_origin_map(ws):
    """結合セルの各座標 → 左上の座標 の対応表"""
    m = {}
    for rng in ws.merged_cells.ranges:
        top_left = (rng.min_row, rng.min_col)
        for r in range(rng.min_row, rng.max_row + 1):
            for c in range(rng.min_col, rng.max_col + 1):
                m[(r, c)] = top_left
    return m
```

そのうえで、入力欄の候補について**左と上の両方**を見て、見出しを探します。
これで **17/17** になりました。

## ③ 書式の側にも、書かれていない前提がある

ここからは、機械の話ではなく**書式の読み方**の話です。

### 「書かれていない」ことが情報だった

土地だけの重要事項説明書で、権利のチェック欄が1つも見つかりませんでした。

理由は、**その書式には「土　地」「建　物」という区別の言葉が無い**からでした。
土地しかないので、書く必要がない。人間は表題を見れば分かります。

こちらは「土地」という語を手がかりに欄を探していたので、当たりません。
**シート名（「土地の売買・交換用」など）から側を決める**ようにしました。

### チェック欄を、記入欄だと思っていた

災害に関する3項目について、割り当て先が**チェックの記号（□）が入ったセル**でした。
しかも3項目とも「区域の**外**」を示す側です。ここに説明文を流し込むところでした。

気づいたのは、**公式書式25本すべてで実際の位置を調べたから**です。
1本だけ見て「この位置だろう」と決めていたら、そのまま出ていました。

いまは、自動で書き込む対象から外し、判定が確実な1項目だけチェックを入れています。
似た制度でも根拠が別なら、自動化しません（浸水想定と災害警戒区域は別の制度です）。

### 同じ名前の書式が、3つある

「不動産売買契約書」という名前の書式が3つありました。
一般の売主向け、宅建業者が売主のとき、消費者契約に配慮したもの。**名前は同じ**です。

こちらは、フォルダを走査して**先に見つかったもの**を採っていました。
実務では一般の売主がいちばん多いので、そちらを既定にして、利用者が選び直せるようにしました。

## まとめ

- **合成データは、自分の前提で作られる**。実物で試すまでテストになっていない
- 見出しは**左とは限らない**。結合セルは**左上へ読み替える**
- 書式には**書かれていない前提**がある。「無い」こと自体が情報
- 似た書式は**名前が同じ**ことがある。選び方を決めておく
- 位置の当たりは、**全部の書式で実測してから**決める

紙の書式は、人が読むために作られています。
人は表題を見て、線の意味を読み取って、□の左右を見分けます。
そこを機械に渡すときに落ちるのは、**書かれていない前提**のほうでした。
