不動産の公式書式（Word・Excel）を200本ほど扱うツールを作っています。
書式ごとに「どのセルが何の入力欄か」を登録した一覧を持っていて、これを走査で作り直します。

一覧を作り直したあと、画面で書式を選ぼうとしたら**あるはずの書式が出てきません**。
数えると、**200本あるはずが126本**しか登録されていませんでした。

コマンドは正常に終わっています。**終了コードは 0** でした。

## 原因は3行

対応表に要素を1つ足したのに、取り出す側が固定の3つ組のままでした。

```python
# 対応表（要素を1つ足した）
RULES = [
    ("住居表示", "text", 1, ["予備の見出し"]),   # ← 4要素になった
    ...
]

# 取り出す側（直す前）
for a, b, c in RULES:      # ← ValueError: too many values to unpack
    ...
```

ここで例外が出て、走査は途中で終わりました。以降の書式は登録されません。

問題は、**それが「成功」に見えたこと**です。

- コマンドは終了する
- 終了コードは 0
- 標準出力には、そこまでの進捗が出ている
- 一覧ファイルも**でき上がっている**（中身が半分だが）

「動いた」と判断する材料が、全部揃ってしまいます。

## なぜ 0 で終わったのか

このスクリプトは、書式ごとの処理を大きな `try` で囲み、
最後に「完了しました」と出して終わる形でした。中断しても、そこへ落ちて終わる。

同じ構造は、次のような書き方で普通に生まれます。

```python
def main():
    try:
        for f in formats:
            register(f)
    except Exception as e:
        print(f"エラー: {e}")     # ← 出しているが、終了コードは変えていない
    print("完了しました")

if __name__ == "__main__":
    main()                        # ← 例外を握ったので 0 で終わる
```

`print` はしています。だから「何も出ていなかった」わけではありません。
ただ、**進捗のログに紛れて流れる**し、自動実行なら誰も読みません。

## 直し方は2段構え

### ① 中断したら 0 で終わらせない

```python
if __name__ == "__main__":
    try:
        n = main()
    except Exception:
        traceback.print_exc()
        sys.exit(1)              # ← 失敗は失敗として返す
```

当たり前の話ですが、**握るなら終了コードも一緒に決める**。ここが抜けていました。

### ② 「成功した」の判定を、成果物の件数に変える

こちらのほうが効きます。終了コードは「処理が最後まで走ったか」しか表しません。
本当に知りたいのは**成果物が想定どおりか**です。

```
走査完了: 200本を登録（前回 200本／差 0）
  売買 11分類 139本
  賃貸  9分類  87本
```

件数を出すようにしたら、126本になった瞬間に分かります。
差が出たら理由を書く、まで運用に入れておくと、なお良い。

**「終わった」ではなく「いくつできた」で見る。** これは他の処理にも効きます。

- PDFの分割 → **何ページを何ファイルにしたか**
- データ取り込み → **何行入って、何行はじいたか**
- 一括変換 → **入力の数と出力の数が合っているか**

## ついでに直した、似た形のもの

同じツールで、書式名を部分一致で探して**先頭にヒットしたものを採る**箇所がありました。
「住宅賃貸借契約書」を探すと「**サブリース**住宅賃貸借契約書」が先に当たる、という壊れ方です。

これも例外は出ません。**それらしいものが返ってくる**ので、気づくのは使う人です。

いまは前方一致を先に見て、無ければ部分一致に落としています。
探索の順番を決めておかないと、**似た名前が増えた日に静かに壊れます**。

## まとめ

- **握った例外は、終了コードにも反映する**
- 「成功した」は**成果物の件数**で判定する。終了コードは、そのための材料の一つでしかない
- 前回との**差**を出せば、半分になった日に気づける
