# 送付書ジェネレーター（soufu-generator・port 8518）

**オーナー個人専用の送付書ツール。** 宛名と用件メモを入れると、`claude` CLI が本文を書き、
送付書を Word（.docx）で出力する。

## 送付書メーカー（8525）との違い — 意図して2本に分けている

| | **このアプリ（8518）** | 送付書メーカー（`soufu-maker`・8525） |
|---|---|---|
| 誰が使う | **オーナー個人**（社内には配らない） | **社員**（社内LAN共有・launchd常時起動） |
| 差出人 | **4プロファイルから選ぶ**（大京商事／新誠プロパティ／京橋地域活性化機構／個人） | 大京商事に**固定**。担当者（名前＋メール）だけ切替 |
| バインド | `127.0.0.1`（社内に出さない） | `0.0.0.0`（社内LAN共有） |

**統合しないこと。** 個人の差出人（個人名義・自宅住所）を社員の画面に出さないための分離であって、
コードが重複しているのは承知のうえの構成。共通部分を触るときは**両方**に同じ修正を入れる。

## 差出人マスタの持ち方（2026-08-23 変更・重要）

自宅住所と携帯番号が**公開リポジトリに入っていた**ため、2段構えにした。

| ファイル | 追跡 | 中身 |
|---|---|---|
| `senders.local.json` | **gitignore** | **実データ**（個人プロファイルの住所・電話を含む）。画面の「送付者を編集・追加」で保存されるのはこちら |
| `senders.json` | 追跡する | 雛形。会社3件のみ実値で、**個人の住所・電話は空** |

読み込みは `senders.local.json` →`senders.json` → `DEFAULT_SENDERS`（app.py）の順。
**書き込みは必ず `senders.local.json`**（公開側へ戻さないため）。

> **他のPCで初めて使うとき**: `cp senders.json senders.local.json` してから、画面で個人プロファイルの
> 住所・電話を入れる。**すでに使っているPCで `git pull` する前**は、先に
> `cp senders.json senders.local.json` で実データを退避すること（pull で雛形に上書きされるため）。

## 起動

```bash
./run.sh          # http://127.0.0.1:8518
```

`claude` の場所は `_find_claude()` が PATH →`~/.local/bin` →`/opt/homebrew/bin` の順に探す
（2026-08-23 まで `/opt/homebrew/bin/claude` の直書きで、Homebrew の無いPCでは本文生成が失敗した）。

## 分かっていること・残っている課題

- launchd には登録していない（使うときに `./run.sh`）。メインPCで常時起動したくなったら登録する
- 宛先の**住所欄は無い**（宛名だけ）。だから日本郵便APIの住所照合は対象外
- 送付書メーカーとの共通部分（docx組版・プレビュー・claude呼び出し）は、まだ共有モジュール化していない
